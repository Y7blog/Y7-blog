想象一下这个场景：你在 Remix 里点了 Deploy，等了一会儿，合约地址出来了；又调了 `mintNft`，第一张 NFT 到了你的钱包里。然后你把合约地址发给朋友，朋友打开一看——只有一串看不懂的十六进制代码。

**这串代码真的是你的合约吗？那张 NFT 真的存在吗？别人怎么知道你没在骗他？**

这就是部署之后要解决的问题。写合约只是上半场，部署、验证、确认，每一步都有讲究。今天这篇就把下半场走完整：部署到底把什么放上了链，部署前要检查什么，怎么在 Etherscan 上验证源码，验证之后能在浏览器上做什么，最后怎么确认你 Mint 的 NFT 真的存在。

> 💡 **先说清楚**：本文是知识科普，只讲部署和验证的操作流程，不推荐你去买任何 NFT，更不构成投资建议。所有操作先在 Sepolia 测试网练手，主网上的每一次部署和 Mint 都是真金白银，别拿着没验证过的合约直接上主网。

## 一、部署到底是把什么放上了链？

点 Deploy 之前，先把“部署”这件事本身想明白。很多新手以为部署就是把写好的 `.sol` 文件传上链，其实不是。

### 链上存的不是源代码，是字节码

你写的 Solidity 代码，人能看懂，链看不懂。编译器会先把源代码翻译成一串机器能执行的十六进制代码，叫**字节码（bytecode）**。部署的时候，真正上链的就是这份字节码。

这意味着两件事：

- **别人默认看不到你的源代码**。部署完之后，任何人去区块链浏览器上搜你的合约地址，看到的都只是一串字节码，看不懂你写了什么逻辑。这就是为什么需要“验证源码”——第四节会细讲。
- **部署之后，代码改不了了**。字节码一旦上链就定死了，发现 Bug 也不能直接改，只能重新部署一个新合约，拿到一个新地址。这一点和改网页完全不一样，部署前多检查一遍，比部署后后悔强得多。

### 部署本身也是一笔交易

部署不是一个免费的上传动作，它就是一笔普通的链上交易：你把字节码当作交易数据发出去，矿工（验证者）把它打包进区块，然后合约地址就诞生了。所以部署也要付 Gas，付多少取决于合约有多大——代码越长、功能越多，字节码越长，Gas 就越贵。

### 合约地址是怎么来的？

合约地址不是你随便挑的，它是由**部署者的钱包地址 + 这笔交易的序号（nonce）**算出来的。同一个钱包部署两个合约，地址肯定不一样；同一个合约换个钱包部署，地址也不一样。所以合约地址本身不带任何含义，它只是一个“这份字节码住在这里”的门牌号。

**一句话记住：部署 = 把编译好的字节码发一笔交易上链，链上只存字节码，不存源代码；部署完了代码就改不了了。**

|  | 部署之前 | 部署之后 |
|---|---|---|
| 源代码在哪 | 只在你的电脑 / Remix 里 | 还是只在你手里，链上没有 |
| 链上有什么 | 什么都没有 | 一份字节码 + 一个合约地址 |
| 别人能看到什么 | 看不到 | 只能看到字节码，看不懂逻辑 |
| 还能不能改 | 随便改 | 改不了，只能重新部署新合约 |

## 二、部署之前，先做这份检查清单

部署是一次性的动作，点下去就收不回来。所以点 Deploy 之前，先花五分钟过一遍这份清单：

### 1. 网络对不对？

打开 MetaMask，看一眼顶部显示的网络名字。练手必须在 **Sepolia 测试网**（Chain ID 是 11155111）。如果显示的是 Ethereum 主网，停下来，先切回来再说。部署到主网的 Gas 是真 ETH，点错一次就真花钱了。

### 2. 测试 ETH 够不够？

部署和 Mint 都要付 Gas，钱包里得有 Sepolia 的测试 ETH。没有的话先去水龙头领一点，比如 sepoliafaucet.com。领来的测试 ETH 就是用来练手的，不用省。

### 3. 合约先在虚拟机里跑一遍

Remix 左边部署环境的第一个选项是 JavaScript VM，也就是在浏览器里模拟的一条假链。在这里先把 `mintNft`、`ownerOf`、`tokenURI` 都调一遍，确认逻辑没问题，再连真测试网。虚拟机里跑通了，测试网上大概率也没问题；虚拟机里都没跑通，千万别直接上测试网。

### 4. Metadata 已经固定好了吗？

Mint 的时候要传 `tokenURI`，这个地址指向的 JSON 文件和图片，最好已经传上 IPFS 并且固定（Pin）住了。如果 Metadata 还放在一个临时链接上，Mint 出来的 NFT 随时可能变空白。固定好了再部署，不急这一会儿。

### 5. 把三样东西记下来，验证的时候要用

部署的时候顺手记下这三样，第四节验证源码全靠它们：

- **编译器版本**：比如 0.8.20、0.8.26，Remix 编译界面上写着。
- **优化设置**：有没有开启优化、优化次数是多少（默认一般是 200 次）。
- **构造函数参数**：部署时传给构造函数的参数。我们上一篇的 `MyFirstNFT` 合约构造函数不接收任何参数，所以验证的时候这一步可以直接跳过——这是个好消息，少了一个最容易出错的环节。

**这份清单最容易被跳过的是第 5 条**：部署的时候随手一记，验证的时候省半小时；部署的时候没记，验证的时候就得回头翻编译记录，一个一个试。

### 顺便说一句：Sepolia 现在是什么状态？

如果你在网上搜 Sepolia，会看到一条旧消息：以太坊基金会 2025 年 3 月说 Sepolia 的预期寿命到 2026 年 9 月 30 日。这个日期已经过了，但 Sepolia 还在正常运行——2026 年 10 月 6 日它还接了 Glamsterdam 升级。替代测试网的方案还在讨论，没有定下来，全面停用不会早于 2027 年。结论很简单：**做应用、做合约开发，继续用 Sepolia；只有做验证者、做质押测试，才去 Hoodi 测试网（Chain ID 560048）。** 以后如果 Sepolia 真要退役，基金会会提前半年通知，到时候再换也不迟。

## 三、在 Remix 里部署：流程你已经会了，但有三样东西要记下来

部署的完整操作，上一篇第六节已经走过一遍了，这里不再从头讲，只列一个清单，重点是**部署时要顺手记下来的东西**：

1. 在 Remix 里编译合约，确认没有报错。
2. 部署环境选 **Injected Provider - MetaMask**，连上钱包。
3. 确认 MetaMask 显示的是 **Sepolia 测试网**。
4. 选 `MyFirstNFT` 合约，点 Deploy，MetaMask 里确认。
5. 等交易上链，Remix 下方出现合约地址，**复制下来保存好**。

部署成功之后，你手里应该有这三样东西：

| 要保存的东西 | 在哪找 | 有什么用 |
|---|---|---|
| 合约地址 | Remix 部署界面下方 / MetaMask 交易记录 | 以后查合约、验证、给别人看，都靠它 |
| 部署交易的哈希 | MetaMask 交易记录 / Sepolia Etherscan | 在浏览器上查这笔部署交易，确认状态 |
| 编译器版本 + 优化设置 | Remix 编译界面 | 下一节验证源码时必须填得一模一样 |

**经常犯的错**：部署完了只记得合约地址，编译器版本和优化设置没记。验证的时候 Etherscan 会问你这两个值，填错一个，验证就失败。部署界面上的设置当时看一眼、记下来，验证的时候直接照抄。

## 四、验证源码：在 Etherscan 上给合约“亮明身份”

部署完了，别人搜你的合约地址，看到的还是一串字节码。**验证源码**就是把源代码交给 Etherscan，Etherscan 用你提供的编译设置重新编译一遍，算出来的字节码和链上的字节码一模一样，就说明“这份源代码就是链上这份合约的代码”，然后给你打上一个绿色的已验证标记。

### 为什么要验证？三个理由

- **别人敢信你**。没人愿意和一个看不懂代码的合约打交道。验证了，任何人都能读到你的代码，确认里面没有藏后门。
- **浏览器上能直接读写合约**。验证之后，Etherscan 的合约页面会出现 Read Contract 和 Write Contract 两个标签，不用写代码、不用开 Remix，直接在网页上就能调 `ownerOf`、`tokenURI`，甚至直接 Mint。
- **市场和工具认你**。很多钱包、市场和数据工具只会给已验证的合约显示完整信息。没验证的合约，在这些地方就是一个光秃秃的地址。

反过来想想：如果你要和一个陌生合约交互，第一件事是不是先看它验没验证源码？没验证的合约，默认就当它不可信。这条规矩对别人适用，对你自己也适用。

### 方法一：Remix 的 Contract Verification 插件（最顺手）

如果你是在 Remix 里部署的，这是最顺的一条路，不用离开浏览器：

1. 点左边的插件管理（Plugin Manager），找到 **Contract Verification**，点启用。
2. 这个插件支持四家验证服务：Etherscan、Sourcify、Blockscout、Routescan。选 Etherscan。
3. Etherscan 验证需要一个 **API Key**。去 etherscan.io 免费注册一个账号，在 API Keys 页面就能拿到。Etherscan 现在用的是 v2 API，同一个 Key 能在 50 多条链上通用，Sepolia 也能用。
4. 填上链（Sepolia）、合约地址、合约名（`MyFirstNFT`），勾选 Etherscan，点 Verify。
5. 看到绿色的 ✅，就是验证成功了。

Sourcify 是另一家验证服务，不用 API Key 也能验。它的好处是验证结果会被很多工具共享，坏处是在 Etherscan 页面上不会显示那个绿勾。两个都验一遍最好，Remix 插件里一次就能选多个。

### 方法二：Etherscan 网页手动验证

不想用插件，也可以直接在网页上验证：

1. 打开 sepolia.etherscan.io，搜你的合约地址。
2. 点 Contract 标签页，再点 **Verify and Publish**。
3. 选单文件（Single File）、编译器版本、许可证。许可证要和你代码第一行的 SPDX 声明一致，我们的合约写的是 MIT，就选 MIT。
4. 把优化设置填成和部署时一模一样的：开没开启优化、优化次数。
5. 粘贴源代码。如果你的合约引用了 OpenZeppelin，需要先把所有 import 合并成一个文件——Remix 里右键点文件名，选 **flatten**，就能生成一份合并后的代码。
6. 点验证，等 Etherscan 编译比对。

**经常踩的坑**：flatten 之后的文件里，SPDX 许可证声明会出现好几次，Etherscan 会报错。处理办法是只留文件最开头的一行 SPDX 声明，把其余的删掉再提交。

### 方法三：Hardhat 验证（适合以后转本地项目）

等你开始用 Hardhat 写本地项目，验证就变成一条命令。Hardhat 3 的官方插件是 `@nomicfoundation/hardhat-verify`：

```
npm install --save-dev @nomicfoundation/hardhat-verify
```

在配置文件里填上 Etherscan 的 API Key，部署好的合约验证只要一行：

```
npx hardhat verify --network sepolia <合约地址>
```

如果部署用的是 Hardhat Ignition，部署的时候加上 `--verify`，部署完自动验证，一步到位：

```
npx hardhat ignition deploy ignition/modules/MyFirstNFT.ts --network sepolia --verify
```

我们的 `MyFirstNFT` 构造函数没有参数，所以这条命令不用额外传参数。如果你的合约构造函数有参数，验证的时候要把参数也传进去，顺序和类型都要和部署时一模一样。

### 方法四：Foundry，一句话的事

用 Foundry 的话，验证也是一条命令：

```
forge verify-contract <合约地址> MyFirstNFT --chain sepolia --etherscan-api-key <你的 Key>
```

这四种方法结果是一样的，选你顺手的就行。刚开始学，用 Remix 插件最省事；以后项目变大了，再换 Hardhat 或者 Foundry。

### 验证失败，最常见的是这几个原因

| 失败原因 | 怎么排查 |
|---|---|
| 编译器版本对不上 | 回到 Remix 编译界面，看当时用的到底是哪个版本，0.8.20 和 0.8.26 编出来的字节码是不一样的 |
| 优化开关或次数不同 | 部署时开没开优化、优化次数是多少，验证时必须填得一模一样 |
| 构造函数参数填错了 | 我们的合约没有构造函数参数，直接跳过；有参数的合约要按部署时的顺序和类型重填 |
| 许可证不一致 | 代码第一行写的是 MIT，验证表单里也要选 MIT |
| 合约名选错了 | 一个文件里有多个合约时，确认选的是 `MyFirstNFT`，不是 OpenZeppelin 的某个合约 |
| 字节码里混进了别的东西 | 部署之后又改了代码、重新编译过，拿新代码去验证旧部署，永远对不上；验证用的必须是部署那一刻的代码 |

**验证失败先别慌**。Etherscan 会告诉你失败的原因，大多数情况下就是上面这张表里的某一项对不上。逐项核对，改过来再提交一次就行，验证本身不花钱，可以反复试。

## 五、验证通过之后，你能在浏览器上做什么？

验证成功之后，再打开你的合约地址页面，变化很明显：合约名字旁边多了一个绿色的 ✅，Contract 标签页里出现了源代码。下面这几件事，不用写一行代码就能做：

### 1. 直接读合约状态

点 **Read Contract**，能看到所有只读函数：`name()` 返回 "My First NFT"，`symbol()` 返回 "MFN"，`totalSupply()` 返回已经 Mint 了几张。输入一个编号调 `ownerOf`，就能查到这张 NFT 现在属于谁；调 `tokenURI`，就能看到这张 NFT 的 Metadata 地址。

### 2. 直接写合约（要连钱包）

点 **Write Contract**，连上 MetaMask，就能直接调用 `mintNft`。填上 Metadata 地址，点 Write，钱包里确认，等交易上链，一张新 NFT 就 Mint 出来了。注意 `onlyOwner` 的限制还在：只有合约主人调用才会成功，别人调了会直接失败。

### 3. 看这张 NFT 的全部历史

合约页面的 **ERC721 Token Txns** 标签，能看到每一张 NFT 的 Mint 和转账记录。每一笔 Transfer 事件都写得清清楚楚：从谁手里、到谁手里、哪一个编号、哪一笔交易。

**这就是验证的意义**：你的合约从一串谁也看不懂的字节码，变成了一个任何人都能读、能查、能交互的公开合约。别人不用相信你说的话，自己点开浏览器就能验证。

## 六、确认 Mint 真的存在：三步查到底

Mint 完了，怎么确认这张 NFT 真的存在？按下面三步查，一步一步来：

### 第 1 步：看 Mint 那笔交易

在 Sepolia Etherscan 上搜 Mint 那笔交易的哈希，确认三件事：状态是 Success、有一条 Transfer 事件、这条 Transfer 的发送方是 `0x0000000000000000000000000000000000000000`（零地址）。

从零地址转出来，就是 Mint 的标志：这张 NFT 不是从别人手里转来的，是凭空创造出来的。Transfer 事件里还写着 Token ID，第几张 Mint 出来的 NFT，一眼就能看到。

### 第 2 步：在合约页面查归属

打开合约地址，点 Read Contract，调 `ownerOf`，输入编号（比如 `0`）。返回的地址如果是你的钱包地址，这张 NFT 就是你的。再调 `tokenURI`，输入 `0`，返回的应该是你 Mint 时传的 Metadata 地址。链上存的地址对了，这张 NFT 的“户口”就没问题。

### 第 3 步：去能看到图的地方确认

这里要更新一个情况：**OpenSea 在 2025 年 6 月换成 OS2 之后，不再支持测试网了。** 也就是说，上一篇里说的“去 OpenSea 测试网上看”，现在已经行不通了——testnets.opensea.io 上的测试网 NFT 很可能显示不出来，或者根本打不开。这不是你的合约有问题，是 OpenSea 不再维护测试网入口了。

测试网的 NFT，现在可以去这几个地方看：

- **Sepolia Etherscan 的 NFT 视图**：合约页面能看到 Token 的持有情况和 Transfer 记录，虽然没有市场那么好看，但信息最准。
- **thirdweb 这类开发工具的面板**：连上钱包、填合约地址，就能看到 NFT 的名字、图片和属性。
- **Alchemy 的 NFT API / 仪表盘**：能直接按合约地址查 NFT 的 Metadata，适合想确认 Metadata 有没有被正确读取的时候用。

### 图出不来，先按这个顺序排查

Mint 完了图显示不出来，是最常见的问题。别急着怀疑合约，按这个顺序查：

1. **先等一等**。市场和浏览器都有索引器，不会每秒都去链上读新数据。刚 Mint 完等 15 到 30 分钟，很多“图出不来”自己就好了。
2. **直接打开 tokenURI**。把 `tokenURI` 返回的地址粘贴到浏览器里，看 JSON 文件能不能打开。打不开，问题在文件托管，不在合约。
3. **检查 JSON 格式**。JSON 里多一个逗号、少一个引号，文件就解析失败，图自然出不来。先用在线 JSON 校验工具检查一遍。
4. **检查图片地址**。JSON 里的 `image` 字段指向的图片地址，能不能在浏览器里打开？IPFS 的文件有没有固定住？没固定的文件，网关可能暂时读不出来。
5. **确认看的是同一条链**。在 Sepolia 上 Mint 的 NFT，去主网的页面上当然找不到。先确认你看的页面选的是 Sepolia。

**最容易出现的问题**：第 1 步和第 2 步都通过了，图还是出不来。这种情况大概率是市场在等索引器刷新，或者缓存还没过期。链上地址对了、文件也能打开，剩下的就是等，别急着重新部署。

## 七、准备上主网之前，再过一遍这份清单

测试网跑通了、验证通过了、Mint 也确认了，离主网只差最后一步。但主网和测试网有一个本质区别：**测试网的 ETH 是免费领的，主网的 ETH 是真金白银。** 上主网之前，再过一遍这份清单：

### 1. 测试网全流程跑通过了吗？

部署、验证、Mint、查归属、看图，这五步在 Sepolia 上都跑通过了吗？哪一步还没跑通，就别上主网。主网没有“重来一次”的免费机会。

### 2. 合约主人是你控制的钱包吗？

`Ownable(msg.sender)` 把部署者设成了主人。确认部署用的钱包是你自己的、助记词保管好的钱包。**助记词和私钥绝不放进代码里，绝不发给任何人，任何向你要助记词的人都是骗子。**

### 3. Metadata 固定住了吗？

图片和 JSON 文件都在 IPFS 上，并且已经用 Pin 服务固定住了。放在临时链接上的 Metadata，主网上的 NFT 也会跟着变空白。

### 4. 算过主网要花多少钱吗？

部署和 Mint 在主网都要付真 ETH，多少钱取决于当时的 Gas 价格。部署之前先去 Etherscan 的 Gas Tracker 看一眼当前价格，心里有个大概数。再提醒一句：主网上部署一个 ERC721 合约，Gas 费不是小数目，测试网上先把流程练熟，主网只部署一次。

### 5. 合约再读一遍：有没有留不该留的东西？

部署之前，把合约从头读一遍，重点看这几个问题：

- 谁能 Mint？是不是只有你想让 Mint 的人能 Mint？
- `tokenURI` 能不能被改？谁能改？改了会有什么后果？
- 有没有写了一半没用上的函数？有没有测试用的后门没删掉？

**这一步没有捷径**。合约上链就改不了了，部署前多读两遍，比部署后发现问题强一百倍。

## 总结

- **部署是把字节码发上链**：链上只存字节码，不存源代码；合约地址由部署者地址和交易序号算出来；部署本身是一笔要付 Gas 的交易；部署完代码就改不了了。
- **部署前先过检查清单**：网络是 Sepolia、钱包里有测试 ETH、合约先在虚拟机里跑通、Metadata 已经固定好，最重要的是把编译器版本、优化设置记下来，验证的时候要用。
- **验证源码就是“亮明身份”**：把源代码交给 Etherscan，它重新编译、比对链上字节码，对上了就打绿勾。Remix 插件、Etherscan 网页、Hardhat、Foundry 都能验，选顺手的就行。验证失败最常见的原因是编译器版本、优化设置、构造函数参数、许可证这几项对不上，逐项核对就能解决。
- **验证之后，浏览器就是你的控制台**：Read Contract 直接查状态，Write Contract 连钱包就能 Mint，ERC721 Token Txns 里能看到每一张 NFT 的全部历史。
- **确认 Mint 分三步**：看 Mint 交易的 Transfer 事件、调 `ownerOf` 查归属、去能看到图的地方确认。图出不来先等 15 到 30 分钟，再按顺序查 tokenURI、JSON 格式、图片地址和网络。
- **一个新情况要记住**：OpenSea OS2 从 2025 年 6 月起不再支持测试网，测试网的 NFT 改去 Sepolia Etherscan、thirdweb、Alchemy 这类地方看。
- **上主网之前再过一遍清单**：测试网全流程跑通、主人钱包确认、Metadata 固定、Gas 价格看过、合约从头读过一遍。主网没有免费重来的机会。
