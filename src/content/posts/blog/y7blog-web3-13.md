当时，我们做了一个很简单的实验：部署 `HelloY7` 合约，然后把里面的消息从 `Hello, Y7 Blog!` 改成 `Hello Blockchain!`。

但这里有一个值得继续研究的问题：

**如果智能合约已经部署好了，下次我们想再次使用它，应该怎么找到它，又该如何调用它？**

比如，你想查询一个 Token 的余额、读取 NFT 的信息，或者调用某个 DeFi 协议的函数，总不能每次都重新编写和部署一遍合约。

这就涉及智能合约交互。

这篇文章，我们就从最基础的概念开始，弄清楚调用智能合约需要什么，以及如何通过 Remix 与一个已经部署的合约交互。

## 一、合约部署完成后，为什么还需要调用？

先区分两个动作：**部署合约**和**调用合约**。

部署，可以理解为把合约程序放到指定的区块链环境中，让它拥有一个可以被访问的合约地址。

调用，则是使用这个地址找到合约，再读取它保存的数据，或者执行它提供的函数。

举个例子。

假设我们部署了一个简单的消息合约：

```solidity
contract HelloY7 {
    string public message = "Hello, Y7 Blog!";

    function setMessage(string memory newMessage) public {
        message = newMessage;
    }
}
```

它有两个主要功能：

- 读取当前保存的消息。
- 接收一段新文字，并修改消息。

部署完成后，合约就可以在对应的区块链环境中被访问。

当我们想查看消息时，可以调用 `message()` 对应的读取接口；当我们想修改消息时，可以调用 `setMessage()` 函数。

这有点像使用一个已经上线的网站。

网站上线后，你不需要重新开发整个网站才能查看页面。你只需要访问对应的网址，再执行相应的操作。

智能合约也有类似的地方。不过，合约不是通过普通网页地址来定位，而是通过**合约地址**来找到对应的实例，并按照合约提供的接口进行交互。

当然，两者也有重要区别：区块链上的状态和交易有自己的执行规则，修改链上状态通常需要提交交易。

## 二、调用智能合约，需要准备什么？

想要调用一个已经部署的智能合约，最重要的是先准备好三个东西：

**合约地址、ABI，以及正确的区块链网络。**

如果调用操作需要修改状态，通常还需要一个能够签名交易的账户。

### 1. 合约地址：告诉程序去哪里找合约

合约地址是合约部署后在对应区块链环境中的地址。

它通常是一串以 `0x` 开头的十六进制字符，例如：

`0x1234...abcd`

这里仅用于展示格式，并不是一个真实可用的合约地址。

可以把合约地址理解为合约在某个网络中的定位信息。

如果你想查询某个 Token 的余额，或者调用某个 NFT 合约的函数，就需要知道对应合约的地址。

不过，有一点需要特别注意：

**只有地址还不够，网络也必须匹配。**

例如，你在 Ethereum Sepolia 测试网上部署了一个合约，之后却切换到了 Base 网络。即使你输入相同的地址，也不能因此认定自己访问的就是 Sepolia 上的那个合约实例。

同一串地址可以出现在不同网络中，但它们对应的代码和状态可能完全不同。

因此，在调用之前，先确认合约部署在哪条链上。

### 2. ABI：告诉程序应该如何与合约沟通

如果说合约地址解决的是“去哪里找”，那么 ABI 解决的就是“找到之后，怎么沟通”。

ABI 的全称是 **Application Binary Interface**，中文通常称为应用二进制接口。

对于 Solidity 智能合约，我们可以先把 ABI 理解成一份接口说明书。

它描述了合约对外提供哪些函数、函数需要什么参数，以及调用结果应该如何解码。

例如，我们的 `HelloY7` 合约提供了这些接口：

- `message()`：读取当前消息。
- `setMessage(string)`：传入一段字符串，修改消息。

外部程序需要知道这些接口的信息，才能正确地组织调用数据，并理解返回结果。

如果没有合适的 ABI，程序就很难仅凭一个合约地址，自动知道应该如何调用它的函数。

这里有一个容易误解的地方：

**ABI 不是合约代码，也不是合约地址。**

它主要描述接口，而不是完整的业务逻辑。

ABI 通常可以在编译 Solidity 源代码时生成。如果你没有源码，但能从可信来源获得正确的 ABI，也可以在具备相应工具和调用条件时与合约交互。

### 3. 正确的网络：确保访问的是目标合约

区块链不是只有一条链。

Ethereum 主网、Ethereum Sepolia 测试网，以及 Base 等网络，都有各自的链上状态。

所以，调用合约前需要确认：

- 合约部署在哪条链上。
- 当前工具连接的是哪条链。
- 使用的合约地址是否属于这个网络。
- 当前拿到的 ABI 是否与目标合约的接口匹配。

如果其中任何一项不匹配，都可能导致调用失败，或者读取到与你预期不同的数据。

对于需要修改状态的操作，还需要准备能够签名交易的账户，并满足目标网络的交易费用要求。

## 三、实战：调用已经部署的 HelloY7 合约

概念讲完，我们直接动手。

这次仍然使用 Remix，因为它已经包含了编写、编译、部署和交互所需的基本工具，不需要额外安装开发环境。

打开 Remix：

https://remix.ethereum.org/

### 第一步：找到之前部署的合约

进入 Remix 后，打开左侧的 `Deploy & Run Transactions` 面板。

如果你之前已经在当前 Remix VM 环境中部署过 `HelloY7`，并且虚拟环境没有被重置，那么可以在 `Deployed Contracts` 区域找到它。

展开合约实例，就能看到可以调用的函数和变量。

如果之前的虚拟环境已经重置，原来的合约实例可能就不在了。这时可以重新编译并部署 `HelloY7`，再继续实验。

注意：这里的 Remix VM 是模拟区块链环境。它适合练习交互，但不代表合约已经部署到 Ethereum 公共网络。

### 第二步：读取合约中的数据

找到 `message` 按钮并点击。

正常情况下，返回的内容是：

`Hello, Y7 Blog!`

为什么可以直接读取？

因为合约中声明了：

```solidity
string public message = "Hello, Y7 Blog!";
```

Solidity 会为公开状态变量自动生成 getter 函数，因此外部可以读取这个变量的值。

你不需要手动再编写一个 `getMessage()` 函数。

这次操作只是读取状态，不会修改 `message` 的值。

在真实网络中，这类只读调用通常通过 RPC 的 `eth_call` 等方式完成，不需要发送一笔用于改变链上状态的交易。

### 第三步：调用函数修改消息

现在找到 `setMessage` 函数。

在参数输入框中填入：

`Hello Blockchain!`

然后点击 `setMessage`。

如果操作成功，你会看到 Remix 显示相应的执行结果。

在当前 Remix VM 环境中，合约状态应该已经发生变化。

但我们还需要进一步验证，而不是仅凭按钮被点击就判断成功。

### 第四步：再次读取消息

重新点击 `message`。

如果结果变成：

`Hello Blockchain!`

说明修改已经生效。

我们刚刚完成了一个完整的合约交互流程：

1. 通过合约实例找到目标合约。
2. 调用公开接口读取状态。
3. 调用写入函数修改状态。
4. 再次读取状态，确认修改结果。

这也是很多 Web3 应用背后的基础操作。

例如，钱包查询 Token 余额、NFT 应用读取 NFT 属性，以及 DeFi 应用查询某些协议数据，都可能涉及与智能合约进行类似的交互。

## 四、如果只有合约地址，怎么调用？

刚才的实验相对简单，因为我们使用的是自己编写并部署的合约，Remix 已经知道它的接口。

但在实际使用中，我们经常会遇到另一种情况：

**别人已经部署好了合约，只给了我们一个合约地址。**

这时候应该怎么办？

首先要明确：只有合约地址，并不一定能直接在图形界面中看到所有函数。

你还需要获取与目标合约匹配的 ABI。

ABI 可以来自可靠的项目文档、合约源码编译结果，或者区块链浏览器提供的已验证合约信息。

接下来，仍然可以使用 Remix 进行交互。

### 方法一：通过已有的合约接口加载实例

如果你已经有目标合约的 ABI，并且能够在 Remix 中选择或加载对应的合约接口，可以使用 `At Address` 一类的功能，将合约地址与该接口关联起来。

操作思路是：

1. 确认 Remix 连接的是目标合约所在的网络。
2. 准备与目标合约匹配的 ABI。
3. 在合约选择区域选择对应的合约接口。
4. 在 `At Address` 输入目标合约地址。
5. 加载合约实例。
6. 根据界面显示的函数进行读取或调用。

Remix 不同版本的界面可能有所变化，但核心原理相同：使用正确的接口描述和合约地址建立交互实例。

需要注意，ABI 必须与目标合约的实际接口匹配。不能因为两个合约都叫 `Token`，就认为它们拥有完全相同的函数。

### 方法二：通过区块链浏览器查看已验证合约

如果目标合约部署在支持区块链浏览器的网络上，可以尝试通过对应的浏览器查看合约信息。

以 Etherscan 为例：

https://etherscan.io/

打开浏览器后，搜索目标合约地址。

如果该合约已经验证源码，页面通常会提供合约源码、合约接口等相关信息，具体展示取决于浏览器页面和合约状态。

你可以通过这些信息进一步理解合约提供了哪些函数。

但要注意，合约未验证并不代表它一定不安全；同样，源码已经验证也不代表它一定安全。验证主要帮助用户检查已发布源码与链上字节码之间的对应关系，并不等于安全审计。

另外，如果合约地址属于测试网，就应该使用对应测试网的区块链浏览器，而不是直接使用 Ethereum 主网浏览器。

## 五、读取数据和修改数据，有什么区别？

这是理解智能合约交互时非常重要的一点。

表面上看，读取和修改都是点击一个按钮，但它们的执行方式可能完全不同。

| 对比 | 读取数据 | 修改数据 |
| --- | --- | --- |
| 常见目的 | 查询余额、读取消息、查看状态 | 转账、修改参数、执行状态变更 |
| 是否改变链上状态 | 通常不会 | 会尝试改变状态 |
| 常见执行方式 | 通过 RPC 只读调用 | 发送交易并执行合约 |
| 是否需要签名交易 | 通常不需要 | 通常需要 |
| 是否需要支付链上 Gas | 只读调用通常不需要用户支付链上 Gas | 通常需要 |

这里需要稍微解释一下 `view` 和 `pure`。

在 Solidity 中，如果函数声明为 `view`，表示它不会修改合约状态；`pure` 则进一步表示它不读取也不修改合约状态。

例如：

```solidity
function getMessage() public view returns (string memory) {
    return message;
}
```

这个函数只负责返回消息，不会修改状态。

不过，我们前面的 `message` 已经是公开状态变量，因此 Solidity 会自动生成 getter，并不一定需要再编写这个函数。

而下面的函数会修改状态：

```solidity
function setMessage(string memory newMessage) public {
    message = newMessage;
}
```

在真实公共网络上，调用这个写入函数通常需要通过交易执行。

交易需要由账户签名，并支付相应的 Gas 费用。交易执行后，还需要根据网络的确认情况判断操作是否最终生效。

这里也有一个细节：如果你通过某些工具使用 `eth_call` 模拟执行一个本来会修改状态的函数，模拟结果不会自动变成永久的链上状态。真正修改状态，仍然需要按照网络规则提交交易。

## 六、为什么有时候调用合约会失败？

即使拿到了合约地址，也准备好了 ABI，调用仍然可能失败。

常见原因有以下几种。

### 1. 合约地址不正确

如果地址输入错误，或者地址属于其他网络，可能会找不到预期的合约。

解决方法：重新核对地址，并确认网络。

### 2. ABI 与合约不匹配

例如，你拿到了一个旧版本合约的 ABI，但目标地址对应的是另一个版本。

程序可能无法正确编码函数调用，也可能无法正确解析返回数据。

解决方法：确认 ABI 来自目标合约的正确版本。

### 3. 交易没有成功执行

调用写入函数时，可能因为权限不足、参数不符合要求、余额不足以支付费用，或者合约内部条件不满足而失败。

解决方法：查看交易或执行记录中的具体错误信息。

### 4. 把读取操作当成写入交易

只读调用和写入交易的执行方式不同。

如果只是读取状态，通常不需要发送交易；如果需要改变链上状态，则通常需要签名并提交交易。

解决方法：先判断自己想做的是读取还是修改，再选择合适的调用方式。

### 5. 误以为按钮被点击就代表交易成功

钱包弹出确认窗口、工具显示正在处理，或者按钮被点击，都不等于交易已经成功。

在真实网络中，应该进一步检查交易状态和执行结果。

对于重要操作，还应核对目标网络、合约地址、函数参数，以及交易最终产生的状态变化。

## 七、从合约部署到合约交互，我们走到了哪一步？

回头看这几篇文章，学习路线其实很清晰。

第 9 篇，我们认识了 Solidity，知道它是编写 Ethereum 智能合约的语言之一。

第 10 篇，我们开始使用 Remix 编写和编译合约。

第 11 篇，我们完成了第一个合约的部署。

而这篇文章，我们进一步学会了如何调用已经部署的合约。

现在，你应该能够理解几个关键概念：

- **合约地址**：定位目标合约实例。
- **ABI**：描述如何与合约接口交互。
- **读取调用**：获取合约数据，通常不需要发送链上交易。
- **写入交易**：执行状态变更，通常需要签名并支付 Gas。
- **网络匹配**：确保调用的是预期网络中的合约实例。

这些知识看起来基础，却是后续学习 ERC20、NFT、预言机和跨链应用的共同基础。

因为无论是查询 Token 余额、读取 NFT 信息，还是调用 DeFi 协议的某个函数，背后都离不开合约地址、接口和调用方式。
