上一篇文章，我们认识了 Solidity，知道它是一种用于编写智能合约的编程语言。

但了解一门语言，只是学习开发的第一步。

如果想真正写出一个智能合约，还需要解决几个问题：代码在哪里写？写完之后怎么检查？如何让它运行起来？又该怎么与它交互？

对于刚入门的人来说，最容易被这些开发环境和工具配置劝退。

好消息是，我们可以先不安装任何开发软件，直接使用浏览器完成这些操作。

今天就来认识一个非常适合初学者的工具：**Remix IDE**。

我们会从创建文件开始，编写一个简单的 Solidity 合约，再完成编译、部署和调用。整个过程不需要连接真实钱包，也不需要准备真实 ETH。

## 一、Remix 是什么？为什么不用安装开发环境？

Remix IDE 是一个面向智能合约开发的集成开发环境，主要用于编写、编译、部署和调试 Solidity 智能合约。

你可以把它理解成一个专门为智能合约准备的在线工作台。

平时写代码，可能需要安装编辑器、配置编程语言环境、安装依赖，再运行程序。

而 Remix 把很多常用的开发功能整合在了一起。打开浏览器，就可以开始编写智能合约。

它能帮我们完成哪些事情？

- **编写代码：** 在编辑器中创建和修改 Solidity 文件。
- **编译合约：** 检查代码，并将 Solidity 源代码编译成 EVM 可以执行的字节码。
- **部署合约：** 将编译后的合约部署到本地虚拟环境或支持的区块链网络。
- **调用合约：** 通过界面执行合约函数，查看返回结果和状态变化。
- **调试程序：** 查看错误信息，帮助定位问题。

对于刚入门的人来说，Remix 最大的价值不是它能替你写出多复杂的程序，而是它让我们可以先把注意力放在智能合约本身，而不是一开始就陷入开发环境配置。

### 打开 Remix

官方地址：

https://remix.ethereum.org/

进入网站后，就可以开始使用 Remix IDE。

第一次使用时，不需要急着连接钱包。我们先使用 Remix 提供的本地虚拟环境，完成一个最简单的实验。

这里需要明确一点：**Remix 是开发工具，不是区块链本身。** 在 Remix 中写代码，并不意味着代码已经发布到了 Ethereum 主网。

## 二、认识 Remix 的开发界面

第一次打开 Remix，可能会看到不少按钮和面板。

不用着急全部弄懂。我们先认识完成本次练习需要的几个区域。

### 1. 文件管理器

这里负责管理项目文件。

我们可以创建 Solidity 文件、查看已有文件，也可以将不同的合约放在不同文件中。

Solidity 文件通常使用 `.sol` 作为扩展名。

例如：

`HelloY7.sol`

这是我们接下来要创建的文件。

### 2. 代码编辑器

这是编写智能合约的主要区域。

和普通代码编辑器类似，我们可以在这里输入 Solidity 代码、修改变量和函数，也可以根据错误提示调整代码。

### 3. Solidity 编译器

代码写完后，需要通过编译器进行编译。

编译器会检查代码是否符合 Solidity 的语法和规则，并在编译成功后生成部署和交互所需要的相关产物。

如果代码存在语法错误，通常可以在这里看到相应提示。

### 4. 部署与交互面板

编译成功之后，我们就可以在这里选择合约、部署实例，并调用合约提供的函数。

后面我们会用它读取和修改合约中保存的文字。

先记住这几个区域就够了。随着练习深入，你会逐渐理解它们之间的关系。

## 三、编写第一个智能合约

现在开始动手。

在 Remix 的文件管理器中，创建一个新文件：

`HelloY7.sol`

然后将下面的代码复制进去。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract HelloY7 {
    string public message = "Hello, Y7 Blog!";

    function setMessage(string memory newMessage) public {
        message = newMessage;
    }
}
```

这就是我们今天要完成的第一个智能合约。

代码不长，但已经包含了几个重要概念：合约、状态变量、函数和数据修改。

对于初学者来说，与其一开始就写复杂的业务逻辑，不如先理解这几个基本组成部分。

### 1. 许可证声明

```solidity
// SPDX-License-Identifier: MIT
```

这行代码声明了源代码使用的许可证。

它通常放在 Solidity 文件的开头，帮助开发者明确代码的许可信息。

它不是让合约运行起来的核心业务逻辑，但属于规范代码中常见的声明。

### 2. Solidity 版本声明

```solidity
pragma solidity ^0.8.20;
```

这行代码指定了合约允许使用的 Solidity 编译器版本范围。

这里的 `^0.8.20` 表示允许使用兼容的 0.8.x 版本，但不包括 0.9.0 及以上版本。

因此，编译时需要选择符合这个版本范围的编译器。

如果选择的版本不兼容，编译器就可能报错。

### 3. 创建一个合约

```solidity
contract HelloY7 {
```

`contract` 是 Solidity 中用于声明智能合约的关键字。

我们将这个合约命名为 `HelloY7`。

可以暂时把它理解成一个独立的程序容器，里面可以保存数据，也可以定义操作这些数据的函数。

合约的大括号 `{}` 之间，就是它的主要代码内容。

### 4. 保存一段文字

```solidity
string public message = "Hello, Y7 Blog!";
```

这行代码定义了一个状态变量。

拆开来看：

- `string`：表示数据类型是字符串，也就是一段文字。
- `public`：表示这个变量可以通过公开的访问接口读取。
- `message`：变量的名称。
- `"Hello, Y7 Blog!"`：变量的初始值。

那么，为什么要使用状态变量？

因为我们希望合约不仅能够执行代码，还能够保存数据，并在之后的调用中继续使用这些数据。

当合约成功部署后，这个变量的值会成为合约状态的一部分。

由于变量声明为 `public`，Solidity 会自动提供一个对应的读取函数，我们不需要自己再写一个单独的读取函数。

### 5. 编写一个修改数据的函数

```solidity
function setMessage(string memory newMessage) public {
    message = newMessage;
}
```

这个函数负责修改 `message` 保存的文字。

逐项理解：

- `function`：声明一个函数。
- `setMessage`：函数名称。
- `string memory newMessage`：接收一段字符串作为参数。
- `public`：允许外部调用这个函数。
- `message = newMessage`：把传入的新文字保存到状态变量中。

例如，我们调用这个函数并传入：

`Hello, Blockchain!`

那么，合约中的 `message` 就会从原来的文字变成新的文字。

这里有一个重要概念：

**函数不仅可以读取数据，也可以改变合约保存的状态。**

这正是我们接下来要通过 Remix 观察的事情。

## 四、编译智能合约：为什么代码写完还不能直接部署？

代码写完后，不代表智能合约已经可以部署。

Solidity 是人类编写和阅读的源代码，而 Ethereum 虚拟机（EVM）执行的是特定格式的字节码。

因此，我们需要通过编译器，将 Solidity 代码转换成相应的编译产物。

可以简单理解为：

**Solidity 源代码 → 编译器 → EVM 字节码及其他编译产物**

编译器还会检查代码中的语法和类型等问题。如果代码存在不符合规则的地方，就可能无法成功编译。

### 1. 打开 Solidity 编译器

在 Remix 左侧工具栏中，找到 Solidity 编译器面板。

选择与代码版本声明兼容的编译器版本。

我们的代码使用了：

```solidity
pragma solidity ^0.8.20;
```

因此，需要选择符合这一版本范围的编译器。

### 2. 执行编译

确认当前打开的是 `HelloY7.sol`，然后点击编译按钮。

如果代码没有问题，Remix 就会生成相应的编译产物。

如果出现错误，可以先检查：

- 是否漏写分号；
- 大括号是否成对；
- 变量和函数名称是否拼写一致；
- 编译器版本是否符合代码要求。

对于初学者来说，编译失败并不意味着整个开发过程出了大问题。很多错误只是语法或版本不匹配，阅读提示并逐项检查就可以了。

### 3. 认识 ABI 和字节码

编译成功后，你可能会看到两个经常出现在智能合约开发中的术语：ABI 和 Bytecode。

它们分别有什么作用？

**Bytecode（字节码）**

这是编译器生成的代码产物之一，用于在 EVM 中执行。

当我们把合约部署到兼容的区块链网络时，部署过程会使用相应的编译产物。

**ABI（应用二进制接口）**

ABI 描述了外部程序应该如何与合约的函数和数据进行交互。

例如，我们的合约有 `setMessage()` 函数。前端程序或其他工具需要知道这个函数的名称、参数类型等信息，才能按照正确的接口发起调用。

现在不需要深入研究 ABI 的具体格式，只要先记住：

- 字节码与合约在 EVM 中的执行有关；
- ABI 与外部如何识别和调用合约接口有关。

后面学习合约交互时，我们还会继续接触它们。

## 五、部署智能合约：让合约运行起来

编译成功后，接下来就可以部署合约了。

不过，先解释一下“部署”是什么意思。

在智能合约开发中，部署通常是指将编译后的合约代码通过一笔部署交易提交到相应的执行环境中，并创建合约实例。

对于公共区块链来说，这通常意味着发起一笔链上交易，并支付相应的 Gas 费用。

但我们现在只是学习，不需要一开始就使用真实区块链。

Remix 提供了本地虚拟环境，可以让我们先熟悉部署和调用流程。

### 1. 选择本地虚拟环境

打开 Remix 的部署与交互面板。

在 Environment（环境）选项中，选择 Remix 提供的本地虚拟环境，例如 Remix VM。

具体名称可能会随着 Remix 版本变化。

本地虚拟环境会提供模拟账户和运行所需的环境，让我们可以进行开发测试。

这一步不需要连接 MetaMask，也不需要准备真实 ETH。

### 2. 选择要部署的合约

在合约选择区域，选择：

`HelloY7`

确认选中的是刚才编译成功的合约。

然后点击 Deploy（部署）。

Remix 会在所选虚拟环境中执行部署操作，并在部署成功后显示相应的合约实例。

如果部署失败，可以检查当前选中的合约、编译结果以及运行环境。

### 3. 部署成功意味着什么？

如果你看到了已经部署的 `HelloY7` 合约实例，说明我们已经完成了本地环境中的合约部署。

但这里必须区分两件事：

- **在本地虚拟环境中部署：** 用于开发和测试，不等于发布到公共区块链。
- **部署到公共区块链：** 需要选择相应网络，通常还需要钱包、账户余额和真实交易。

所以，我们现在得到的是一个可以在本地实验环境中交互的合约实例，而不是已经部署到 Ethereum 主网的合约。

先把这个区别理解清楚，可以避免后面学习时把“本地运行”和“真正上链”混为一谈。

## 六、调用智能合约：亲手修改保存的数据

到这里，我们已经完成了代码编写、编译和部署。

现在来验证这个合约是否按照预期工作。

在 Remix 的部署与交互面板中，找到刚才部署的 `HelloY7` 合约实例。

你应该可以看到与公开变量 `message` 对应的读取按钮，以及 `setMessage` 函数对应的交互入口。

### 1. 读取当前内容

点击 `message` 对应的按钮。

如果一切正常，你会看到：

`Hello, Y7 Blog!`

这说明合约当前保存的文字可以被成功读取。

因为 `message` 被声明为 `public`，Solidity 自动生成了对应的读取接口。

### 2. 修改内容

找到 `setMessage` 函数对应的输入框，输入一段新文字，例如：

`Hello, Blockchain!`

然后执行函数调用。

在本地虚拟环境中，Remix 会模拟相应的执行过程。如果操作成功，合约中的状态变量就会被修改。

### 3. 再次读取

再次点击 `message` 的读取按钮。

这一次，你应该会看到：

`Hello, Blockchain!`

恭喜你，你已经完成了一个完整的智能合约交互过程。

我们并没有使用复杂的代码，却观察到了一个关键现象：

**合约可以保存状态，并通过函数调用改变状态。**

这也是理解智能合约的一个重要起点。

### 4. 读取和修改，究竟有什么区别？

在 Ethereum 这类区块链中，读取和修改状态的操作有重要区别。

对于本篇的合约来说：

- 读取 `message`：读取当前状态，不需要发起改变链上状态的交易。
- 调用 `setMessage()`：会修改合约状态。在真实链上，通常需要通过交易执行，并支付 Gas。

在 Remix 的本地虚拟环境中，这些操作使用的是模拟环境，因此不需要花费真实 ETH。

但在真实网络中，修改状态需要经过相应的交易执行流程，并受到网络规则和交易费用的约束。

这里先建立基本认识就好。之后学习 Gas、交易和合约交互时，我们还会进一步拆解这些机制。

## 七、初学者使用 Remix 时，最容易遇到的问题

第一次操作时，出现错误很正常。下面整理几个常见情况。

### 问题一：编译失败

先检查代码是否完整，尤其是分号、大括号、变量名称和函数名称。

然后确认编译器版本是否符合 `pragma` 声明。

如果仍然失败，可以查看 Remix 显示的错误信息，定位具体出错的代码行。

### 问题二：部署按钮无法正常执行

先确认合约已经成功编译，再检查部署面板中选择的合约是否正确。

如果你修改过代码，也要确认当前看到的编译结果对应的是最新代码。

### 问题三：找不到部署后的合约

检查是否已经成功完成部署，以及当前是否仍处于原来的运行环境。

不同环境中的合约实例和状态并不一定相同。切换环境后，看不到原来的合约，不代表合约代码一定有问题。

### 问题四：调用函数后，文字没有变化

可以按顺序检查：

1. 是否在正确的合约实例中调用函数；
2. 是否在输入框中填写了参数；
3. 函数调用是否成功执行；
4. 是否再次读取了 `message` 的当前值。

如果只是修改了编辑器里的源代码，却没有重新编译和部署，已有合约实例也不会因此自动变成新版本。

### 问题五：为什么本地测试成功，真实网络却可能失败？

本地虚拟环境和真实区块链网络并不完全相同。

真实网络可能涉及账户余额、Gas 费用、网络拥堵、合约依赖和其他执行条件。

因此，本地测试成功只是开发过程中的一个重要检查步骤，并不代表合约在所有环境下都一定能正常运行。

## 八、用 Remix 学习智能合约，还需要注意什么？

Remix 降低了开发门槛，但它不能替代对智能合约原理和安全性的理解。

在继续学习之前，有几个边界值得记住。

**第一，编译成功不等于合约没有漏洞。**

编译器可以发现很多语法和类型问题，但无法保证业务逻辑正确，也不能证明合约不存在安全风险。

**第二，本地部署不等于真正上链。**

我们今天使用的本地虚拟环境主要用于练习。想让合约在公共区块链上运行，还需要完成相应网络配置和真实部署流程。

**第三，合约部署后，修改并不总是像编辑普通文件一样简单。**

普通程序可以修改文件后重新运行，而部署在公共区块链上的合约，其代码和状态受到链上规则约束。除非合约本身设计了升级机制，否则通常不能直接替换已部署的代码。

**第四，不要随意把真实资产交给未经验证的合约。**

刚入门时，建议先使用本地虚拟环境，之后再使用测试网练习。不要因为某个合约可以成功编译和部署，就认为它适合管理真实资产。

## 九、总结：第一次写智能合约，其实没那么复杂

回顾一下今天完成的事情：

1. 打开 Remix IDE，认识基本开发界面；
2. 创建 `HelloY7.sol` 文件；
3. 编写一个保存文字、修改文字的简单合约；
4. 使用 Solidity 编译器完成编译；
5. 在本地虚拟环境中部署合约；
6. 通过函数调用修改状态，再读取结果进行验证。

从这个例子可以看到，智能合约并不是一个无法接近的黑盒。

它本质上仍然是一段程序，只不过它运行在特定的区块链执行环境中，并按照相应的规则处理数据和交易。

我们现在还没有开发复杂的 Token、NFT 或 DeFi 应用，但已经走完了智能合约开发中最基本的一条路径：

**编写 → 编译 → 部署 → 调用。**

理解这条路径之后，后面再接触合约地址、ABI、Gas、区块链浏览器等概念，就会容易很多。

对我来说，学习 Web3 开发最重要的，不是一次性记住多少专业术语，而是把每个概念放进一个可以实际操作的流程里，逐步理解它为什么存在。
