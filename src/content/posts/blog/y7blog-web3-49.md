想象一下，CRE 的开发工具装好了，第一个 Hello World 工作流也在自己电脑上跑起来了。下一步自然是把它部署到生产环境，让它真的在链上跑起来。但在点部署之前，有一个问题得先想明白：**这东西跑起来，到底要花多少钱？**

这是一个很实际的问题，也是一个很容易踩坑的问题。因为如果你是照着 Functions 时代的老教程学过来的，脑子里会有一个现成的答案：开一个 Subscription，往里面充 LINK，跑一次扣一次。但 CRE 里这套东西已经不存在了。更直接地说，**截至 2026 年 11 月 26 日，Chainlink 官方没有公布 CRE 每次执行多少钱，也没有公开的价目表。** 这篇不会给你编一个价格出来，而是把能查到的、能算的账讲清楚，把查不到的也如实告诉你——先把成本这件事搞清楚，再动手部署生产环境才踏实。

> 💡 **先说清楚**：这篇是知识科普，不是投资建议。CRE 正式上线才一年，计费方式和额度规则还在演进，本文按 2026 年 11 月 26 日核对的官方文档写；如果你照着动手，遇到和本文不一致的地方，以官方文档为准，先在测试网练手。Functions 的退役日期只写到“已退役/已关闭”，因为不同来源对具体日期的说法并不一致。

## 一、先说结论：CRE 里没有“订阅”这回事

如果你去 CRE 的官方文档里找“Billing”或者“Pricing”页面，会发现根本找不到。CRE 的文档里有总览、入门教程、CLI 参考、模板、服务配额，唯独没有一页告诉你“跑一次工作流收多少钱”。这不是你找错了地方，而是官方确实还没公布。

这和 Functions 时代完全不一样。Functions 有一整套订阅计费模型，流程是这样的：

```
你开一个 Subscription
        ↓
往里面充 LINK（余额）
        ↓
每次发请求，系统先估算费用、冻结一部分余额
        ↓
请求完成，按实际用的 Gas 结算、多退少补
        ↓
余额不够了，请求直接失败
```

CRE 里没有 Subscription、没有 LINK 余额、没有“先冻结、再结算”这个流程。工作流的部署和管理走的是另一套东西：账号、组织、部署审批、registry（注册表）。你在 47 篇里见过的 `cre account access`（申请部署权限）和 `cre registry list`（看组织里的 registry），就是这套新机制的一部分。

所以这篇的写法也要跟着变：不讲“多少钱一次”，而是讲三件事——**钱花在哪、额度卡在哪、怎么控制**。这三件都是官方文档里能查到的，也是部署之前真正需要想明白的。

|  | Functions 时代 | CRE |
|---|---|---|
| 计费入口 | Subscription（订阅） | 没有订阅这个概念 |
| 付费方式 | 往订阅里充 LINK | 没有公开的按次收费 |
| 费用构成 | Gas 成本 + 美元计价的 premium（换算成 LINK） | 见下文：部署、写链、调 API 各有各的账 |
| 余额不够会怎样 | 请求失败 | 不适用，没有余额这个概念 |
| 官方价目表 | 有，按网络列出 premium | 没有，官方文档里找不到 Billing 页面 |
| 真正的“预算” | 订阅余额 | 服务配额（额度） |

## 二、Functions 时代的订阅是怎么收费的

要理解 CRE 为什么没有订阅，先花一点时间把 Functions 的旧模型讲清楚。不是为了怀旧，而是因为网上现在还能搜到大量 Functions 的计费教程，如果你分不清新旧，很容易把旧模型套到 CRE 头上。

Functions 的计费分两步走。第一步是请求的时候：系统先估算这次请求要花多少钱。估算的公式大概是这个意思：

```
预估 Gas 成本 = 高估的 Gas 价格 ×（固定开销 + 回调 Gas 上限）
预估总费用 = 预估 Gas 成本（换算成 LINK）+ premium
```

这里有两个细节值得注意。第一，Gas 价格是“高估”的——故意按比当前高一点的价格算，留出波动的余地，免得请求执行到一半 Gas 涨价了不够付。第二，premium 是按美元计价的，但从来不用美元结算，系统在请求那一刻按喂价把它换算成 LINK。

估算完，系统把这笔预估费用从你的订阅余额里冻结起来。第二步是请求完成的时候：按实际用的 Gas 重新算一遍真正的费用，从订阅余额里扣掉，多退少补，冻结解除。

这套模型有两个特点。第一，**费用和你的合约逻辑直接挂钩**：回调 Gas 上限设得越高，预估费用就越高；回调函数写得越复杂，实际费用也越高。第二，**余额是你自己管的**：充多少、花多少、什么时候没钱了，都是订阅余额上看得见的数字。

CRE 把这套东西整个拿掉了。没有订阅余额可以充，没有预估冻结，也没有“回调 Gas 上限”这个参数。取而代之的，是下面要讲的几笔分开算的账。

## 三、现在真正要花钱的四个地方

CRE 的工作流跑起来，钱不是交给一个地方的，而是分四处花。每一处的收费方、付费方式都不一样，分开看才不会算糊涂。

### 1. 本地模拟：不花钱

这是 47 篇讲过的，也是 CRE 里最友好的设计：本地模拟不需要审批、不需要 LINK、不需要订阅。在自己电脑上跑 `cre workflow simulate`，调的是真实的 API、读的是真实的公链，但**模拟默认不广播交易**，所以不产生链上费用。

模拟的唯一成本是你自己的电脑和时间。练手、调试、改代码，都应该尽量在模拟这一步完成——因为这是整个流程里唯一完全免费的一环。

### 2. 部署：看你选哪种 registry

部署的时候，费用取决于你选的是哪种 registry（47 篇讲过，部署目标在 `workflow.yaml` 里用 `deployment-registry` 指定）：

|  | 私有 registry（private） | 链上 registry（onchain:ethereum-mainnet） |
|---|---|---|
| 部署操作怎么授权 | 用你的 CRE 登录会话授权 | 向以太坊主网的 Workflow Registry 合约发交易，用关联的钱包密钥授权 |
| 要不要付 Gas | 不用 | 要，付以太坊主网 Gas |
| 适合谁 | 练手、测试、内部项目 | 正式的生产部署 |
| 组织额度 | 每个组织最多 3 个工作流 | 每个组织最多 1 个关联密钥，每个密钥最多 3 个工作流 |

也就是说，选私有 registry 练手，部署本身不花钱；选链上 registry 上生产，部署那一步就要付一笔以太坊主网的 Gas。Gas 价格随网络波动，部署前记得给关联的钱包留够主网 ETH，不然部署会失败。

### 3. 工作流自己写链：Gas 是你的密钥在付

这是最容易被忽略的一笔钱。工作流一旦部署到 DON 上跑起来，它里面的 EVM 写操作——比如把 API 取到的数据写回你的合约——是真的要上链的。每一笔写操作都是一笔链上交易，Gas 由工作流关联的密钥出。

这笔钱有几个特点：

- **按链上实际 Gas 结算**：写哪个链，就付哪个链的 Gas。写 Sepolia 测试网，ETH 是水龙头领的，不花钱；写以太坊主网，付的就是真金白银的主网 Gas。
- **和执行次数直接挂钩**：Cron 每 30 秒触发一次、每次都写链，一个月就是约 8.6 万次写操作，Gas 是按次累加的。触发频率是成本的第一杠杆，后面还会细讲。
- **有单笔上限**：官方配额规定，单笔 EVM 交易的 Gas 上限是 10,000,000。这是个上限，不是典型值——正常的数据写回操作用不了这么多，但你的回调函数如果写得太复杂，单笔 Gas 就会往上走。

### 4. 调用的外部 API：API 商在收费，不关 CRE 的事

工作流调的 API 如果是付费的，费用是 API 商收的，和 CRE 没有关系。两种常见情况：

- **传统 API 密钥模式**：比如天气、行情这类 API，按调用次数或套餐收费。你在 `secrets.yaml` 里声明的 API 密钥、对应的套餐和配额，都是你和 API 商之间的事。
- **x402 按次付费模式**：这是一种比较新的模式，API 不用密钥，改成每次调用付一小笔稳定币。Chainlink 官方的 x402 演示项目里，创建一个价格提醒要付 0.01 USDC。CRE 的工作流可以直接调这种 x402 保护的 API，费用按次结算，用 USDC 付。

这一笔钱经常被漏算：工作流本身的执行不收费，不代表调用是免费的。Cron 设得太密，API 的账单也会跟着涨。

| 花钱的地方 | 谁收钱 | 用什么付 | 能不能省 |
|---|---|---|---|
| 本地模拟 | 不花钱 | — | 已经是免费的 |
| 部署（私有 registry） | 不花钱 | — | — |
| 部署（链上 registry） | 以太坊网络 | 主网 ETH（Gas） | 练手别用链上 registry |
| 工作流写链 | 各条链的网络 | 对应链的 Gas 代币 | 降低触发频率、少写链 |
| 调付费 API | API 商 | 按 API 商的规则（密钥套餐 / x402 的 USDC） | 降低调用次数、用缓存 |

## 四、额度：CRE 真正的“预算”是配额

既然没有按次收费、没有订阅余额，那什么在管着你“能跑多少”？答案是**服务配额（Service Quotas）**。这是官方文档里专门有一页讲的东西（最后更新 2026 年 10 月 29 日，页面上注明“可能调整”），也是目前 CRE 里唯一成体系的“预算”。

配额分三个层级，像三道关卡一样套在一起。

### 第一道：组织级

| 配额 | 数值 |
|---|---|
| 每个组织最多用户数 | 40 |
| 私有 registry：每个组织最多工作流数 | 3 |
| 链上 registry：每个组织最多关联密钥数 | 1 |
| 链上 registry：每个密钥最多工作流数 | 3 |

注意这个数字：**一个组织最多只能有 3 个工作流**（私有和链上各算各的）。这意味着部署名额本身就是稀缺的，别拿生产环境的名额练手——练手用私有 registry 的 staging 目标，生产名额留给真正要上线的东西。额度不够可以找 Chainlink 申请提高，官方文档里写了联系入口。

### 第二道：每个工作流

| 配额 | 数值 |
|---|---|
| 一个工作流最多触发器数 | 10 |
| Cron 触发器最快间隔 | 30 秒 |
| HTTP 触发器速率 | 每 30 秒 1 次 |
| 链上事件触发器速率 | 每 6 秒 10 个事件 |
| 单次执行最长总时间 | 5 分钟 |
| 编译后的 WASM 体积 | 100 MB（压缩后 20 MB） |
| 工作流配置大小 | 50 KB |
| 单次执行返回的数据大小 | 100 KB |
| 单次执行分配的内存 | 100 MB |

Cron 最快 30 秒这个数字值得算一笔账：一个触发器按最快速度跑，一天最多触发 2,880 次，一个月约 86,400 次。如果每次触发都写链、都调付费 API，一个月就是 8.6 万次写链和 8.6 万次 API 调用。这就是为什么“触发频率”是成本的第一杠杆——额度允许你跑这么快，不代表你应该跑这么快。

### 第三道：每次执行

| 配额 | 数值 |
|---|---|
| 能力调用最大并发数 | 30 |
| 单次能力调用最长耗时 | 3 分钟 |
| 共识调用次数 | 每次执行最多 50 次 |
| 链上读调用 | 每次执行最多 15 次 |
| HTTP 请求 | 每次执行最多 15 次 |
| HTTP 响应大小 | 250 KB |
| 链上写目标链数量 | 最多 10 条 |
| 单笔 EVM 交易 Gas 上限 | 10,000,000 |
| 密钥读取 | 每次执行最多 5 次调用 |
| 日志 | 每行 1 KB、每次执行最多 1,000 行 |

这张表其实是一份“成本控制清单”：每次执行最多调 15 次 API、最多读 15 次链、最多写 10 条链。写工作流的时候，照着这张表数一数自己的调用次数，就知道一次执行大概是什么量级。

本地模拟也可以提前按生产额度测：`cre workflow simulate` 默认就会按生产额度强制执行，超了会直接报错；想看完整的额度数值，可以跑 `cre workflow limits export` 导出来。部署之前先在模拟里把超限问题暴露出来，比部署之后再改便宜得多。

## 五、测试环境和生产环境的成本有什么不一样

47 篇讲过，`workflow.yaml` 里默认有 staging 和 production 两套目标。这个区分不只是配置不同，成本结构也完全不一样。

|  | 测试环境（staging） | 生产环境（production） |
|---|---|---|
| 部署 registry | 私有 registry | 链上 registry（正式）或私有 registry |
| 部署要不要 Gas | 不用（登录会话授权） | 链上 registry 要付主网 Gas |
| 写链的 Gas | Sepolia 测试网，ETH 水龙头领的 | 主网，付真金白银的 Gas |
| 调 API 的费用 | 一样要付（API 商不分测试生产） | 一样要付 |
| 额度 | 和生产同一套配额 | 同一套配额 |
| 模拟 | 免费，随便跑 | — |

这里最容易犯的错，是把测试环境的“免费”错当成生产也免费。在 Sepolia 上跑一个月不花钱，不代表主网也一样——主网的 Gas、付费 API 的调用，都是按次计费的。部署到生产之前，先把触发频率、每次执行的调用次数、写链次数这三件事算一遍，再决定上不上生产。

还有一个方向的提醒：**测试环境的 API 费用一样要付**。API 商不区分你的请求来自测试还是生产，调了就计费。测试的时候用免费额度的 API、或者 mock 数据，是很常见的省钱办法。

## 六、怎么写工作流才能少花冤枉钱

前面讲的都是“钱花在哪”，这一节讲“怎么少花”。六条，都是从配额和计费结构里直接推出来的。

### 1. 触发频率按数据的变化速度设，别按最快设

Cron 最快可以 30 秒，但不代表就要设 30 秒。先问一句：我要的数据多久变一次？天气数据一小时变一次，设 30 秒跑就是 120 倍的浪费——120 次执行里 119 次写回去的是同一个数字。新闻应用同理，没新文章的时候跑也是白跑。

一个简单的判断方法：**触发间隔不要短于数据的更新间隔**。价格数据可能几分钟一变，天气一小时一变，新闻更慢。按这个节奏设 Cron，执行次数立刻降下来。

### 2. 一次执行里别重复调同一个接口

每次执行最多调 15 次 HTTP 请求，这个额度不难撞上。常见的情况是：一个工作流里既要读价格、又要读天气、又要读新闻，三个 API 各调一次没问题；但如果同一个接口在不同步骤里反复调，15 次很快就用完了。

HTTP 响应还可以缓存 10 分钟——同一个工作流在 10 分钟里重复请求同一个地址，可以直接用缓存的结果，不用再调一次。写代码的时候有意识地复用结果，比事后优化管用。

### 3. 写链是花钱最多的地方，能链下算的别上链

一次执行里，读链、调 API 都是链下成本，真正上链的只有写操作。数据处理、格式转换、判断逻辑，全部应该在工作流里算完，只把最终结果写一次上链。

反过来最容易犯的错是：每算一步就写一次链。中间结果不需要上链，写上去除了花 Gas 没有任何好处，还会让每次执行的写操作次数翻倍。

### 4. 先模拟，再部署

模拟免费，还能按生产额度测。`cre workflow simulate` 默认就强制执行生产额度，超了直接报错。部署之前先在模拟里跑通、把超限问题解决掉，比部署之后发现工作流跑不起来、再改再部署便宜得多——链上 registry 的每次部署都是要付 Gas 的。

### 5. 部署之后盯着执行记录看

部署之后，工作流的执行记录在平台界面里看（工作流 → Execution → Logs），也可以在终端跑 `cre execution list`。重点看两件事：**失败重试**和**异常高频触发**。

失败重试是最常见的烧钱方式：工作流因为某个 API 超时失败了，触发器还在按 Cron 继续跑，每次都失败、每次都重试，Gas 和 API 调用照常花，链上却什么都没写成。HTTP 触发器的限速（每 30 秒 1 次）能拦住外部的突发请求，但拦不住你自己的 Cron 设错了、或者逻辑里形成了死循环。定期看一眼执行记录，比月底看账单管用。

### 6. 额度先算好，别拿生产名额练手

一个组织只有 3 个工作流名额（私有和链上各算各的）。练手、试模板、跑演示，都用私有 registry 的 staging 目标；生产名额只给真正要上线的东西。名额用完了再申请提高要走流程，提前规划比事后申请快。

## 七、经常踩的坑

**以为要先充 LINK、开订阅。**

CRE 没有订阅、没有 LINK 余额。照着 Functions 的老教程去找 Subscription 页面是找不到的，这不是你操作错了，是产品本身换了。

**以为能查到“跑一次多少钱”的价目表。**

截至 2026 年 11 月 26 日，官方没有公布 CRE 每次执行的定价。网上如果有人说“CRE 跑一次收 X 个 LINK”，先问他来源是哪里——官方文档里没有这个数字，写这篇的时候能找到的第三方分析也明确说了，没有公开的每次运行定价和 LINK 收费路径。

**把测试网的免费当成生产也免费。**

Sepolia 的 ETH 是水龙头领的，写链不花钱；主网的 Gas 是真金白银。部署到生产之前，先把触发频率、每次执行的调用次数、写链次数算一遍。

**Cron 设 30 秒跑天气、跑新闻。**

数据一小时才变一次，30 秒跑一次就是 120 倍的浪费。触发间隔不要短于数据的更新间隔。

**链上 registry 的部署忘了留主网 ETH。**

链上 registry 的部署要向以太坊主网发交易，关联的钱包里没有主网 ETH，部署会直接失败。部署之前先检查钱包余额。

**付费 API 的钱没算进成本。**

工作流本身的执行不收费，不代表调用免费。API 密钥套餐、x402 按次付费（比如 0.01 USDC 一次），都是要另外算的账。

**模拟的时候没按生产额度测，部署后才发现超限。**

`cre workflow simulate` 默认就按生产额度强制执行，超了会报错。部署之前先在模拟里把这个问题解决掉，别等到部署之后再改——链上 registry 的每次部署都要付 Gas。

## 总结

- Functions 的 Subscription 计费模型已经跟着产品一起退役了：充 LINK、预估冻结、按实际结算，那套流程在 CRE 里不存在。
- 截至 2026 年 11 月 26 日，Chainlink 官方没有公布 CRE 每次执行的定价，也没有 Billing 页面。网上流传的“CRE 跑一次多少钱”没有官方来源，别轻信。
- 现在真正要花钱的有四个地方：本地模拟免费；部署看 registry，私有不花 Gas、链上要付主网 Gas；工作流自己写链，Gas 由你的密钥出；调付费 API，API 商按自己的规则收费（密钥套餐或 x402 按次付费）。
- CRE 真正的“预算”是服务配额：一个组织最多 3 个工作流（私有和链上各算各的）、一个工作流最多 10 个触发器、Cron 最快 30 秒、单次执行最长 5 分钟、每次执行最多 15 次 HTTP 请求和 15 次链上读、单笔写链 Gas 上限 10,000,000。额度可以申请提高。
- 测试环境和生产环境的成本结构不一样：Sepolia 写链不花钱，主网要付真金白银的 Gas；但 API 的费用测试生产都要付。
- 成本控制的六条：触发频率按数据变化速度设、一次执行别重复调接口、能链下算的别上链、先模拟再部署、部署后盯着执行记录看、别拿生产名额练手。
- 容易踩的坑：找 Subscription、找价目表、把测试网免费当成生产免费、Cron 设太密、部署忘留主网 ETH、漏算 API 的钱、模拟没按生产额度测。
