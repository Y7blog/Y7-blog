> 从所有权、身份、资产和应用架构四个角度，理解 Web3 到底改变了什么。

如果你第一次接触 Web3，可能会有一个很常见的疑问：

**Web3 到底是什么？**

有人说 Web3 就是区块链。

有人说 Web3 就是加密货币。

也有人说 Web3 是下一代互联网。

这些说法不能算完全错误，但如果只停留在这里，还是很难真正理解 Web3。

因为 **Web3 并不是简单地“把 Web2 搬到区块链上”**。

它真正值得理解的地方，是互联网中一些原本由平台掌握的东西，开始尝试交给用户自己掌握。

比如：

- 我的身份是谁？
- 我的资产属于谁？
- 我的数据由谁控制？
- 我能不能不依赖某个平台使用自己的资产？
- 一个应用关闭以后，我拥有的东西还能不能继续存在？

这些问题，才是理解 Web3 的关键。

这篇文章不讨论某个具体项目，也不讨论某种 Token 是否值得投资。

我们只解决一个最基础的问题：

**Web3 和我们已经用了很多年的 Web2，到底有什么区别？**

---

## 一、先从 Web1、Web2 和 Web3 说起

如果想理解 Web3，可以先简单回顾一下互联网的发展。

### Web1：主要是“读”

早期互联网的特点比较简单。

网站把信息展示给用户，用户主要负责阅读。

你可以把它理解成：

> **网站发布内容 → 用户阅读内容**

这个阶段的互联网互动能力比较有限。

用户可以访问网页，但自己参与创造内容的能力没有今天这么强。

---

### Web2：变成“读 + 写”

后来互联网进入 Web2。

最大的变化之一，就是：

**用户开始真正参与内容生产。**

比如：

- 发布微博
- 上传视频
- 写博客
- 发朋友圈
- 发布短视频
- 在线购物
- 在线游戏
- 使用各种 SaaS 应用

互联网从：

> “我看别人发布的内容”

逐渐变成：

> “我也可以在互联网上创造内容。”

所以我们今天使用的大多数互联网产品，都属于 Web2。

搜索引擎、社交平台、电商平台、视频网站、网盘、游戏等，都建立在这种模式之上。

---

## 二、那 Web2 有什么问题？

Web2 本身并没有什么“错”。

实际上，Web2 给互联网带来了非常大的便利。

问题在于：

**大部分互联网服务都建立在平台中心化的架构上。**

举一个非常简单的例子。

你注册了一个社交平台账号。

你拥有：

- 用户名
- 头像
- 粉丝
- 内容
- 私信
- 收藏
- 社交关系

看起来这些东西都是“你的”。

但从技术架构上来说，它们通常还是存储在平台自己的服务器和数据库中。

你的账号能不能使用？

平台说了算。

你的内容能不能被推荐？

平台的算法决定。

你的账号是否被封禁？

平台可以决定。

你的数据能不能导出？

也受到平台规则限制。

所以 Web2 有一个非常明显的特点：

> **用户使用互联网服务，但平台掌握着底层基础设施和账户体系。**

这就引出了 Web3 想解决的一些问题。

---

# 三、Web3 最核心的变化：所有权

理解 Web3，我认为最重要的一个词就是：

**Ownership —— 所有权。**

在传统互联网里，你可能拥有一个账号。

但这个账号通常属于某个平台的账户体系。

而在 Web3 中，很多应用尝试使用区块链作为资产和状态的基础设施。

这时候，用户可以通过自己的钱包与区块链进行交互。

例如：

你拥有一个钱包地址。

这个地址下面可能存在：

- ETH
- ERC-20 Token
- NFT
- 链上交易记录

这些资产的状态记录在区块链网络上，而不是某一个 Web2 平台的数据库里。

这意味着：

> **应用可以变化，但链上的资产不一定随着某个应用消失。**

这就是 Web3 和传统互联网非常重要的区别之一。

---

# 四、钱包到底是什么？

说到 Web3，就绕不开钱包。

很多刚接触 Web3 的人会把钱包理解成：

> “存放加密货币的 App。”

这个理解不够准确。

钱包更重要的作用，是帮助你管理**账户和密钥**，并代表你与区块链进行交互。

你可以把它简单理解成：

> **钱包是你进入 Web3 世界的一把钥匙。**

传统互联网登录一个网站，通常是：

```text
用户名 / 邮箱
      ↓
     密码
      ↓
  平台服务器
      ↓
   你的账户
```

Web3 则可以是：

```text
 钱包
  ↓
 签名
  ↓
区块链
  ↓
你的地址与链上状态
```

两者最大的区别之一，就是：

**Web2 的身份通常由平台创建和管理，Web3 则可以由用户自己控制密钥对应的账户。**

当然，这也意味着用户需要承担更多责任。

如果私钥或者助记词丢失，通常没有一个中心化客服可以直接帮你“重置密码”。

所以：

**Web3 的自由和责任是同时存在的。**

---

# 五、Web3 的第二个关键词：身份

Web2 中，我们经常拥有很多账号。

比如：

```text
微信账号
微博账号
邮箱账号
游戏账号
电商账号
论坛账号
```

每个平台都有自己的账户系统。

于是你可能会有几十个甚至上百个账号。

而 Web3 尝试建立一种不同的身份模式：

> **用户可以通过自己的钱包地址进入不同的应用。**

比如：

```text
钱包地址
   ↓
Web3 应用 A
   ↓
Web3 应用 B
   ↓
Web3 游戏
   ↓
DeFi 应用
```

当然，这并不意味着“一个钱包地址就等于完整的现实身份”。

它更像是一种：

**用户自己控制的链上身份入口。**

你可以用同一个地址与不同的链上应用进行交互。

---

# 六、Web3 的第三个关键词：数字资产

这是 Web3 最容易被大众看到的部分。

比如：

- ETH
- ERC-20 Token
- NFT

这些都可以成为链上的数字资产。

但需要特别注意：

**Web3 ≠ 加密货币。**

加密货币只是 Web3 生态中的一部分。

如果只把 Web3 理解成：

> 买币 → 卖币 → 看价格

其实就把 Web3 的范围缩得太小了。

从开发者角度来看，Token 更像是一种可以在区块链网络中被程序识别、转移和管理的数字资产形式。

NFT 则可以表示具有唯一标识的链上资产。

例如一个 NFT 可以包含：

```text
Token ID
   ↓
Metadata
   ↓
图片 / 属性 / 描述
```

这也是后面学习 NFT 时必须理解的基础。

---

# 七、Web2 和 Web3 最大的区别之一：资产属于谁？

我们举一个游戏的例子。

假设你在一款 Web2 游戏里花了很多时间。

你获得：

- 游戏角色
- 武器
- 装备
- 游戏道具

这些东西看起来是你的。

但它们实际上通常存在于游戏公司的数据库里。

如果游戏停止运营：

```text
游戏服务器关闭
      ↓
游戏账号无法访问
      ↓
游戏道具也无法继续使用
```

而 Web3 游戏希望探索另一种模式。

部分资产可以通过 Token 或 NFT 的形式存在于区块链上。

例如：

```text
游戏
 ↓
NFT
 ↓
区块链
```

这样，资产的所有权记录就不完全依赖游戏自己的数据库。

这并不意味着所有 Web3 游戏都能做到真正的“资产跨游戏使用”。

**能不能使用、怎么使用，仍然取决于具体项目的技术设计。**

但这种“资产可以独立于单个平台存在”的思想，就是 Web3 非常重要的探索方向。

---

# 八、Web2 是“平台中心”，Web3 更强调“协议和网络”

这可能是 Web3 最难理解的地方。

我们再换一个例子。

假设你使用一个 Web2 社交平台。

整个系统大概可以理解成：

```text
        平台
         │
 ┌───────┼───────┐
 ↓       ↓       ↓
用户A   用户B   用户C
```

平台掌握：

- 用户账户
- 数据库
- 推荐系统
- 内容分发
- 权限

平台是整个系统的中心。

而 Web3 的很多应用会尝试把一部分核心状态放到公共区块链网络中：

```text
       区块链网络
      /    |    \
     /     |     \
  应用A   应用B   应用C
     \     |     /
      \    |    /
        用户钱包
```

这里有一个很重要的变化：

**应用不一定是资产和状态的最终控制者。**

应用更像是在调用底层网络。

---

# 九、这也是 dApp 和传统 App 的区别

我们以后会经常看到一个词：

**dApp**

也就是：

> decentralized application  
> 去中心化应用

它可以简单理解成：

> **使用区块链作为核心后端基础设施的一类应用。**

传统 App 可以简单理解成：

```text
前端
 ↓
服务器
 ↓
数据库
```

而一个典型的 Web3 dApp 可能更接近：

```text
前端
 ↓
钱包
 ↓
RPC
 ↓
智能合约
 ↓
区块链
```

如果还需要外部数据，则可能进一步出现：

```text
区块链
  ↓
Oracle
  ↓
外部数据
```

这就是为什么学习 Web3 开发时，我们后面会逐渐遇到：

- Smart Contract
- Solidity
- Token
- Oracle
- Chainlink
- Wallet
- RPC
- dApp

它们并不是一堆孤立的概念。

而是在共同组成一个 Web3 应用。

---

# 十、Web3 并不是“完全去中心化”

这里需要纠正一个非常常见的误解。

很多人第一次听到 Web3，会觉得：

> Web3 = 所有东西都去中心化。

实际上并不是。

一个真实的 Web3 应用，很可能同时包含：

```text
中心化组件
+
去中心化组件
```

例如：

```text
前端网站
   ↓
服务器 / CDN
   ↓
钱包
   ↓
智能合约
   ↓
区块链
```

前端网站完全可以部署在传统服务器或者云服务上。

但是核心资产和关键状态可能由智能合约管理。

所以更准确的理解是：

> **Web3 不是要求整个互联网彻底去中心化，而是在探索哪些部分应该由用户、协议和开放网络共同控制。**

这比简单喊一句“去中心化”更接近实际开发。

---

# 十一、用四个问题理解 Web2 和 Web3

如果你觉得前面的概念还是有点多，可以先记住下面四个问题。

## 1. 谁拥有资产？

**Web2：**

资产通常由平台数据库记录和控制。

**Web3：**

部分资产可以由区块链记录，用户通过钱包控制相关账户。

---

## 2. 谁控制身份？

**Web2：**

平台创建并管理你的账户。

**Web3：**

钱包可以作为用户进入不同应用的账户入口。

---

## 3. 应用的数据和状态在哪里？

**Web2：**

主要由平台自己的服务器和数据库维护。

**Web3：**

部分核心状态可以由区块链和智能合约维护。

---

## 4. 应用和资产是什么关系？

**Web2：**

资产通常和平台绑定。

**Web3：**

尝试让部分资产脱离单一应用，成为可以在开放网络中验证和交互的数字资产。

---

# 十二、一张表看懂 Web2 和 Web3

| 对比 | Web2 | Web3 |
|:---:|:---:|:---:|
| 账户 | 平台账户 | 钱包 / 链上账户 |
| 身份 | 平台管理 | 用户控制密钥 |
| 数据 | 平台数据库为主 | 部分状态由区块链维护 |
| 资产 | 平台内部记录为主 | 可以成为链上数字资产 |
| 应用后端 | 服务器 + 数据库 | 智能合约 + 区块链 |
| 登录方式 | 用户名 / 密码等 | 钱包签名等 |
| 平台角色 | 通常是核心控制者 | 更强调协议和开放网络 |
| 数据公开性 | 通常由平台决定 | 链上数据通常可公开验证 |
| 可组合性 | 平台之间相对独立 | 链上协议可以相互组合 |
| 用户责任 | 平台承担较多账户管理 | 用户需要承担更多密钥管理责任 |

这张表并不是说 Web3 在所有方面都优于 Web2。

实际上，Web2 在性能、用户体验、成本和成熟度等方面仍然具有非常明显的优势。

Web3 真正有意思的地方，是它提供了一套不同的技术和组织方式。

---

# 十三、Web3 真正改变的是什么？

如果一定要用一句话概括：

> **Web2 更关注“互联网服务”，Web3 更进一步探索“互联网中的所有权”。**

Web2 解决了：

> 如何让全世界的人更方便地获取信息、交流和使用互联网服务？

Web3 则进一步提出：

> 如果数字资产、数字身份和数字规则也可以存在于开放网络中，会发生什么？

这也是为什么 Web3 不应该简单理解成“加密货币”。

加密货币只是其中一个应用方向。

真正值得理解的是背后的基础设施：

```text
密码学
   ↓
钱包与身份
   ↓
区块链
   ↓
智能合约
   ↓
Token / NFT
   ↓
Oracle
   ↓
 dApp
```

而我们接下来学习的内容，其实就是沿着这条路线一步一步展开。

---

# 十四、从 Web3 到智能合约

到这里，你可能会产生下一个问题：

> 如果 Web3 应用不完全依赖传统服务器，那么程序到底运行在哪里？

答案之一就是：

**智能合约。**

智能合约可以简单理解成：

> **部署在区块链上的程序。**

它可以按照预先写好的规则执行逻辑，并修改区块链上的状态。

例如：

```text
用户
 ↓
钱包签名
 ↓
发送交易
 ↓
智能合约
 ↓
执行程序逻辑
 ↓
区块链状态发生变化
```

这也是为什么 Web3 开发和普通 Web 开发相比，会多出一个非常重要的学习方向：

**Smart Contract。**

而这正是下一阶段要进入的内容。

---

# 十五、最后重新理解一次 Web3

如果把整篇文章压缩成几个关键词：

**Web2：**

> 平台 → 账户 → 服务 → 数据

**Web3：**

> 用户 → 钱包 → 资产 → 协议 → 区块链

Web3 并不是简单地把网站换成区块链。

它真正想探索的是：

**当用户可以自己控制身份和部分数字资产，当应用可以建立在开放的区块链网络和智能合约之上，互联网会变成什么样？**

这个问题，到现在其实还没有一个最终答案。

但对于一个刚开始学习区块链开发的人来说，至少可以先建立一个正确的认知：

> **不要把 Web3 等同于“炒币”。**
>
> **Web3 更值得研究的地方，是区块链、钱包、智能合约、数字资产和开放网络组合起来之后，能不能构建出一种不同于传统互联网的应用模式。**

理解了这一点，再去学习钱包、Token、智能合约和 dApp，很多概念就不会再是孤立的名词了。
