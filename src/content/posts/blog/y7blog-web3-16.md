上一篇文章里，我们学会了验证合约源码：打开 Etherscan，看到的不再是一串天书般的字节码，而是能逐行阅读的 Solidity 代码。

今天我们换个角度，打开你自己的钱包看一眼。除了 ETH，你很可能还看到 USDT、LINK，或者别的什么代币。它们安安静静地躺在钱包的资产列表里，带着各自的余额。

但你有没有想过几个很基本的问题：

**这些代币到底是什么东西？它们「存在」哪里？当你把 10 个 USDT 转给朋友时，链上到底「转」了什么？**

今天这篇文章，就要把代币这件事彻底讲明白。而答案的核心，是一个你一定听说过、但可能从没真正理解过的名字：**ERC20**。

读完之后，你会明白钱包里的每一个代币是怎么来的、怎么转的，以及——怎么分辨它是不是假的。

## 一、你的代币，到底存在哪？

先说一个大多数新手都会搞错的直觉：很多人以为，代币就像手机里的照片文件一样，「存在」钱包里，转账就是把文件从一个钱包「发」到另一个钱包。

**不是这样的。**

真相是：钱包里其实什么代币都没有。你的钱包（比如 MetaMask）真正保存的只有一样东西——**你的私钥**。私钥能证明「这个地址是你的」，除此之外，钱包本身不存放任何资产。

那代币存在哪？答案是：**存在发行它的那个智能合约里的一张「余额表」上。**

### 一张所有人都能查的公开账本

想象一个小区的物业办公室，墙上挂着一本业主名册：

```
101 室：张三，余额 1,000
102 室：李四，余额 500
103 室：王五，余额 0
```

ERC20 代币合约里，就有这样一本「名册」。只不过它不是写在纸上，而是写在合约代码里的一张表，技术上叫 `mapping`（映射）：

```solidity
mapping(address => uint256) balances;
```

翻译成人话就是：**地址 → 余额，一一对应**。

- 你的地址后面写着 100，就表示你有 100 个这个代币；
- 朋友的地址后面写着 0，就表示他一个也没有；
- 这张表存在区块链上，任何人随时都能查，任何人都改不了——除了合约自己按规则改。

所以，**一个 Token 从来不是一个「东西」，它只是一个合约账本上的一行数字。** 你「拥有」代币的意思，其实是：那张公开账本上，你的地址那一行写着一个属于你的数字。

### ETH 和 Token，有什么区别？

这里要分清两个概念，很多新手会把它们混为一谈：

|  | ETH（以太币） | ERC20 Token（代币） |
|---|---|---|
| 身份 | 以太坊自带的「原生货币」 | 某个智能合约发行的「记账凭证」 |
| 存在哪 | 直接记在你的账户余额里，是链本身的一部分 | 记在某个代币合约的余额表里 |
| 谁发行 | 没人发行，是以太坊网络的一部分 | 任何人写个合约都能发行 |
| 转账方式 | 直接改两个账户的余额 | 调用代币合约，让它改余额表 |

打个比方：**ETH 是这个国家的法定货币，Token 是各个公司自己发的「购物卡」「积分」「会员券」**。购物卡能在很多地方用，是因为大家都认同一种通用的卡片格式——而 ERC20，就是这个「通用格式」。

> 💡 **一句话记住**：钱包不存代币，代币是合约里的一张余额表；你钱包里显示的余额，只是钱包帮你去各个合约的账本上查出来的数字。

## 二、ERC20 是什么？先定一个「通用标准」

如果每个项目都按自己的想法发代币，钱包、交易所、去中心化交易所（DEX）就要为每一种代币单独写一套适配代码——新代币一多，整个生态就乱套了。

所以在 2015 年，以太坊开发者 Fabian Vogelsteller 和 Vitalik Buterin 一起提出了一份提案：**EIP-20**。它规定：所有想叫自己「代币」的合约，都必须提供同一套「标准接口」——也就是同样名字的函数、同样格式的事件。

这套标准后来就叫 **ERC20**（ERC 是 Ethereum Request for Comments 的缩写，20 是提案编号）。

### 一个「通用插座」的比喻

ERC20 就像插座的国家标准：

- 不管哪个厂家生产电器，只要插头符合标准，就能插进任何一家符合标准的插座；
- 不管哪个项目发行代币，只要合约符合 ERC20 标准，任何钱包、交易所、DEX 就能直接支持它，不用单独适配。

这就是为什么 USDT、USDC、LINK、UNI 这些完全不同的代币，你的钱包都能一视同仁地显示、转账——因为它们背后都遵守同一套 ERC20 规则。

### 标准到底规定了什么？

EIP-20 规定的内容其实很少，一共只有三样东西：

| 内容 | 数量 | 作用 |
|---|---|---|
| **核心函数** | 6 个 | 代币必须提供的操作：查总量、查余额、转账、授权、查授权、代扣转账 |
| **事件** | 2 个 | 代币发生重要变化时必须「广播」：转账事件、授权事件 |
| **可选信息** | 3 个 | 代币的名字、符号、小数位数（建议提供，但不是强制） |

注意一个关键点：**ERC20 只规定「接口」，不规定「实现」**。也就是说，标准只说「你的合约必须有一个叫 `transfer` 的函数，长这个样子」，至于你内部怎么写、余额表怎么维护、要不要加增发功能，标准一概不管。

这也正是下一节要讲的：六个函数，就是一个 Token 的全部「招式」。

> 💡 **一句话记住**：ERC20 不是一种代币，而是一份「代币应该长什么样」的约定。有了它，钱包和交易所才能认出全世界成千上万种不同的代币。

## 三、六个函数：一个 Token 的全部「招式」

一个 ERC20 代币合约，对外只提供六个核心操作。钱包、交易所、DEX 在背后调用的，翻来覆去就是这六个函数。我们一个一个讲清楚。

### 先看总览表

| 函数 | 作用 | 打个比方 |
|---|---|---|
| `totalSupply()` | 查这个代币一共发行了多少 | 问物业：小区一共发了多少张购物卡 |
| `balanceOf(地址)` | 查某个地址有多少代币 | 问物业：张三名下有多少余额 |
| `transfer(给谁, 多少)` | 把自己的代币转给别人 | 你亲手把钱转给朋友 |
| `approve(给谁, 多少)` | 授权别人最多可以从你这里拿多少 | 给代扣协议签个额度 |
| `allowance(谁, 给谁)` | 查还剩多少授权额度 | 查代扣协议还剩多少额度没用 |
| `transferFrom(从谁, 给谁, 多少)` | 被授权的人替别人转账 | 代扣方按协议直接划款 |

下面是这六个函数的标准样子（来自 EIP-20，语法是 Solidity 0.4.17 及以上版本）：

```solidity
function totalSupply() public view returns (uint256)
function balanceOf(address _owner) public view returns (uint256 balance)
function transfer(address _to, uint256 _value) public returns (bool success)
function approve(address _spender, uint256 _value) public returns (bool success)
function allowance(address _owner, address _spender) public view returns (uint256 remaining)
function transferFrom(address _from, address _to, uint256 _value) public returns (bool success)
```

看不懂代码也没关系，你只需要记住每一行的意思：

### 1. `totalSupply()`：一共发行了多少

返回这个代币的总量。比如一个代币总量是 1,000,000，那就表示这张余额表上所有地址的数字加起来，等于 1,000,000。

### 2. `balanceOf(地址)`：查余额

输入一个地址，返回它在这个代币账本上的余额。你的钱包每次显示「你有 100 USDT」，背后就是调用了 USDT 合约的 `balanceOf(你的地址)`。

### 3. `transfer(给谁, 多少)`：转账

最常用的函数。你转 10 个代币给朋友，合约内部做的事只有两件：

```
你的余额 减 10
朋友的余额 加 10
```

就这么简单。同时合约还会发出一个 `Transfer` 事件（后面会讲），告诉全世界「这笔转账发生了」。

### 4. `approve(给谁, 多少)` 与 5. `allowance()`：授权与查额度

这两个函数是一对，专门管「授权」这件事，下一节会详细讲。这里先记住：`approve` 是你主动给某个地址（通常是某个应用的合约）开一个额度，`allowance` 是查这个额度还剩多少。

### 6. `transferFrom(从谁, 给谁, 多少)`：代扣转账

被授权的地址用这个函数，替你把代币转给别人。注意：它只能转你事先 `approve` 过的额度之内的数量，多一分都不行。

### 两个必须广播的「事件」

除了六个函数，标准还要求合约在两种情况下必须发出「事件」（Event）——相当于合约向全网喊一嗓子：

```solidity
event Transfer(address indexed _from, address indexed _to, uint256 _value)
event Approval(address indexed _owner, address indexed _spender, uint256 _value)
```

- 每次转账成功，必须发出 `Transfer` 事件；
- 每次授权成功，必须发出 `Approval` 事件。

事件有什么用？你想想第 13 篇讲的区块链浏览器：Etherscan 上的每一笔代币转账记录，就是从这些 `Transfer` 事件里读出来的。没有事件，浏览器就不知道「刚才发生了一笔代币转账」。

> 💡 **一句话记住**：六个函数就是代币的全部对外接口——查总量、查余额、自己转、授权别人、查额度、别人代转。再加两个事件负责「广播」。钱包和交易所天天打交道的，就是这几样东西。

## 四、一笔转账在链上到底发生了什么？

现在我们把前面学的东西串起来，完整走一遍：你把 10 个 USDT 转给朋友，链上到底发生了什么？

### 五个步骤

```
第 1 步：你在钱包里点「发送」，输入朋友地址和 10 USDT
第 2 步：钱包构造一笔交易，调用 USDT 合约的 transfer(朋友地址, 10 USDT)
第 3 步：你用私钥签名，付一点 ETH 做 Gas，交易广播上网
第 4 步：矿工/验证者打包交易，USDT 合约执行：
         你的余额 -10，朋友的余额 +10，同时发出 Transfer 事件
第 5 步：交易被打包进区块，全网确认；Etherscan 上出现这笔代币转账记录
```

请注意第 4 步：**链上没有任何「代币」在移动**。移动的不是代币，而是账本上的两个数字——你的那一行减 10，朋友的那一行加 10。仅此而已。

这就是为什么第 1 节说「Token 只是一行数字」。转账的本质，就是合约按规则改写自己账本上的数字。

### 小数位数：为什么 1 个代币不是「1」

这里有个新手最容易晕的细节：**链上没有小数**。合约里的余额，永远是整数。

那「0.5 个代币」怎么表示？靠一个叫 `decimals`（小数位数）的约定：

- 如果一个代币的 `decimals` 是 18，那么链上的 `1,000,000,000,000,000,000`（1 后面 18 个 0）才等于你看到的「1 个代币」；
- 18 位小数是最常见的选择，大多数代币都用它；
- USDT 和 USDC 比较特殊，它们的 `decimals` 是 6，所以链上的 `1,000,000` 才等于「1 USDT」。

所以钱包显示「你有 10.5 USDT」时，背后其实是：钱包去查了你的余额 `10,500,000`，再除以 10 的 6 次方，换算给你看。

> ⚠️ **新手常踩的坑**：在 Etherscan 上看代币转账，金额那一栏显示的可能是没换算过的原始大数字，别被那串 0 吓到——先看这个代币的 `decimals` 是几位，再换算。

### 转账代币，也要付 ETH 做 Gas

还有一个细节：转 USDT 的时候，你付的手续费是 **ETH**，不是 USDT。因为你的交易本质上是「调用 USDT 合约」，而调用任何合约都要消耗 Gas，Gas 只能用 ETH 支付。

所以钱包里如果 ETH 余额是 0，哪怕你有再多 USDT，也一枚都转不出去——这就是很多新手第一次转代币时遇到「余额不足」报错的原因：**缺的不是 USDT，缺的是付 Gas 的 ETH**。

## 五、授权 Approve：代币世界的「代扣协议」

六个函数里，最难理解、也最重要的是 `approve` 和 `transferFrom` 这一对。它们解决的是一个很现实的问题：

**如果某个应用需要替你转代币，怎么办？**

比如你想在去中心化交易所（DEX）上把 USDT 换成 ETH：DEX 的合约需要先拿到你的 USDT，再给你 ETH。但 DEX 的合约不能直接动你账本上的数字——你的余额只有你自己（通过 `transfer`）或者你授权过的人才能动。

于是 ERC20 设计了一套「授权—代扣」机制，分两步走：

### 第 1 步：你授权（Approve）

```
你调用 approve(DEX 合约地址, 100 USDT)
→ 意思是：我允许 DEX 合约最多从我这里拿走 100 USDT
```

这一步本身不转走任何代币，只是记下了一个额度，存在合约里的另一张表上：

```solidity
mapping(address => mapping(address => uint256)) allowance;
```

翻译成人话就是一张「谁授权给谁、额度多少」的表。

### 第 2 步：对方代扣（TransferFrom）

```
DEX 合约调用 transferFrom(你的地址, DEX 地址, 100 USDT)
→ 合约检查：你的授权额度够不够？够，就执行转账，同时把额度扣掉 100
```

整个流程画出来是这样的：

```
你 ── approve(DEX, 100) ──→ 代币合约：「记下了，DEX 最多拿 100」
DEX ── transferFrom(你, DEX, 100) ──→ 代币合约：「额度够，转账！余额改写，额度清零」
```

这和现实生活里的「代扣协议」一模一样：你给水电公司签个代扣授权，它每个月按账单从你卡里划钱——但划多少、划几次，都不能超过你签过的额度。

### 授权最大的风险：无限授权

很多应用为了省事，会请你授权一个「无限额度」——也就是 2 的 256 次方减 1，一个天文数字，约等于「随便拿」。这样你以后每次交易就不用重复授权了，方便是方便，但风险也很大：

> 一旦这个应用的合约出了问题、或者它本身就是恶意的，它就能把你钱包里这种代币**全部转走**，而你事先已经「同意」了。

所以请记住三条安全习惯：

1. **授权前先看额度**：钱包弹窗上会显示你要授权多少，养成看一眼的习惯；
2. **用完就撤销**：交易完成后，去 Etherscan 的 Token Approvals 页面（或 revoke.cash 这类工具）把不再用的授权撤销掉；
3. **定期检查**：每隔一段时间查一次，你到底给过哪些应用授权，额度还剩多少。

> 💡 **一句话记住**：授权不等于转账——授权本身一枚币都不会转走，但它给了对方「随时转走」的权力。额度就是你的防线，别轻易签无限额度。

## 六、四个新手最容易踩的坑

理解了 ERC20 的工作原理，最后提醒四个最常见的坑。它们都不是技术难题，而是「不知道就会吃亏」的常识。

### 坑 1：同名同符号的代币，可能是假的

ERC20 标准里，代币的名字（`name`）和符号（`symbol`）是**可选信息**，任何人发行代币时都可以随便填。也就是说，任何人都能发行一个名字也叫「Tether」、符号也叫「USDT」的代币。

分辨真假只有一个办法：**认合约地址，不认名字**。

- 真 USDT 在以太坊上的合约地址是公开可查的（可以去 CoinGecko、CoinMarketCap 或 Etherscan 官方页面核对）；
- 收到陌生人转来的「USDT」，先上 Etherscan 查它的合约地址，再决定信不信。

> ⚠️ **记住**：代币的名字和符号谁都能起，合约地址才是它的「身份证号」。

### 坑 2：ERC20 不保证「不能增发」

标准只规定了六个函数，**没有规定总量能不能变**。一个代币合约里如果写了 `mint`（增发）函数，项目方随时可以凭空造出新的代币，稀释你的持有。

怎么判断？两个办法：

- 查 `totalSupply()` 的历史变化——如果总量一直在涨，说明有人在增发；
- 读源码（第 14 篇教过你怎么验证和读源码）——看看有没有只有项目方能调用的 `mint` 函数。

### 坑 3：符合标准，不等于项目靠谱

ERC20 只是一份「接口约定」，它不管项目是做什么的、团队是谁、代码有没有漏洞。一个完全符合 ERC20 标准的代币，依然可以是骗局。

标准保证的是「钱包能认出它」，不是「它值得信任」。这两件事，一定要分开。

### 坑 4：转错链、转到不支持的地址，基本找不回来

代币存在某个链的某个合约里。如果你把以太坊上的 USDT 转到一个只支持另一条链的地址，或者转给了一个根本不支持这种代币的合约地址，这笔转账在链上是「成功」的——但对方永远收不到、你也拿不回来。

转账前养成一个习惯：**先小额试一笔，确认到账再转大额**。链上交易没有「撤回」按钮。

> ⚠️ **风险提示**：本文是知识科普，不是投资建议。任何代币在动手之前，都请先查合约地址、读源码、看清风险；涉及真实资产的操作，请务必先用小额在测试网练熟流程。

## 七、回顾：从第一篇到今天，我们走到了哪一步

不知不觉，这个系列已经写到第 15 篇了。我们不妨停下来，把学过的东西串成一条线——你会发现，每一篇都在为下一篇铺路：

## 总结

今天我们学了四件事：

1. **代币是什么**：不是存在钱包里的「东西」，而是某个智能合约账本上的一行数字；钱包只存私钥，余额是去合约上查出来的。
2. **ERC20 是什么**：2015 年提出的代币标准接口，规定了 6 个函数、2 个事件和 3 个可选信息，让所有钱包、交易所都能通用所有代币。
3. **转账和授权是怎么发生的**：转账只是改写账本上的两个数字；授权是「代扣协议」，`approve` 开额度、`transferFrom` 执行代扣；无限授权有风险，用完记得撤销。
4. **四个坑**：认合约地址不认名字；标准不管增发；符合标准不等于靠谱；转错链基本找不回来。

还要记住一个细节：**转代币也要付 ETH 做 Gas**，钱包里留一点 ETH 备用，别让代币「转不出去」。
