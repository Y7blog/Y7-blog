上一篇我们认识了 Oracle 这个「信使」：智能合约看不见外面的世界，需要有人把链外的数据安全地送进来。

但「有人送」只是讲清了原理。一个很实际的问题马上就来了：

**如果我今天就想写一个合约，让它知道 BTC 现在多少钱，我该从哪里开始？**

自己搭一套预言机？去雇一群节点？还是每天手动把价格写进合约？

都不用。Chainlink 早就把最常用的那部分数据，做成了一份「现成的价目表」，每天 24 小时不断更新，放在链上等你来读。它的名字叫 **Data Feeds（数据流）**，其中最常用的一种，就是**价格数据流（Price Feeds）**。

今天这篇文章，我们就把这份「价目表」彻底讲明白：它是什么、价格是怎么被送上链的、去哪里找到 BTC/USD 的地址，以及——最关键的一步——亲手写几行代码，让你的合约第一次「开口问价」。

---

## 一、Data Feeds 是什么：一份放在链上的「价目表」

先给 Data Feeds 一个最简单的定义：

> **Chainlink Data Feeds 是把真实世界的数据（最常见的是资产价格）持续搬上链、变成智能合约可以直接读取的链上数据的服务。**

换个更生活化的说法：

- 智能合约住在一间**密封的玻璃房**里，出不去，也看不见外面；
- 外面的集市上，BTC、ETH、黄金、美元汇率的价格每秒都在变；
- Data Feeds 就像一份**每天有人准时送进玻璃房的价目表**：上面写着「BTC/USD：97,000 美元」「ETH/USD：3,400 美元」，而且每过一会儿就有人来换一张新的。

你的合约不用自己出门打听，也不用自己雇信使——它只要低头看一眼这张价目表，就知道外面的价格了。

### 它和 Oracle 是什么关系？

还记得上一篇的定义吗：Oracle 是把链外数据搬上链的**机制**，而 Data Feeds 是 Chainlink 用这套机制做出来的**具体产品**。打个比方：

- **Oracle** 是「送外卖」这个行当；
- **Data Feeds** 是其中最火的一家外卖店，专送「价格」这道菜，而且菜单、价格、营业时间全是公开的。

除了价格，Data Feeds 家族里还有别的「菜」：比如储备证明（某个稳定币背后是不是真有足额美元）、利率数据等等。但对新手来说，先吃透最常用的**价格数据流**就够了——DeFi 里借贷、稳定币、衍生品用的，几乎全是它。

### 为什么不自己写个合约手动填价格？

你可能想过：我自己写个合约，每天手动把 BTC 价格输进去，不就行了吗？

技术上能跑，但有三个问题：

1. **你睡觉的时候价格还在变**。BTC 半夜暴跌 10%，你的合约还拿着 8 小时前的旧价格在干活，清算该发生的没发生，不该发生的发生了。
2. **你一个人说了算**。你填什么价格，合约就信什么价格——这等于把整个系统的信任押在你一个人身上，和中心化服务器没区别。
3. **你填错了怎么办**。手一抖多输一个零，合约可能瞬间把所有抵押品按天价卖掉。

Data Feeds 解决的正是这三个问题：**有人 24 小时帮你更新、不是一个人说了算、价格经过多方核对才上链**。而「怎么保证可信」，就是下一节要讲的。

> 💡 **一句话记住**：Data Feeds 不是帮你「算」价格的，它是把外面已经存在的市场价格，安全、可信地「搬」到链上，变成你的合约能直接读的链上数据。

## 二、一个价格是怎么来到链上的？

上一篇我们讲过，去中心化预言机的工作分四步。Data Feeds 的价格上链，就是这四步的一次完整演出。我们拿 **BTC/USD** 这条最常用的价格流当例子，从头走一遍。

### 第 1 步：从多个优质数据源采集

价格不是从某一家交易所抄来的。Chainlink 的节点会同时向多个**专业数据提供商**查询行情，而这些提供商本身，又汇总了几十家中心化交易所和去中心化交易所的成交价，并且按成交量加权、过滤掉明显异常的报价。

为什么要这么麻烦？因为任何一家交易所的价格都可能被操纵、可能宕机、可能报错。多家汇总之后，一家出问题，整体几乎不受影响。

### 第 2 步：多个独立节点各自取数

一条价格数据流的背后，通常站着 **21 个或更多独立的节点运营方**。它们各自运行 Chainlink 的软件，各自去查数据，互不通气。没有哪一个节点能单方面决定「今天 BTC 是多少钱」。

这就是去中心化的精髓：**不信任任何一个节点，只信任它们共同算出来的结果**。

### 第 3 步：链下聚合，取中位数

节点们把各自查到的价格汇总到一起，取**中位数**作为最终价格，再用 OCR（Off-Chain Reporting，链下报告）机制签名确认。

为什么是中位数，而不是平均数？因为中位数天生抗干扰：就算有两三个节点报了离谱的价格，中位数几乎纹丝不动；而平均数会被一个极端值直接拉偏。想想看：21 个人里有 1 个人说 BTC 是 1 美元，平均数会被拉低一大截，中位数却连眉毛都不会动一下。

### 第 4 步：把结果写进链上的聚合器合约

聚合好的价格，最终被写进一个链上的**聚合器合约（Aggregator）**。从这一刻起，这个价格就成了链上数据——任何智能合约都可以直接读取它，就像读链上余额一样自然。

整个流程可以浓缩成一张表：

| 步骤 | 谁在做 | 作用 |
|---|---|---|
| 采集 | 多个专业数据提供商 | 不依赖单一交易所 |
| 取数 | 21+ 个独立节点 | 不依赖单一节点 |
| 聚合 | 节点网络链下取中位数 | 过滤异常值和个别作恶 |
| 上链 | 聚合器合约 | 变成所有合约都能读的链上数据 |

### 价格多久更新一次？

价格不是每个区块都更新的——那样又贵又没必要。更新由两个条件触发，哪个先到就执行哪个：

- **偏差阈值（Deviation Threshold）**：链下价格和链上最后一次价格相比，变化超过一定比例，就更新一次。不同资产的阈值不同，比如 ETH/USD 主网常用 0.5%。
- **心跳（Heartbeat）**：就算价格没怎么动，过一段时间也强制更新一次，保证数据不会太旧。比如 ETH/USD 主网的心跳大约是 1 小时。

所以你在链上读到的价格，永远是「最近一次更新时」的价格，可能是几秒前，也可能是几十分钟前——取决于这段时间价格波动大不大。**它不是实时行情，而是「经过核对的、最近一次的可靠价格」。** 写合约的时候，这个心态很重要，后面第七节还会细讲。

## 三、去哪里找到 BTC/USD 的喂价地址？

知道了价格是怎么上链的，下一个问题很实际：**我的合约要去哪个地址读价格？**

每个价格、每条链，都有自己专属的聚合器合约地址。BTC/USD 在以太坊主网是一个地址，在 Sepolia 测试网是另一个地址，千万不能混用。找地址的官方渠道只有一个，记住它：

> **data.chain.link** —— Chainlink 官方的价格数据流目录。

打开它，操作就三步：

### 第 1 步：选网络

页面上方先选你要用的网络。我们做练习，用 **Ethereum Sepolia** 测试网——它是免费的，练手不用花真钱。

### 第 2 步：搜交易对

在搜索框里输入 `BTC/USD`，找到 Bitcoin / USD 这一条。点进去，你会看到这条喂价的完整信息：合约地址、最新价格、最近更新时间、偏差阈值、心跳间隔。

### 第 3 步：复制代理合约地址

页面上给出的地址，就是你的合约要去读的地址。写合约的时候，用的就是这个地址。

为了方便你照着练，这里直接给出两条 Sepolia 测试网上最常用的喂价地址（以 Chainlink 官方文档为准，写代码前建议再去 data.chain.link 核对一次）：

| 交易对 | 网络 | 聚合器合约地址 |
|---|---|---|
| BTC / USD | Ethereum Sepolia | `0x1b44F3514812d835EB1BDB0acB33d3fA3351Ee43` |
| ETH / USD | Ethereum Sepolia | `0x694AA1769357215DE4FAC081bf1f309aDC325306` |

⚠️ **注意**：以太坊**主网**的 BTC/USD 地址是另外一个（`0xF4030086522a5bEEa4988F8cA5B36dbC97BeE88c`），和测试网完全不同。**测试网练手用测试网地址，主网部署用主网地址**，抄错地址，你的合约读到的就是另一条链上另一份数据——或者干脆读不到。

> 💡 **一句话记住**：喂价地址没有「通用」这一说。每次用之前，先去 data.chain.link 按「网络 + 交易对」查一遍，复制官方给出的代理合约地址。

## 四、动手：让你的合约第一次「开口问价」

原理讲完了，地址也有了。现在轮到最有意思的部分：**亲手写一个合约，读一次链上的 BTC 价格**。

我们用 Remix（第 10 篇用过的在线开发环境），全程不需要安装任何东西。如果你还没领过 Sepolia 测试 ETH，记得先去水龙头领一点——部署合约要花一点测试网 Gas（第 11 篇讲过步骤）。

### 第 1 步：在 Remix 里新建合约

打开 [remix.ethereum.org](https://remix.ethereum.org)，新建一个文件，名字就叫 `PriceConsumerV3.sol`，把下面的代码完整粘贴进去：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.7;

import "@chainlink/contracts/src/v0.8/shared/interfaces/AggregatorV3Interface.sol";

contract PriceConsumerV3 {
    AggregatorV3Interface internal priceFeed;

    constructor() {
        priceFeed = AggregatorV3Interface(
            0x1b44F3514812d835EB1BDB0acB33d3fA3351Ee43
        );
    }

    function getLatestPrice() public view returns (int) {
        (, int price, , , ) = priceFeed.latestRoundData();
        return price;
    }
}
```

这份代码只有 20 行出头，但每一行都值得讲明白。

### 第 2 步：逐行读懂这份代码

**第 5 行：`import` 导入接口**

```solidity
import "@chainlink/contracts/src/v0.8/shared/interfaces/AggregatorV3Interface.sol";
```

`AggregatorV3Interface` 是 Chainlink 官方提供的**接口文件**：它规定了「一个价格聚合器合约应该有哪些函数」。你的合约不用知道聚合器内部是怎么算价格的，只要知道「我可以调它的 `latestRoundData()` 函数」就够了。这就是第 12 篇讲过的 ABI 和接口的思想——**你不需要知道对方怎么做，只需要知道对方提供什么**。

在 Remix 里，这行 import 需要先安装 `@chainlink/contracts` 这个包（Remix 的文件管理器里可以一键安装），或者改用 GitHub 直链导入。编译如果报找不到包，先检查这一步。

**第 8–13 行：构造函数里「认准」喂价地址**

```solidity
constructor() {
    priceFeed = AggregatorV3Interface(
        0x1b44F3514812d835EB1BDB0acB33d3fA3351Ee43
    );
}
```

合约部署的时候，就把 Sepolia 上的 BTC/USD 聚合器地址「记」下来。`AggregatorV3Interface(地址)` 这一步，是把一个普通的地址「包装」成一个可以调用的喂价合约对象。从此以后，`priceFeed` 这个变量就代表「Sepolia 上的 BTC/USD 价格表」。

**第 15–18 行：读价格的函数**

```solidity
function getLatestPrice() public view returns (int) {
    (, int price, , , ) = priceFeed.latestRoundData();
    return price;
}
```

`latestRoundData()` 是最常用的一个函数：它返回最新一轮价格的完整数据，一共五个值。我们的函数只要其中第二个——`price`，也就是最新价格；其他的四个用逗号空着，表示「这次不用」。

注意 `view` 这个关键字：它表示这个函数**只读数据、不改状态**，所以在 Remix 里点一下就能看结果，不用发交易、不用花 Gas。

### 第 3 步：编译、部署、点一下

1. 在 Remix 里点 **Compile** 编译，确认没有报错；
2. 环境选 **Injected Provider - MetaMask**，网络切到 **Sepolia**；
3. 点 **Deploy** 部署，钱包里确认一下（花一点测试 ETH）；
4. 部署成功后，在下方找到 `getLatestPrice` 这个按钮，点一下。

你会看到一个很长的数字，比如：

```text
9752143000000
```

先别慌——这不是 bug。**这就是链上 BTC 的价格，只不过带着 8 位小数。** 下一节我们就把这个数字翻译成人话。

## 五、读懂返回的数字：8 位小数和五个返回值

### 为什么价格是一串「天文数字」？

区块链上没有小数点。智能合约只认识整数，所以 Chainlink 把价格乘上 `10^decimals` 再存起来。BTC/USD 这类加密货币对美元的喂价，`decimals` 是 **8**，也就是说：

```text
链上读到的数字 ÷ 10^8 = 真实价格
9752143000000 ÷ 100000000 = 97521.43 美元
```

Chainlink 官方文档里也给了同样的换算例子：一个 8 位小数的喂价返回 `3030914000000`，对应的就是 `30309.14` 美元。

> 💡 **新手最容易踩的坑**：直接把链上读到的 `9752143000000` 当成价格用，你的合约会以为 BTC 值 9.7 万亿美元。**每次用价格之前，先除以 `10^decimals`**。更稳妥的做法，是在代码里调用 `priceFeed.decimals()` 动态去取小数位数，而不是把 8 这个数字写死——因为不同交易对的小数位数可能不一样（加密货币对美元一般是 8 位，但加密货币对 ETH 一般是 18 位）。

### `latestRoundData()` 返回的五个值

刚才我们只取了第二个值，其实它一次返回五个。认识它们，你才算真正会「读价」：

| 返回值 | 类型 | 含义 |
|---|---|---|
| `roundId` | uint80 | 这一轮数据的编号，每更新一次就变 |
| `answer` | int256 | 最新价格（就是我们要的那个数） |
| `startedAt` | uint256 | 这一轮开始的时间戳 |
| `updatedAt` | uint256 | 这一轮价格最后更新的时间戳 |
| `answeredInRound` | uint80 | 这个价格是在哪一轮被算出来的 |

其中最值得你关心的是 **`updatedAt`**：它告诉你这个价格是什么时候更新的。你的合约在用价格做重要决定之前，应该先检查一下：这个价格是 10 秒前更新的，还是 3 天前更新的？如果数据源出了故障、价格长时间没更新，聪明的合约会选择暂停关键操作，而不是拿着一个过期价格继续执行。

另外两个顺手能用的函数：

- `decimals()`：返回这个喂价的小数位数（BTC/USD 是 8）；
- `description()`：返回这条喂价的文字描述，比如 `"BTC / USD"`；
- `getRoundData(roundId)`：用轮次编号查某一轮的历史价格——想回看上个月某一天的价格，就靠它。

## 六、拿到价格之后，能用来做什么？

会读价只是第一步。价格一旦进了合约，能玩的花样就多了。这里先给你三个最典型的用途，具体的实战我们后面几篇再展开：

### 1. 做一个「按市价卖 Token」的小系统

第 15、16 篇我们有了自己的 ERC20 Token。第 20 篇，我们会把 Token 和价格数据流拼在一起：合约先读 BTC（或 ETH）的价格，再按这个价格算出「1 个 ETH 能买多少个 Token」，实现一个链上 Token 购买系统。没有 Data Feeds，这件事根本做不成——合约自己不知道 ETH 现在值多少钱。

### 2. 给借贷协议「估值」

第 17 篇讲过，Aave 这类借贷协议要靠预言机知道你的抵押品现在值多少钱，才敢决定要不要清算你。读价，就是清算逻辑的第一步。

### 3. 让 NFT「看价格变脸」

第 30 篇的动态 NFT 会用到这个本事：NFT 合约定时读一次 BTC/USD 的价格，涨了就换一张笑脸，跌了就换一张哭脸。价格数据流，就是 NFT 和真实世界之间的那根线。

可以说，**读价是智能合约从「自娱自乐」走向「和真实世界打交道」的第一步**。你今天写的这 20 行代码，是后面很多大功能的地基。

## 七、用 Data Feeds 的四个注意事项

最后，也是最重要的部分：Data Feeds 很好用，但它不是魔法。用的时候，这四件事要刻进脑子里：

### 1. 地址和网络，一定要对得上

测试网地址和主网地址不一样，不同交易对的地址也不一样。每次部署前，去 data.chain.link 核对一遍「网络 + 交易对 + 地址」。抄错一个字符，你的合约读到的就是错误的数据——而且合约不会报错，它会一本正经地按错误的价格执行。

### 2. 先看新鲜度，再用价格

用价格之前，先看 `updatedAt`。如果价格是很久以前更新的（比如数据源故障、网络拥堵），先停下来，别急着做清算、买卖这类不可逆的操作。一个简单实用的做法，是在合约里加一行检查：「如果价格超过 N 小时没更新，就拒绝执行」。

### 3. 不要把小数位数写死

不同喂价的 `decimals` 可能不同。今天 BTC/USD 是 8 位，明天你换一个交易对可能是 18 位。写代码的时候调用 `decimals()` 去取，养成这个习惯，能帮你避开一整类低级错误。

### 4. 它不是实时行情，别拿它做高频交易

价格只在「偏差超过阈值」或「心跳时间到」时才更新，两次更新之间可能隔几分钟。拿它做需要秒级行情的高频交易，是用错了工具。Data Feeds 的定位是「可靠的、经过核对的参考价」，不是交易所的实时报价屏。

> ⚠️ **风险提示**：本文是知识科普，不是投资建议。文中给出的合约代码仅供在 Sepolia 测试网学习使用，没有经过安全审计，不要直接部署到主网、不要往里面放真实资金。判断任何 DeFi 协议的安全性时，预言机设计只是其中一环，还要结合合约审计、抵押率、团队背景等多方面考察。

## 总结

今天我们认识了 Chainlink Data Feeds——智能合约的「现成价目表」：

1. **Data Feeds 是什么**：Chainlink 把真实世界的资产价格持续搬上链、做成任何合约都能直接读取的链上数据的服务，最常用的是价格数据流。
2. **价格怎么上链**：多个数据源采集 → 21+ 个独立节点各自取数 → 链下取中位数聚合 → 写进链上聚合器合约。任何一个环节出问题，其他环节都能顶住。
3. **价格多久更新**：偏差超过阈值就更新，或者心跳时间到了强制更新。它不是实时行情，而是经过核对的最近一次可靠价格。
4. **去哪找地址**：官方目录 data.chain.link，按「网络 + 交易对」查找。Sepolia 测试网 BTC/USD 是 `0x1b44F3514812d835EB1BDB0acB33d3fA3351Ee43`，ETH/USD 是 `0x694AA1769357215DE4FAC081bf1f309aDC325306`；主网地址不同，部署前务必核对。
5. **怎么写代码读价**：导入 `AggregatorV3Interface`，在构造函数里认准喂价地址，调 `latestRoundData()` 取第二个返回值；记得除以 `10^decimals`（BTC/USD 是 8 位小数）才是真实价格。
6. **用之前先检查**：核对地址与网络、看 `updatedAt` 判断新鲜度、动态取小数位数、别把它当实时行情用。

到现在，你的工具箱里又多了一件关键工具：你的合约第一次真正「看见」了外面的世界——至少，看见了外面的价格。
