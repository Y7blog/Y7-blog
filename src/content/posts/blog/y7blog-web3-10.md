上一篇文章，我们了解了智能合约是什么，以及它为什么可以按照预先编写的规则执行。

[[y7blog-web3-09]]


但还有一个问题没有解决：

**开发者到底用什么语言，才能把这些规则写成区块链可以执行的程序？**

比如，我想开发一个简单的 Token 合约，让用户可以查询余额、转账；或者开发一个 NFT 合约，让用户能够铸造和转移数字资产。

这些功能都需要通过代码实现。

在 Ethereum 生态中，有一种经常出现的编程语言：Solidity。

如果你看过一些 Web3 开发教程，可能已经见过它的名字。很多智能合约示例、DeFi 协议和 NFT 项目，都会使用 Solidity 编写核心合约逻辑。

那么，Solidity 到底是什么？它为什么会成为 Ethereum 智能合约开发中最常见的语言之一？

这篇文章，我们从零开始理解。

## 一、为什么有了智能合约，还需要学习编程语言？

先回顾一下上一篇文章。

智能合约本质上是一种运行在区块链执行环境中的程序。开发者通过代码定义规则，当用户发起交易或调用时，网络会按照相关规则执行程序。

问题是，区块链不会直接理解我们平时使用的自然语言。

例如，我们想写一个简单的规则：

> 用户可以修改一条消息，但每次修改都必须通过区块链交易完成。

这句话人类很容易理解，但计算机需要更明确的指令。

开发者必须把规则转换成程序能够处理的逻辑，例如：

- 定义一个变量，用来保存消息。
- 编写一个函数，用来修改消息。
- 设置相应的访问规则。
- 规定修改成功后，链上状态如何变化。

这就需要编程语言。

在普通软件开发中，我们会使用 JavaScript、Python、Java 等语言编写程序。

而在 Ethereum 智能合约开发中，Solidity 是最常见的选择之一。

你可以先把它理解成：

**Solidity 是一种专门面向智能合约开发设计的编程语言，可以帮助开发者把业务规则写成能够编译并在 EVM 兼容环境中执行的程序。**

不过，Solidity 并不是唯一的智能合约语言，也不是所有区块链都使用它。

它的主要应用场景，是 Ethereum 及许多兼容 EVM 的区块链生态。

## 二、Solidity 到底是什么？

Solidity 是一种高级编程语言，语法受到 JavaScript、C++、Python 等语言的一些设计影响，但它有自己的语法和运行规则。

这里的「高级语言」，并不是说它比其他语言更高级或更强大，而是说它使用相对容易理解的语法，让开发者能够更方便地表达程序逻辑。

例如，假设我们想在智能合约中保存一条消息。

使用 Solidity，可以写成：

```solidity
string public message = "Hello Web3";
```

这行代码定义了一个字符串变量 `message`，并将初始内容设为 `Hello Web3`。

其中：

- `string` 表示字符串类型。
- `public` 表示该变量可以通过编译器生成的公开访问接口读取。
- `message` 是变量名称。
- `"Hello Web3"` 是初始值。

看起来是不是和普通编程语言有些相似？

但 Solidity 不只是用来保存文字。

开发者还可以使用它定义函数、判断条件、管理权限、记录资产状态，以及实现各种业务逻辑。

例如：

- Token 合约可以记录余额和处理转账。
- NFT 合约可以管理 Token ID 和所有权。
- 借贷合约可以记录抵押资产和借款状态。
- 兑换合约可以根据规则执行 Token 交换。

这些应用的复杂程度不同，但都可以通过 Solidity 表达相应的程序逻辑。

需要注意的是，代码本身只是规则的表达方式。它最终能否正确运行，还取决于编译、部署、执行环境和合约设计。

## 三、为什么 Solidity 常用于 Ethereum 智能合约？

这就涉及 Ethereum 的运行方式。

Ethereum 不仅仅是一条记录 ETH 转账的区块链，它还提供了一套可以执行智能合约的环境。

这套环境叫作 Ethereum Virtual Machine，简称 EVM。

如果把智能合约比作一个程序，那么 Solidity 就是开发者用来编写程序的一种语言，而 EVM 则是负责执行相应程序的环境。

两者承担的角色并不一样。

### 1. Solidity 让开发者更容易编写合约

如果直接使用底层指令编写复杂业务逻辑，开发和维护都会更加困难。

Solidity 提供了变量、函数、条件判断、循环、结构体和合约等语言特性，让开发者能够用更清晰的方式表达规则。

例如，我们可以定义一个函数：

```solidity
function setMessage(string memory newMessage) public {
    message = newMessage;
}
```

它的作用是接收一个新的字符串，并将它保存到 `message` 变量中。

当然，真实的智能合约还需要考虑谁可以调用这个函数、是否允许任何人修改消息，以及修改是否应该触发事件等问题。

### 2. EVM 为智能合约提供统一的执行环境

Solidity 代码不能直接交给 EVM 原样执行。

通常需要先经过编译，将高级语言代码转换成 EVM 能够执行的字节码。

EVM 会按照 Ethereum 的执行规则处理这些字节码，并根据交易和当前链上状态计算执行结果。

Ethereum 网络中的节点需要遵循相应协议规则，验证交易和执行结果。

这也是智能合约能够在 Ethereum 网络中运行的重要基础。

### 3. 兼容 EVM 的链也能使用 Solidity

Solidity 并不是只能用于 Ethereum 主网。

许多兼容 EVM 的区块链，也支持部署 Solidity 编译生成的合约字节码。

这意味着，开发者掌握 Solidity 后，可以在多个 EVM 兼容网络中复用大量开发经验和工具。

不过，**代码能够编译，不代表它就能不经修改地在所有网络上安全运行。**

不同网络可能在链上环境、费用、预编译合约、外部服务和协议配置等方面存在差异。部署前仍然需要检查目标网络的具体条件。

## 四、Solidity、EVM 和字节码到底是什么关系？

第一次接触智能合约开发时，很多人容易把 Solidity、EVM 和字节码混在一起。

其实，它们的关系可以简单理解为：

**Solidity 源代码 → 编译器 → EVM 字节码 → EVM 执行**

我们逐个来看。

### Solidity 源代码：开发者编写的代码

这是开发者直接编写和维护的部分。

例如：

```solidity
contract HelloY7 {
    string public message = "Hello Web3";
}
```

这段代码定义了一个名为 `HelloY7` 的合约，并保存一条初始消息。

人类可以通过阅读源代码理解它的设计意图。

### 编译器：把源代码转换成目标代码

编译器会检查代码是否符合语言规则，并将源代码转换成目标形式。

Solidity 的常用编译器是 `solc`。

如果代码存在语法错误，编译器通常会报告错误，开发者需要修复后再继续。

编译成功也不代表代码一定没有漏洞，只能说明它通过了相应的编译检查。

### 字节码：供执行环境处理的程序表示

编译之后会得到 EVM 字节码。

字节码不是给普通用户阅读的文章，而是供 EVM 执行的低层程序表示。

对于初学者来说，不需要马上掌握每条字节码指令。现阶段只要理解：**Solidity 是编写合约的语言，字节码是编译后的结果，EVM 负责执行它。**

### EVM：按照规则执行字节码

当合约部署完成，用户发起交易调用合约时，EVM 会按照代码和当前状态执行相应逻辑。

执行结果可能会改变合约存储、账户余额或其他链上状态。

如果执行成功，相关状态变化会随着交易被纳入区块而成为链上记录的一部分。

如果执行失败，状态变化通常会回退，但交易仍可能消耗 Gas。

因此，部署、调用和执行并不是同一件事。

理解这几个步骤，后面学习 Remix、合约部署和区块链浏览器时，就会容易很多。

## 五、用一段简单代码认识 Solidity

只看概念可能还是有些抽象。

下面我们用一个非常简单的示例，定义一个可以读取和修改消息的智能合约。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract HelloY7 {
    string public message = "Hello Web3";

    function setMessage(string memory newMessage) public {
        message = newMessage;
    }
}
```

这段代码还不涉及 Token、NFT 或复杂的金融逻辑，但已经包含了几个值得认识的基本概念。

### 1. `pragma solidity ^0.8.20;`

这行代码声明了源代码所要求的 Solidity 编译器版本范围。

它不是告诉区块链使用哪个网络，而是告诉编译器，这份代码适用于哪些版本的 Solidity 编译器。

实际编译时，仍然需要选择符合版本约束的编译器。

### 2. `contract HelloY7`

这是合约定义。

你可以把 `HelloY7` 理解为这个合约的名称。

在 Solidity 中，`contract` 用于声明智能合约。合约可以包含变量、函数、事件以及其他定义。

### 3. `string public message`

这行代码定义了一个公开的字符串状态变量。

`message` 初始值为 `Hello Web3`。

由于它声明为 `public`，Solidity 编译器会自动生成相应的 getter 接口，方便外部读取这个变量。

但这里有一个容易误解的地方：

`public` 不代表任何人都能随意修改变量。

它主要影响外部读取接口。变量是否能够被修改，仍然取决于实际代码中提供了哪些操作。

### 4. `function setMessage(...)`

这是一个函数，用来修改消息内容。

```solidity
function setMessage(string memory newMessage) public {
    message = newMessage;
}
```

这里的 `newMessage` 是函数接收的参数，`memory` 表示这个字符串参数在执行期间使用的内存数据位置。

函数被调用后，会将新的字符串赋值给 `message`。

因为这个操作会修改合约状态，所以在已部署的合约上调用它，通常需要通过交易执行，并消耗 Gas。

如果通过 Remix 在本地模拟环境或测试环境中运行，实际操作方式和费用表现可能有所不同。

### 5. 这段合约有什么限制？

这只是一个教学示例。

任何人都可以调用 `setMessage` 修改消息，因此它不适合直接用来保存必须受到严格权限保护的数据。

如果想让它只有特定地址可以修改，就需要增加访问控制逻辑。

这也说明了一个重要问题：

**能运行的合约，不一定是设计合理或足够安全的合约。**

后续学习 Solidity 时，我们不仅要关注语法，还要逐步学习权限控制、错误处理和安全设计。

## 六、Solidity 代码是如何部署到区块链上的？

现在我们已经知道，Solidity 代码需要经过编译才能生成 EVM 字节码。

但代码编译完成后，怎么才能真正运行在区块链上？

通常可以把开发流程分为几个阶段。

### 第一步：编写源代码

开发者创建 Solidity 文件，编写合约的变量、函数和业务逻辑。

例如前面的 `HelloY7` 合约。

### 第二步：编译合约

使用 Solidity 编译器检查代码，并生成合约部署所需的字节码以及其他相关信息。

ABI 也是这一步经常接触的产物之一。后续文章会专门介绍它的作用。

### 第三步：部署合约

开发者通过部署交易，将合约部署到目标区块链。

在 Ethereum 上，部署交易会携带合约创建代码。交易成功执行后，网络会创建相应的合约账户，并为它分配合约地址。

这一步通常需要支付 Gas。

### 第四步：调用合约

合约部署完成后，用户或其他程序可以通过合约地址和相应接口调用它。

例如，调用 `setMessage` 修改消息，或者读取 `message` 的当前值。

对于会改变链上状态的操作，通常需要发送交易；对于符合条件的只读调用，则可以通过 `eth_call` 这类方式读取结果，而不必提交一笔改变链上状态的交易。

### 第五步：查询执行结果

交易提交后，可以通过钱包、开发工具或区块链浏览器查询状态。

如果是修改状态的交易，需要确认它是否被成功执行。

这就是一个基础的智能合约开发与交互流程：

**编写 → 编译 → 部署 → 调用 → 查询结果。**

下一篇，我们就会用 Remix，把其中的前几个步骤真正操作一遍。

## 七、Solidity 可以用来开发什么？

了解基础语法之后，我们再看 Solidity 在实际 Web3 项目中能做什么。

### 1. ERC-20 Token

很多 Ethereum 生态中的同质化 Token，都通过智能合约实现。

开发者可以按照 ERC-20 标准定义代币的基本接口，例如查询余额、转账和授权等。

需要注意，Solidity 本身不会自动让一个项目成为 ERC-20 Token。合约仍然需要按照相关标准实现对应接口和行为。

### 2. NFT

NFT 合约通常会涉及 Token ID、所有权和转移规则等内容。

开发者可以使用 Solidity 编写符合 ERC-721 等标准的合约，实现 NFT 的铸造、查询和转移。

### 3. DeFi 协议

去中心化交易、借贷、流动性管理等应用，往往会使用 Solidity 编写链上业务逻辑。

例如，兑换合约可以根据设定的规则处理资产交换，借贷合约可以管理抵押、借款和还款状态。

但这些系统通常比简单示例复杂得多，需要考虑价格变化、资金安全、权限设计和合约漏洞等问题。

### 4. 链上游戏和自动化应用

Solidity 也可以用来编写游戏资产、奖励规则和其他链上逻辑。

如果应用还需要读取现实世界数据、调用外部 API 或按照时间自动执行，就可能需要结合预言机、自动化服务或其他链下基础设施。

这也为后面的 Chainlink 相关内容埋下了伏笔。

## 八、学习 Solidity 前，应该先掌握什么？

如果你是完全零基础，不需要一开始就学习复杂的算法或研究 EVM 字节码。

可以先掌握以下内容。

### 1. 区块链基础概念

理解账户、地址、交易、Gas、区块确认和智能合约的基本关系。

否则，当你部署代码时，可能会遇到很多看起来与编程无关、实际上却很重要的问题。

### 2. 基础编程思维

先理解变量、函数、参数、条件判断和返回值。

这些概念在许多编程语言中都很常见，掌握后学习 Solidity 会轻松不少。

### 3. 理解状态变化

普通程序可能只是在本地计算一个结果，而智能合约还可能修改链上状态。

你需要逐渐区分只读操作与改变状态的操作，以及它们在调用方式和费用上的区别。

### 4. 学会使用开发工具

初学阶段可以先使用 Remix 这类在线开发环境，编写、编译和测试简单合约。

不必一开始就搭建复杂的本地开发环境。

先让第一段合约成功运行，再逐步学习更完整的开发工具链。

### 5. 重视安全

智能合约可能直接管理真实资产。

因此，权限控制、输入验证、外部调用和错误处理都非常重要。

不要因为一个合约可以成功编译或部署，就认为它已经可以安全地用于生产环境。

## 九、初学者常见的几个误解

### 误解一：Solidity 就是 Ethereum 本身

不是。

Solidity 是一种编程语言，Ethereum 是区块链网络。Solidity 可以用来编写在 Ethereum 上运行的智能合约，但它们不是同一个东西。

### 误解二：所有区块链都使用 Solidity

不是。

不同区块链可能使用不同的执行环境和编程语言。Solidity 主要应用于 Ethereum 和许多 EVM 兼容生态。

### 误解三：编译成功就代表合约没有问题

不是。

编译器主要检查代码是否符合语法和类型等规则。业务逻辑错误、权限问题和安全漏洞，仍然可能存在于能够成功编译的合约中。

### 误解四：部署合约后，它就会自动运行

也不是。

部署只是把合约创建到链上。通常还需要交易或其他机制触发函数执行。智能合约不会因为已经部署，就自动完成所有预期任务。

### 误解五：学习 Solidity 就必须马上成为专业开发者

不必。

如果你的目标是理解 Web3 项目，能够读懂基本的合约结构，就已经很有帮助。

如果你想进一步开发应用，再逐步学习语法、工具、测试和安全知识即可。

## 写在最后

回到最初的问题：

**Solidity 是什么？为什么它成为 Ethereum 智能合约开发中最常见的语言之一？**

因为它提供了一种相对清晰的方式，让开发者可以编写智能合约，再通过编译生成 EVM 能够执行的字节码。

它把业务规则转换成程序，让 Token、NFT、DeFi 和其他链上应用有了实现逻辑的基础。

现在，你可以把几个概念串起来理解：

- 智能合约：定义链上业务规则的程序。
- Solidity：开发者编写合约时常用的高级语言。
- 编译器：把 Solidity 源代码转换成目标代码。
- EVM：按照相应规则执行字节码的环境。
- 部署与调用：让合约进入链上运行环境，并执行对应功能。

这几个概念，是理解后续智能合约开发教程的重要基础。
