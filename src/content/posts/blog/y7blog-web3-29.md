想象一下，你的钱包里有两样东西：100 个 USDC，和一张画着猫的 NFT。

100 个 USDC，你随便花掉其中 10 个，再从别人那收回 10 个，钱包里的东西一点没变——反正每个 USDC 都长得一样。

但那张猫 NFT 不一样。你把它转给别人，再让他转一张“看起来差不多”的猫回来，你一眼就能看出来：**这不是我那张。编号不一样，猫的样子不一样，连以前的交易记录都不一样。**

同样是 Token，为什么一个可以随便换，另一个换一张就不行？这就是这篇要讲的事：**NFT 到底是什么，ERC721 和 ERC20 的区别到底在哪。**

> 💡 **先说清楚**：本文是知识科普，只讲 NFT 和 ERC721 标准是怎么回事，不推荐你去买任何 NFT，更不构成投资建议。NFT 的价格波动很大，很多 NFT 最后接近归零，动手之前先在测试网把流程走熟，再用你输得起的金额尝试。

## 一、NFT 到底是什么？先从“同质化”这个词说起

NFT 的全称是 Non-Fungible Token，中文一般叫“非同质化 Token”。这个名字听着拗口，其实拆开就很好懂。

**“同质化”（Fungible）的意思是：每一个都一样，可以互相替换。**

- 人民币就是同质化的：你手里这张 100 块，和我手里那张 100 块，面值一样、能买的东西一样，换一张没有任何区别。
- USDC 也是同质化的：你钱包里的 10 个 USDC，和我钱包里的 10 个 USDC，完全一样。借出去 10 个，收回来任意 10 个就行，不用还“原来那 10 个”。

**“非同质化”（Non-Fungible）正好反过来：每一个都不一样，不能互相替换。**

- 你的身份证是非同质化的：全世界只有一张是你的，拿别人的身份证换你的，肯定不行。
- 你家房子的房产证也是：门牌号、面积、位置都写在上面，换一本就不是你的房子了。

**NFT 就是区块链上的“非同质化 Token”：每个 Token 都有自己唯一的编号，代表一个独一无二的东西。**

|  | 同质化（Fungible） | 非同质化（Non-Fungible） |
|---|---|---|
| 每个单位一样吗 | 一样，随便换 | 不一样，每个都有编号 |
| 现实里的例子 | 人民币、USDC、LINK | 身份证、房产证、演唱会门票 |
| 链上的代表 | ERC20 Token | ERC721 Token，也就是 NFT |
| 能拆成零头吗 | 能，比如 0.5 个 USDC | 不能，一个 NFT 就是一个整体 |

所以一句话：**ERC20 是“一堆一样的 Token”，ERC721 是“一群各不相同的 Token”。**

## 二、ERC721 和 ERC20：根本区别不在名字，在记账方式

第 15 篇讲过，ERC20 合约里最核心的是一张“余额表”：

```
mapping(address => uint256) balances
```

翻译过来就是：**某个地址有多少个 Token。** 合约只记数量，不记“哪一个”。你有 100 个 USDC，合约只知道“你有 100”，不关心是哪 100 个——因为反正都一样。

ERC721 的记账方式正好反过来：

```
mapping(uint256 => address) owners
```

翻译过来是：**某个编号的 Token，现在归谁。** 合约不记“你有几个”，而是记“编号 1 归你、编号 2 归他、编号 3 归你……”。

这个差别看起来小，实际上决定了两种 Token 的一切：

```
ERC20：钱包 → 数量
  你的地址 → 100 个 USDC
  他的地址 → 50 个 USDC
  （只记多少，不记哪一个）

ERC721：编号 → 主人
  编号 #1 → 你的地址
  编号 #2 → 他的地址
  编号 #3 → 你的地址
  （每个编号都有名有姓，换一个就不是同一个）
```

**这就是 ERC20 和 ERC721 最根本的区别：一个按地址记数量，一个按编号记归属。**

顺着这个差别，其它区别就都好理解了：

|  | ERC20 | ERC721（NFT） |
|---|---|---|
| 标准提案 | EIP-20，2015 年提出 | EIP-721，2018 年 1 月定稿 |
| 记账方式 | 地址 → 余额（数量） | 编号 tokenId → 主人地址 |
| 每个 Token 有编号吗 | 没有，只看总数 | 有，每个都有唯一的 tokenId（uint256） |
| 能拆成小数吗 | 能，一般 18 位小数 | 不能，一个 NFT 就是 1 个整体 |
| 怎么查 | `balanceOf(地址)`：你有几个 | `ownerOf(编号)`：这个编号归谁 |
| 转账函数 | `transfer(地址, 数量)` | `transferFrom(从谁, 给谁, 编号)` |
| 典型代表 | USDC、LINK、UNI、DAI | Bored Ape、ENS 域名、游戏道具 |
| 在哪交易 | Uniswap 这类去中心化交易所 | OpenSea、Blur 这类 NFT 市场 |

还有一点很关键：**ERC20 一个合约只代表一种 Token，ERC721 一个合约通常代表一个系列。** 比如 USDC 的合约只发 USDC；但一个 NFT 合约可以管一整个系列，比如 1 万只各不相同的猿猴，每只一个编号，都在这个合约里。

## 三、ERC721 标准到底规定了什么？

和 ERC20 一样，ERC721 也是一份“接口清单”：只要你的合约实现了清单上的函数，钱包、浏览器、市场就能认出它、读懂它、交易它。

这份标准写在 EIP-721 里，2018 年 1 月 24 日提出，作者是 William Entriken、Dieter Shirley、Jacob Evans 和 Nastassia Sachs，同年 1 月定稿。它的接口编号是 `0x80ac58cd`，并且要求同时实现 ERC-165（让别的合约能问一句“你支持 ERC721 吗”）。

### 核心函数：8 个

| 函数 | 干什么 | 和 ERC20 的对应 |
|---|---|---|
| `balanceOf(地址)` | 查这个地址有几个 NFT | 同名，但 ERC20 查的是数量 |
| `ownerOf(编号)` | 查某个编号的 NFT 现在归谁 | ERC20 没有这个函数 |
| `transferFrom(从谁, 给谁, 编号)` | 把指定编号的 NFT 转给别人 | ERC20 转的是数量 |
| `safeTransferFrom(从谁, 给谁, 编号)` | 安全转账：先检查接收方能不能收 NFT | ERC20 没有 |
| `approve(地址, 编号)` | 授权某人可以转走你指定的这一个 NFT | ERC20 授权的是数量 |
| `setApprovalForAll(地址, 是/否)` | 授权某人可以转走你这个合约里的全部 NFT | ERC20 没有 |
| `getApproved(编号)` | 查某个编号授权给了谁 | ERC20 查的是 allowance |
| `isApprovedForAll(主人, 操作人)` | 查某人是不是被授权管你全部 NFT | ERC20 没有 |

### 核心事件：3 个

| 事件 | 什么时候触发 |
|---|---|
| `Transfer(从谁, 到谁, 编号)` | NFT 易主时，包括第一次 Mint 和销毁 |
| `Approval(主人, 被授权人, 编号)` | 单个 NFT 授权时 |
| `ApprovalForAll(主人, 操作人, 是/否)` | 全部授权开通或取消时 |

### 两个可选扩展

| 扩展 | 加了什么 | 接口编号 |
|---|---|---|
| 元数据扩展 | `name()`（系列名）、`symbol()`（简称）、`tokenURI(编号)`（指向一张 JSON 描述文件） | 0x5b5e139f |
| 枚举扩展 | `totalSupply()`（总数）、`tokenByIndex()`、`tokenOfOwnerByIndex()`（按顺序查编号） | 0x780e9d63 |

注意一个细节：**元数据扩展是可选的。** 也就是说，一个 ERC721 合约可以没有 `tokenURI`，照样是合法的 NFT——只不过钱包和市场就不知道它长什么样、叫什么名字。现实中绝大多数 NFT 合约都实现了这个扩展，因为没有它，NFT 在市场上就是一张“白板”。

### 安全转账：safeTransferFrom 是干什么的？

这是新手最容易忽略、但最有用的一个函数。

ERC20 的 `transfer` 是“只管转”：你把 Token 转到一个不会处理 Token 的合约地址，那笔 Token 就卡在里面，基本拿不回来了。

ERC721 的 `safeTransferFrom` 多了一步检查：转账之前，先问接收方一句“你会收 NFT 吗？”——接收方如果是合约，必须实现 `onERC721Received` 这个回调函数，能回答才转；答不上来，转账直接失败，NFT 还在你手里。

```
你调 safeTransferFrom
   │
   ▼
合约先问接收方：你会收 NFT 吗？
   │
   ├─ 接收方是普通钱包 → 直接转，没问题
   │
   ├─ 接收方是合约，且实现了 onERC721Received → 转
   │
   └─ 接收方是合约，但不会收 NFT → 转账失败，NFT 还在你手里
```

**所以记住一条规矩：转 NFT 优先用 `safeTransferFrom`，不要图省事用 `transferFrom`。** 第 31、32 篇写 NFT 合约和部署的时候，还会再碰到它。

### 现在写 NFT 合约，用什么工具？

和 ERC20 一样，现在没人从零手写 ERC721。标准做法是直接用 OpenZeppelin 的 `ERC721` 实现（再加 `ERC721URIStorage` 存每个 Token 的元数据链接），第 31 篇会完整走一遍。

顺便提一个最新进展：OpenZeppelin Contracts 在 2026 年 7 月发布了 v5.7，里面加了跨链 ERC721 桥——同一个 NFT 系列可以在不同链之间转移，这正是第 35、36 篇要讲的跨链 NFT 的底层工具之一。不过对这篇来说，你只需要记住：**ERC721 标准本身自 2018 年定稿后就没怎么变过，变的是周围的工具和玩法。**

## 四、NFT 不是图片：先把这个误会解开

说到 NFT，很多人第一反应是“一张很贵的 JPG”。这个理解，错了一半。

**NFT 本身不是图片。** 链上那个 NFT，只是一条记录：

```
合约地址：0xBC4C...（某个 NFT 系列的合约）
编号：#8817
主人：0x1234...
```

就这么多。没有像素、没有颜色、没有图片文件。图片在哪？在另一份文件里。

NFT 的完整结构其实是三层，下一篇文章（第 29 篇）会一层一层拆开讲，这里先给你一张总图：

```
链上：NFT 合约
  │
  │  tokenId #8817
  │  主人是 0x1234...
  │  tokenURI → 指向一份 JSON 文件
  ▼
链下：Metadata（JSON 文件）
  {
    "name": "Bored Ape #8817",
    "description": "...",
    "image": "ipfs://.../8817.png",
    "attributes": [...]
  }
  │
  │  image 字段 → 指向图片文件
  ▼
图片文件（存在 IPFS 或服务器上）
```

**所以“买 NFT”买到的，严格来说是链上那条“编号 #8817 归你”的记录，外加一份指向图片的链接。** 图片本身通常不在链上——把一张图整个存进区块链又贵又慢，没人这么干。

这个区别很重要，后面第八节的坑，有一半都跟它有关。

## 五、NFT 是怎么火起来的？一只猫把以太坊堵了

NFT 这个概念不是 2021 年凭空冒出来的。它的起点，是一群电子猫。

2017 年 11 月 28 日，一款叫 CryptoKitties（加密猫）的游戏在以太坊上上线。玩法很简单：买猫、养猫、让两只猫“繁殖”生出小猫。每只猫都是一个 NFT，编号、花纹、眼睛、毛色各不相同，稀有的猫能卖出高价。

结果火得超出了所有人的预料：

- 上线一周内，CryptoKitties 的交易一度占到**整个以太坊网络流量的约 25%**，以太坊被堵得交易排长队、Gas 费暴涨；
- 2017 年 12 月 2 日，第一只创世猫 Genesis 以 **246.9255 个 ETH（当时约 11.7 万美元）** 卖出；
- 到 2018 年 10 月，已经繁殖出了超过 100 万只猫，相关交易超过 320 万笔。

这件事有两个后果：

**第一，它逼出了 ERC721 标准。** CryptoKitties 的作者之一 Dieter Shirley 本来就是 EIP-721 的作者。游戏火了之后，大家发现“独一无二的 Token”这个需求是真实存在的，标准在 2018 年 1 月正式定稿，钱包、市场、浏览器从此有了统一的接口。

**第二，它让所有人第一次看到：区块链不只能转钱，还能记录“这是谁的东西”。**

之后的故事你可能听过：2021 年，无聊猿（Bored Ape Yacht Club）一只卖到几十万美元，NFT 成了新闻头条；再后来市场冷下来，价格跌了九成以上的项目比比皆是。但标准本身留下来了，而且越用越广。

还有两个经常被拿来举例子的 NFT，你可以记一下：

| 例子 | 是什么 | 为什么常被提到 |
|---|---|---|
| Bored Ape Yacht Club | 1 万只风格统一、细节各不相同的猿猴头像 | 最出圈的头像类 NFT，也是 ERC721 的代表 |
| ENS 域名 | 比如 `y7.eth` 这样的以太坊域名 | 每个域名都是一个 ERC721 NFT，能转让、能过期 |
| CryptoPunks | 2017 年 6 月发布的 1 万个像素头像 | 比 ERC721 标准还早，用的是自己的合约，并不完全符合 ERC721——这是个经常被搞错的细节 |

## 六、除了收藏，NFT 还能用来干什么？

如果 NFT 只是“贵的图片”，那它走不远。它真正的价值在于：**任何需要证明“这个独一无二的东西归谁”的场景，都可以用 NFT 来记。**

| 场景 | 为什么适合用 NFT |
|---|---|
| 游戏道具 | 一把全服唯一的剑、一件限量皮肤，每个都有编号，换号、交易都走链上记录 |
| 门票和会员卡 | 一张演唱会门票就是一个 NFT，检票就是查 `ownerOf`，转让就是一次转账，黄牛票和假票无处藏身 |
| 域名 | ENS 域名本身就是 ERC721，买域名就是买一个 NFT |
| 学历和证书 | 一张毕业证、一个结课证书发成 NFT，雇主上链一查就知道真假 |
| 供应链和票据 | 一批货、一张提单对应一个 NFT，流转全程留痕 |
| 数字身份和凭证 | 参加过某场活动、完成过某项任务，都可以发一个 NFT 当凭证 |

看出来了吗？这些场景都有一个共同点：**东西本身是唯一的，而且“归谁”这件事很重要。** 只要满足这两点，ERC20 就不够用——因为 ERC20 只记数量，记不住“哪一个归谁”。

反过来，如果东西是可以互相替换的，比如积分、优惠券、游戏金币，那就该用 ERC20，别硬套 NFT。**选标准的第一原则，永远是先看东西本身是“一样的”还是“不一样的”。**

## 七、顺带认识一下 ERC1155：一个合约管多种 Token

ERC20 和 ERC721 各管一头：一个只管同质化，一个只管非同质化。2018 年又出了第三个标准 ERC-1155，思路是“一个合约，两种都管”：

- 同一个合约里，有的编号代表同质化 Token（比如游戏金币，编号 #1 有 10000 个，都一样）；
- 有的编号代表非同质化 Token（比如一把唯一的剑，编号 #2 只有 1 个）；
- 还支持批量转账，一次转多个编号，省 Gas。

游戏是最典型的使用场景：金币、药水、装备全放在一个合约里，不用每种东西单独部署一个合约。不过对初学者来说，先把 ERC20 和 ERC721 这两个分清楚就够了，ERC1155 知道有这么个东西就行，后面做游戏项目的时候再细讲。

## 八、新手最容易踩的五个坑

### 坑 1：以为买了 NFT，就买了图片的版权

这是最常见的误会。**买 NFT 买到的是链上那条所有权记录，不是图片的版权。** 除非项目方明确写了“持有者拥有商用授权”（比如无聊猿就给了持有者商用权），否则你不能拿那张图去印 T 恤卖钱，更不能阻止别人右键保存同一张图。

**怎么避开：** 下单之前，先看项目的授权说明。没写授权，就默认你只有“链上归你”这一项权利。

### 坑 2：以为图片存在链上，其实它在别的地方

第四节讲过，图片一般存在 IPFS 或者项目方的服务器上，链上只有一个链接。如果项目方服务器关了、IPFS 节点没人 pin 了，链接指向的文件就打不开了——**你的 NFT 还在链上，归你，但图片没了，只剩一个名字和编号。**

**怎么避开：** 买之前点开 `tokenURI` 看一眼，图片是不是存在 IPFS（`ipfs://` 开头）或者 Arweave 这类去中心化存储上。存在项目方自己服务器上的，风险更高。

### 坑 3：把 NFT 转到一个不会收 NFT 的地址

用 `transferFrom` 直接转账，如果对方是个不支持 ERC721 的合约地址，NFT 转进去就卡住了，基本拿不回来。

**怎么避开：** 转账优先用 `safeTransferFrom`，它会先检查对方能不能收。钱包里点转账，用的一般也是安全版本，但自己写合约调函数的时候，一定要选对。

### 坑 4：setApprovalForAll 开了就忘关

在 OpenSea 这类市场卖 NFT，第一次要调 `setApprovalForAll`，授权市场合约可以转走你这个系列里的全部 NFT。很多人卖完就忘了这回事，授权一直开着。万一市场合约出问题，或者你点了钓鱼链接，这批 NFT 就有被转走的风险。

**怎么避开：** 卖完之后，到 Revoke.cash 这类工具上查一下授权，不用的就取消掉。授权这东西，用完就收回来，跟第 25 篇讲 ERC20 授权的道理一模一样。

### 坑 5：以为“稀缺”就等于“值钱”

一个系列只发 10 个，听起来很稀缺。但如果没人想要，10 个也卖不出去。NFT 的价格只由市场决定，发行量小不等于有价值。2021 年高峰期之后，大量 NFT 项目的价格跌了九成以上，很多至今没有回到高点。

**怎么避开：** 先把它当技术学明白，再谈价格。**本文是知识科普，不是投资建议。** 真要买，先拿测试网练手，再用你输得起的金额尝试。

> ⚠️ **风险提示**：NFT 涉及真实资产的支出，价格波动极大，流动性也比 ERC20 差得多——想卖的时候不一定有人接。实际操作前请自行核实官方文档，先在测试网（比如 Sepolia）上完整走一遍流程，再考虑主网，而且永远只用你输得起的金额。

## 总结

1. **NFT 是非同质化 Token：** 每个都有唯一的编号，不能互相替换。ERC20 是“一堆一样的 Token”，ERC721 是“一群各不相同的 Token”。
2. **根本区别在记账方式：** ERC20 按地址记数量（`mapping(address => uint256)`），ERC721 按编号记归属（`mapping(uint256 => address)`）。一个记“你有几个”，一个记“这个编号归谁”。
3. **ERC721 标准定在 2018 年 1 月：** 核心函数是 `balanceOf`、`ownerOf`、`transferFrom`、`safeTransferFrom`、`approve`、`setApprovalForAll` 等，接口编号 `0x80ac58cd`；元数据扩展（`name`、`symbol`、`tokenURI`）是可选的，但现实中几乎人人都在用。
4. **NFT 本身不是图片：** 链上只有一条所有权记录和一个指向 JSON 文件的链接，图片存在 IPFS 或服务器上。买 NFT 买到的是记录和链接，不是图片版权。
5. **NFT 是被一只猫带火的：** CryptoKitties 2017 年 11 月上线，一度占以太坊约 25% 的流量，创世猫卖出 246.9255 个 ETH，直接推动了 ERC721 标准的定稿。
6. **NFT 的用处不止收藏：** 游戏道具、门票、域名、证书、凭证——只要东西唯一、且“归谁”很重要，就适合用 NFT。
7. **五个坑要记住：** 没买到版权、图片不在链上、转错地址拿不回、授权开了忘关、稀缺不等于值钱。

到这里，NFT 这条线正式开始了：从第 15 篇的 ERC20，到这篇的 ERC721，你已经认识了以太坊上最常用的两种 Token 标准。**下次再有人问你“NFT 到底是什么”，你可以直接回答他：**

**就是一种每个都有编号的 Token，合约里记的不是“你有几个”，而是“这个编号归谁”。图片不在链上，链上只有记录和链接。**
