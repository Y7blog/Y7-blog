如果你已经跟着前面的文章了解了 Solidity，也试过在 Remix 里编写和编译代码，那么接下来就可以真正动手了。

今天我们不讲太多理论，只做一件事：

**从零开始，把一个智能合约部署起来，再亲手调用它。**

整个过程可以拆成四步：

**编写代码 → 编译合约 → 部署合约 → 调用合约**

不需要安装本地开发环境，也不需要购买 ETH。我们会先使用 Remix 自带的虚拟区块链完成实验。

如果操作顺利，几分钟就能跑通整个流程。当然，第一次接触开发工具时，花更长时间也很正常。

## 一、先搞清楚：今天到底要做什么？

在开始之前，先解释三个容易混淆的概念。

**1. 编写合约**

就像编写普通程序一样，我们使用 Solidity 语言描述合约应该做什么。

**2. 部署合约**

编写完成的代码还不能直接在区块链上使用。我们需要经过编译，并将合约部署到指定的区块链环境中。

可以把它理解成：写好一份程序，再把它放到能够执行这份程序的环境里。

**3. 调用合约**

合约部署成功后，我们就可以调用它提供的函数。例如，读取一条消息，或者修改这条消息。

今天要完成的目标很简单：

- 创建一个名为 `HelloY7` 的智能合约。
- 让合约保存一条消息。
- 成功编译并部署合约。
- 读取消息，再修改消息。
- 确认修改后的结果。

整个实验会使用 Remix VM，也就是 Remix 提供的虚拟区块链环境。

注意：**这次实验是在虚拟环境中完成的，不等于已经把合约部署到了 Ethereum 主网。** 但对于理解开发流程来说，这已经足够了。

## 二、准备开发环境：打开 Remix

首先打开 Remix 官方网站：

https://remix.ethereum.org/

Remix 是一个可以直接在浏览器中使用的 Ethereum 智能合约开发工具。我们可以在里面编写 Solidity、编译代码、部署合约，以及调用合约函数。

如果你跟着上一篇文章操作过，这部分应该很熟悉。

打开 Remix 后，找到左侧的文件管理器。

### 第一步：创建 Solidity 文件

新建一个文件，命名为：

`HelloY7.sol`

`.sol` 是 Solidity 源代码文件常用的扩展名。

接下来，把下面的代码完整复制进去。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract HelloY7 {
    string public message = "Hello, Y7 Blog!";

    function setMessage(string memory newMessage) public {
        message = newMessage;
    }
}
```

这就是我们今天要部署的第一个智能合约。

代码不长，但已经包含了智能合约开发中非常重要的几个概念：合约、状态变量、函数和数据修改。

### 第二步：看懂这段代码

如果你暂时看不懂每一行，不用担心。我们只需要先理解它的基本作用。

**`pragma solidity ^0.8.20;`**

这一行声明了代码使用的 Solidity 编译器版本范围。

它并不是说只能使用 0.8.20 这一个版本，而是允许使用符合该版本约束的兼容编译器。

**`contract HelloY7`**

这是合约的定义，名字叫 `HelloY7`。

你可以先把 `contract` 理解成 Solidity 中用来定义智能合约的关键字。

**`string public message = "Hello, Y7 Blog!";`**

这一行定义了一个字符串类型的状态变量 `message`，初始值是 `Hello, Y7 Blog!`。

这里有两个重点：

- `string` 表示字符串。
- `public` 表示这个变量可以通过 Solidity 自动生成的 getter 函数读取。

因此，我们不需要额外编写一个读取消息的函数，就可以直接查看 `message` 的值。

**`function setMessage(string memory newMessage) public`**

这是一个用于修改消息的函数。

调用它时，我们可以传入一段新的文字。例如：

`Hello Blockchain!`

函数会把传入的内容写入 `message`：

```solidity
message = newMessage;
```

这里的 `memory` 用于声明函数参数字符串在执行过程中的数据位置。初学阶段可以先记住：它出现在这个参数声明中，不代表消息会永久保存在内存里。

真正决定消息能否在后续调用中保留的，是我们把新值写入了状态变量 `message`。

到这里，代码就准备好了。

## 三、编译合约：先检查代码能不能运行

代码写完后，下一步不是直接部署，而是先编译。

在 Remix 左侧找到 **Solidity Compiler**，进入编译器面板。

### 第一步：选择编译器版本

代码中写的是：

```solidity
pragma solidity ^0.8.20;
```

因此，选择一个符合版本约束的 Solidity 0.8.x 编译器即可。

如果你选择的编译器版本与代码声明不兼容，就可能出现版本错误。

### 第二步：点击 Compile

找到对应的编译按钮：

`Compile HelloY7.sol`

点击后，等待编译完成。

如果没有出现编译错误，通常说明这份代码已经通过了当前编译器的检查，可以进入部署环节。

如果出现红色错误提示，先不要急着继续操作。检查以下几项：

- 文件名是否正确。
- 代码有没有漏掉分号或大括号。
- `pragma` 声明与编译器版本是否兼容。
- 复制代码时有没有多复制或漏复制内容。

这里有个容易忽略的区别：

**编译成功，不代表合约已经部署。**

编译器会将 Solidity 源代码转换为 EVM 可以执行的字节码，并生成 ABI 等相关信息。

简单理解：

- 源代码：开发者编写的代码。
- 字节码：供 EVM 执行的程序表示。
- ABI：描述合约如何与外部交互的接口信息。

这些内容会在后续调用已经部署的合约时继续发挥作用。

如果想进一步了解编译过程，可以查看 [Remix 官方编译器文档](https://remix-ide.readthedocs.io/en/latest/compile.html)。

## 四、部署合约：让它在虚拟区块链中运行

现在进入最关键的一步。

在 Remix 左侧找到 **Deploy & Run Transactions** 面板。

这个面板主要负责部署合约、加载已有合约，以及与合约进行交互。

### 第一步：选择环境

找到 `ENVIRONMENT` 选项，选择 Remix VM。

不同版本的 Remix 界面可能会有细微差别，但核心目标一致：使用 Remix 自带的虚拟区块链，而不是连接真实公共网络。

为什么先选 Remix VM？

因为它适合新手练习。我们可以在模拟环境里完成部署和状态修改，不需要准备真实 ETH，也不会因为这次实验产生真实主网交易费用。

### 第二步：选择合约

确认当前选择的合约是：

`HelloY7`

如果下拉列表中没有这个合约，先回到编译器，确认刚才的编译是否成功，以及当前打开的文件是不是 `HelloY7.sol`。

### 第三步：点击 Deploy

确认环境和合约都正确后，点击：

`Deploy`

稍等片刻。

如果一切正常，你会看到 Remix 的部署记录，并且在 `Deployed Contracts` 区域出现一个新的合约实例。

恭喜，你已经完成了第一个智能合约的部署。

不过这里要特别注意：

**你现在得到的是 Remix VM 中的合约实例，不是 Ethereum 主网上的合约。**

如果刷新或重置虚拟环境，实验数据可能会消失。因此，暂时不要把它当成已经公开部署、能够长期访问的真实链上应用。

### 部署成功意味着什么？

可以把刚才的操作拆成两个阶段：

1. 编译阶段：把 Solidity 源代码转换为合约部署所需的程序产物。
2. 部署阶段：在当前环境中创建合约实例，并得到可以交互的合约地址。

部署到真实公共链时，通常需要提交一笔部署交易，并支付相应的 Gas 费用。

而在 Remix VM 中，我们使用的是模拟环境，所以不需要真实 ETH 来支付主网 Gas。

## 五、调用合约：读取并修改第一条链上状态

如果你已经在 `Deployed Contracts` 区域看到 `HelloY7`，接下来就可以开始交互了。

这一步比单纯部署更重要，因为它能让我们真正理解智能合约是如何被使用的。

### 第一步：读取消息

展开 `HelloY7` 合约实例。

你应该能看到一个名为：

`message`

的按钮。

点击它。

正常情况下，返回结果应该是：

`Hello, Y7 Blog!`

为什么直接点击就能读取？

因为我们定义变量时使用了 `public`：

```solidity
string public message = "Hello, Y7 Blog!";
```

Solidity 会自动为这个公开状态变量生成 getter 函数，让外部可以读取它的值。

这次读取不会修改合约状态。

### 第二步：修改消息

现在找到：

`setMessage`

这个函数。

它需要接收一个字符串参数。

在输入框中填入：

`Hello Blockchain!`

然后点击 `setMessage` 按钮。

稍等片刻，观察 Remix 的执行记录。

如果调用成功，就说明函数已经执行，并把新的字符串写入了状态变量。

### 第三步：再次读取消息

再点击一次 `message` 按钮。

这次你应该看到：

`Hello Blockchain!`

这就完成了整个实验。

我们先读取原始值，再调用修改函数，最后重新读取，确认状态已经发生变化。

这几个步骤看起来简单，却包含了智能合约开发中很核心的操作：

**读取状态 → 执行函数 → 修改状态 → 验证结果。**

### 这里有个值得注意的区别

读取和修改状态，并不是完全相同的操作。

在这个合约中，`message` 的 getter 用于读取当前状态；`setMessage()` 则会修改状态变量。

在真实 Ethereum 网络上，单纯读取状态通常可以通过 RPC 调用完成，不需要发送一笔上链交易，也通常不需要用户为这次读取支付链上 Gas。

但修改状态需要通过交易执行，并支付相应费用。

在 Remix VM 中，这些操作发生在模拟环境里。你可以用它学习交互流程，但不要把模拟环境的执行记录直接当作真实链上交易。

## 六、部署成功后，应该关注哪些信息？

第一次部署成功时，Remix 可能会显示不少信息。

不用急着把所有字段都记下来。先认识下面几个就够了。

| 信息 | 可以怎么理解 |
| --- | --- |
| 合约名称 | 当前部署的是哪个合约，例如 `HelloY7` |
| 合约地址 | 当前合约实例在对应区块链环境中的地址 |
| 交易记录 | 部署或执行写入操作时产生的执行记录 |
| 状态变量 | 合约当前保存的数据，例如 `message` |
| ABI | 外部程序如何识别并调用合约接口的描述 |

其中，**合约地址和钱包地址不是同一个概念**。

钱包地址通常与账户及其控制密钥有关；合约地址则指向已经部署的合约实例。

此外，合约地址必须结合具体网络来理解。同一个地址字符串出现在不同网络上，并不自动意味着它们指向同一个合约实例。

今天使用的是 Remix VM，因此当前看到的地址只用于这次虚拟环境中的实验。

等到后面学习 Etherscan 和真实测试网部署时，我们再深入了解交易 Hash、区块高度、合约地址以及如何在区块链浏览器中核对部署结果。

## 七、常见问题：为什么我没有成功？

如果你的操作没有完全按照预期进行，可以先检查以下情况。

### 1. 编译器提示版本错误

回到 Solidity Compiler，确认选择的编译器版本与 `pragma solidity ^0.8.20;` 兼容。

如果代码中有拼写错误，也可能导致编译失败。

### 2. 点击 Deploy 后没有出现合约

先确认：

- 编译是否成功。
- 当前选中的合约是否为 `HelloY7`。
- `ENVIRONMENT` 是否选择了 Remix VM。
- 是否出现了错误信息。

如果部署失败，可以查看 Remix 的终端或执行记录，寻找具体报错，而不是反复点击 Deploy。

### 3. 找不到 `message` 或 `setMessage`

确认部署的是 `HelloY7`，而不是其他合约。

然后检查源码中是否确实包含公开状态变量 `message` 和函数 `setMessage()`，并重新编译后部署。

如果修改源码后才重新编译，记得确认当前交互的是最新部署的合约实例。

### 4. 修改后，消息没有变化

检查 `setMessage()` 是否执行成功，以及输入框中是否填入了新的字符串参数。

然后重新点击 `message` 读取结果。

不要只看函数调用按钮是否被点击，而要通过再次读取状态来确认结果。

### 5. 为什么没有真实交易 Hash 或主网记录？

因为你使用的是 Remix VM。

它是用于开发和测试的模拟环境，不等于 Ethereum 主网或公共测试网。想要在公共网络中查看部署交易，需要后续连接对应的网络，并完成真实的部署流程。

## 八、完成这次实验，你真正学会了什么？

到这里，我们没有编写复杂的合约，也没有涉及 Token、NFT 或预言机。

但你已经走完了一条完整的智能合约开发路径：

1. 使用 Solidity 编写合约。
2. 使用编译器生成合约的编译产物。
3. 在 Remix VM 中部署合约。
4. 读取合约的公开状态。
5. 调用函数修改状态，并再次读取验证结果。

我觉得，入门阶段最重要的不是记住多少术语，而是亲手跑通一次流程。

当你看到 `Hello, Y7 Blog!` 变成 `Hello Blockchain!` 时，就不再只是看别人讲智能合约了。你已经知道，合约可以保存状态，也可以通过函数按照预先定义的逻辑改变状态。

当然，这还只是一个非常简单的实验合约。真实应用还需要考虑权限控制、异常处理、测试、安全审计以及部署网络等问题。不要因为它能成功运行，就认为它已经适合处理真实资产。
