你打开一个跨链页面，想把 10 个 USDC 从 Sepolia 跨到 Fuji。点下“发送”，钱包弹出来一个确认框——不是让你确认转账，而是让你先确认一个叫 Approve 的操作。你点了确认，付了一笔 Gas 费，可你的 USDC 一分都没动。再点一次“发送”，钱包又弹出来一个确认框，这次才是真正的转账。

**为什么转个币，要先同意一次，才能转账？这个 Approve，到底批准了什么？**

简单来说，Approve 就是你亲手写的一张授权书：**你允许某个智能合约，在你规定的额度内，替你动你的 Token。** 授权书本身不转走任何币，它只是把“能不能动”的开关，交到了合约手里。这篇文章，就把这张授权书从头到尾讲清楚。

> 💡 **先说清楚**：本文只讲 ERC20 授权的原理和测试网操作，不教你操作任何真实资产，也不推荐你去用某个具体产品。**本文是知识科普，不是投资建议。** 全文只在测试网操作，先在测试网练手，不要用真实资产做实验。

## 一、为什么转个币，要先同意一次，才能转账？

先想一个生活里的场景：你把车停在餐厅门口，把车钥匙交给代客泊车的小哥。

你把钥匙交出去，不等于把车送给他。钥匙只是让他有能力把你的车开到停车场。车还是你的，停在哪、什么时候取回来，还是你说了算。只不过，从这一刻起，他确实能开动你的车——所以你一定会先看一眼：这个人靠不靠谱？是餐厅正式的泊车员，还是路边随便一个人？

ERC20 的授权，就是这个道理。

### 你自己转账，和让合约替你转账，是两回事

你自己从钱包转 USDC 给朋友，用的是 `transfer()`：你自己签名、自己发交易，币直接从你的地址到朋友的地址。中间没有别人插手，不需要任何授权。

但跨链不一样。跨链的时候，真正去动你的币的不是你，而是一个智能合约——比如 Chainlink CCIP 的路由器合约，或者一个跨链合约。它要替你把币锁起来、烧掉、或者在目标链上铸出来。**合约没有你的私钥，它不能替你签名，所以它动不了你的币——除非你先授权给它。**

这就是为什么跨链之前，钱包会先弹出 Approve：它在问你：“你同不同意，让这个合约替你动你的币？同意的话，最多动多少？”

### 授权书的三个要素

一张授权书，其实只写了三件事：

| 要素 | 对应什么 | 打个比方 |
|---|---|---|
| 谁授权 | 你的地址（owner） | 车主是你 |
| 授权给谁 | 合约的地址（spender） | 钥匙交给泊车员 |
| 最多动多少 | 额度（amount） | 只允许他把车开到停车场，不能开出城 |

**授权不等于转账。** 你点了 Approve、付了 Gas 费，钱包里的币一分都不会少。变的只是一条链上的记录：这个合约现在被允许动你的币了，最多动多少。真正的转账，要等下一步 `transferFrom()` 发生的时候才动。

## 二、approve、allowance、transferFrom：三个函数，一张授权书

ERC20 标准（EIP-20）里，和授权有关的其实只有三个函数。把这三个函数的关系搞懂，授权这件事就懂了一大半。

### 先看这三个函数是干什么的

| 函数 | 谁调用 | 它是干什么的 |
|---|---|---|
| `approve(spender, amount)` | 你（币的主人） | 写一张授权书：允许 spender 最多动你 amount 这么多币 |
| `allowance(owner, spender)` | 任何人都能查 | 查一张授权书还剩多少额度：spender 还能动 owner 的多少币 |
| `transferFrom(sender, recipient, amount)` | 被授权的合约 | 凭授权书办事：把 sender 的 amount 个币转给 recipient，同时扣掉相应的额度 |

这三个函数是这样配合的：

```
你调用 approve(跨链合约, 100)
    ↓
链上记下：跨链合约可以动你的币，最多 100 个
    ↓
跨链合约调用 transferFrom(你, 目标地址, 100)
    ↓
合约检查：你的余额够不够 100？授权额度够不够 100？
    ↓
都够，就转走 100 个币，同时把授权额度扣成 0
    ↓
链上发出两条记录：Transfer 事件 + Approval 事件（额度变了）
```

### allowance：授权书还剩多少额度，随时能查

`allowance()` 是一个只读函数，不用花 Gas，谁都能查。它回答的问题很简单：“这个合约现在还能动我多少币？”

刚开始，没授权过，答案是 0。你授权了 100，答案变成 100。合约替你转走了 60，答案变成 40。合约替你转走了剩下的 40，答案变回 0。

**查 allowance，是你检查自己授权状态最直接的办法。** 在 Etherscan 上打开任意一个 ERC20 Token 合约，点“Read Contract”，找到 `allowance`，填你的地址和合约地址，就能看到还剩多少额度。后面第五节会手把手走一遍。

### approve 会覆盖旧的额度，不是累加

这一点经常被人搞错：**你再调用一次 `approve()`，新的额度会直接覆盖旧的额度，而不是加上去。**

比如你先授权了 100，合约用了 60，还剩 40。这时候你又调用 `approve(同一个合约, 100)`，额度会变成 100，而不是 140。

这个规则本身没什么问题，但它藏着一个历史遗留的坑：改额度的时候，如果交易顺序被别人插了队，旧额度和新额度可能被各用一次。EIP-20 的官方说明里就提醒过这个竞态问题，标准做法是**先把额度改成 0，再设成你想要的新值**。OpenZeppelin 的实现里还专门加了 `increaseAllowance` 和 `decreaseAllowance` 两个函数，就是为了让你不用直接改额度、避开这个坑。

### 无限授权：额度填了最大值，就永远不会扣完

还有一个特殊情况要单独说：如果授权的额度填的是 `uint256` 的最大值（2 的 256 次方减 1，一个大到不可能花完的数字），OpenZeppelin 的实现里，`transferFrom` 执行时就**不再扣减额度**。从效果上看，这就是一张永远用不完的授权书，也就是常说的“无限授权”。

很多应用默认就是这么干的：让你一次授权无限额度，以后每次交易就不用再重复授权了。省事是真的省事，风险也是真的存在。第六节专门讲这个。

```
approve(spender, amount)
    → 链上记录：allowance[你的地址][spender] = amount
    → 发出 Approval 事件

transferFrom(sender, recipient, amount)
    → 检查：余额 >= amount，且 allowance >= amount
    → 转账：sender 的余额减 amount，recipient 的余额加 amount
    → 扣额度：allowance 减 amount（无限授权除外，不扣）
    → 发出 Transfer 事件
```

## 三、授权之后，你的币还在你手里吗？

这是新手问得最多的问题，也是最容易产生误解的地方。答案是：**在，还是你的。但“能动它的人”，多了一个。**

### 授权写在哪里？不在你的钱包里，在 Token 合约里

授权这条记录，不存在你的钱包里，也不存在那个合约里，它存在 **Token 合约内部的一张表**里。

这张表在技术上叫 `_allowances`，是一个两层映射：第一层是你的地址，第二层是被授权的合约地址，值就是剩余额度。用大白话说，就是 Token 合约手里有一本账，上面记着：“这个地址，允许那个合约动多少币。”

所以，授权这件事有三个特点，很多人第一次听说都会觉得意外：

- **断开钱包连接，授权不会消失。** 授权记录在链上的 Token 合约里，不在网页的登录状态里。你关掉网页、断开钱包、甚至换一台电脑，授权都还在。
- **授权没有过期时间。** 你今天授权的额度，下个月、明年都还在，除非合约把它用完，或者你自己把它改回 0。时间不会帮你收回授权。
- **授权是按 Token、按链分的。** 你在 Sepolia 上授权了 USDC，不等于在 Fuji 上也授权了；你授权了 USDC，不等于授权了 LINK。每条链、每个 Token 的授权，都是分开记的。

### 授权和转账，到底有什么区别？

| 对比 | 授权 approve() | 转账 transfer() / transferFrom() |
|---|---|---|
| 币动了没有 | 没动，余额一分不少 | 动了，余额真的变了 |
| 谁发起的 | 币的主人（你） | 币的主人自己，或者被授权的合约 |
| 花 Gas 吗 | 花，你要付一笔 Gas 费 | 花，发起的人付 Gas 费 |
| 能反悔吗 | 能，再调一次 approve 改成 0 | 不能，链上交易发出去就收不回来 |
| 留下什么记录 | Approval 事件 | Transfer 事件 |

记住这张表，下一节讲跨链的时候，你就不会再把“授权”和“转账”搞混了。

## 四、跨链前为什么必须先授权？走一遍 CCIP 的授权链条

前面几节讲的是授权本身，这一节把授权放回跨链的流程里，看它到底卡在哪一步。

### 跨链不是直接把币“送过去”

第 23 篇讲过，Token 跨链不是把币从一条链直接搬到另一条链，而是“这边锁定或者销毁，那边铸造或者解锁”。不管是哪种方式，源链上总要有一个合约先把你的币收走、管起来，然后 CCIP 的路由器再把消息和 Token 发往目标链。

这个“收走你的币”的动作，就是 `transferFrom()`。而合约想调用 `transferFrom()`，前提就是你先授权给它。没有授权，合约一调用就会被 Token 合约拒绝，整笔跨链直接失败。

### 一次跨链，要过几道授权？

以 Chainlink 官方文档里的跨链 Token 转移合约（TokenTransferor）为例，一次跨链要经过这样一条授权链：

```
你（钱包）
    ↓ ① approve(TokenTransferor 合约, 要跨的 Token 数量)
    ↓    —— 你允许这个合约动你的 Token
TokenTransferor 合约
    ↓ ② 调用 transferFrom，把你的 Token 拉进合约
    ↓ ③ approve(CCIP 路由器, 同样数量)
    ↓    —— 合约允许路由器动这些 Token
CCIP 路由器
    ↓ ④ 调用 transferFrom，把 Token 收进路由器 / Token 池
    ↓ ⑤ ccipSend()，把跨链消息发往目标链
目标链
    ↓ ⑥ 解锁或铸造同样数量的 Token，发给接收地址
```

注意，第①步是你自己在钱包里点的，第③步是合约在链上自动做的。你只需要做第①步，后面的步骤都是合约替你完成的——但前提是第①步你确实授权了。

### 跨链的手续费，也要授权

如果跨链的手续费选择用 LINK 支付，还会多一道授权：你得先把 LINK 也授权给这个合约（或者先把 LINK 转进合约），合约才能拿 LINK 去付 CCIP 的手续费。Chainlink 官方文档的最新教程里就是这样写的：先 `approve` 合约可以动你的 CCIP-BnM 测试 Token，再 `approve` 合约可以动你的 LINK，最后才调用发送函数。

手续费也可以选择用源链的原生 Gas 币（比如 ETH）支付，那就不用授权 LINK，直接在调用时把 ETH 一起发过去就行。具体用哪种，看你调用的函数和传的参数。下一篇文章（第 26 篇）会专门讲 LINK 在跨链里到底起了什么作用。

### 先算手续费，再授权

CCIP 的路由器提供了一个 `getFee()` 函数：你把目标链、要发的消息、要转的 Token 告诉它，它会先告诉你这笔跨链大概要收多少手续费。**先问价，再授权、再发送**，是比较稳妥的顺序。官方教程也是这个顺序：先调 `getFee()` 拿到费用，再处理授权，最后才 `ccipSend()`。

手续费不是固定的，它跟目标链、消息大小、目标链的 Gas 价都有关系，测试网和主网也不一样。所以不要背某个具体的数字，每次跨链之前，先用 `getFee()` 问一次。

## 五、动手：在 Remix 和 Etherscan 上授权、查额度

光看原理不够，这一节动手走一遍。全部用测试网，不花真钱。

### 准备：测试网的 Token 和水龙头

以 Sepolia 为例，Chainlink 官方提供了一个测试 Token 叫 CCIP-BnM，专门用来练跨链。它在 Sepolia 上的合约地址是 `0xFd57b4ddBf88a4e07fF4e34C487b99af2Fe82a05`。LINK 在 Sepolia 上的地址是 `0x779877A7B0D9E8603169DdbD7836e478b4624789`。这两个地址以 Chainlink 的 CCIP Directory 为准，动手之前先去官方目录核对一次，不要从聊天群、论坛帖子里复制地址。

CCIP-BnM 和测试网 LINK 都可以从 Chainlink 的水龙头领。领之前，先确认你的钱包已经切到了 Sepolia（第 24 篇讲过怎么切网络）。

### 第 1 步：在 Etherscan 上查你现在的授权额度

1. 打开 Sepolia 的浏览器 sepolia.etherscan.io，搜 CCIP-BnM 的合约地址。
2. 点“Contract”→“Read Contract”，找到 `allowance`。
3. 第一个空填你的钱包地址（owner），第二个空填你想查的合约地址（spender），比如 CCIP 路由器或者 TokenTransferor 的地址。
4. 点查询，返回的数字就是还剩多少额度。第一次查，没有授权过，应该是 0。

### 第 2 步：在 Remix 里调 approve()

1. 打开 Remix，连接 MetaMask（确认已经切到 Sepolia）。
2. 用最简单的 IERC20 接口，或者直接用 OpenZeppelin 的 ERC20 合约，填 CCIP-BnM 的合约地址，加载合约。
3. 找到 `approve` 函数：第一个参数填你要授权的合约地址（spender），第二个参数填额度（amount）。练手的时候，先填一个小数字，比如 10 个 Token 对应的最小单位——注意 CCIP-BnM 的小数位数，别直接填 10。
4. 点 transact，钱包弹出确认框，核对 spender 地址和额度，确认，付 Gas 费。
5. 交易确认之后，回到 Etherscan 再查一次 `allowance`，额度应该已经变成你刚才填的数字了。再看一眼你的余额：**一分都没少。** 这就是授权和转账的区别，最直观的证据。

### 第 3 步：再调一次 allowance，看看额度是怎么扣的

如果你接着用被授权的合约调一次 `transferFrom()`，把一部分 Token 转走，再回来查 `allowance`，你会看到额度跟着减少了。转走多少，额度就少多少。转完剩下的部分，额度不会自己恢复——想再转，就得重新授权。

```
查 allowance（授权前）
    ↓ 返回 0
调 approve(合约地址, 100)
    ↓ 付 Gas，余额不变
再查 allowance
    ↓ 返回 100
合约调 transferFrom(你, 别人, 60)
    ↓ 余额减 60
再查 allowance
    ↓ 返回 40
```

### 读懂钱包弹出的授权确认框

以后你在任何页面点授权，钱包弹出的确认框里其实就三样东西值得你逐字看：

1. **Spender 是谁**：你要授权的合约地址。跟官方文档给的地址逐字对一下，错一个字符就是另一个合约。
2. **额度是多少**：是具体数字，还是无限（Unlimited / Max）。无限授权在钱包里通常会显示成一串很长的数字，或者直接写“无限制”。
3. **这是什么 Token**：授权的是哪个 Token 的合约。别在 USDC 的页面上，授权了 LINK 的合约。

这三样看清楚了，再点确认。养成这个习惯，比事后去查授权记录有用得多。

## 六、无限授权：省事，但代价是什么？

前面提到过，很多应用默认让你授权无限额度。为什么大家都这么干？因为每次交易都重新授权，要多付一笔 Gas 费，还要多点一次确认。对用户来说很烦，对应用来说体验很差。所以应用干脆说：“你一次授权无限额度，以后都不用再授权了。”

这个做法本身不是骗局，但它把风险留给了你。

### 无限授权的风险，到底在哪里？

无限授权的风险不在授权的那一刻，而在授权之后的日子里：

- **授权不会过期。** 你今天授权给一个合约，半年后你早就忘了这回事，授权还在。合约想动你的币，随时都能动，不用再经过你。
- **合约被黑，你的币跟着遭殃。** 如果这个合约后来出了漏洞、被攻击者控制了，攻击者继承的就是这份无限授权，可以直接调用 `transferFrom` 把你的币转走，不需要你再点任何确认。
- **假合约、钓鱼页面，骗的就是一次授权。** 很多钱包盗窃案不是直接偷私钥，而是诱导你给一个恶意合约授权。授权一点，你的币就处在能被转走的状态了。

2026 年的几篇安全复盘文章都提到同一个结论：钱包被盗，很多时候不是私钥泄露，而是几个月前授权过、后来忘掉的无限授权被利用了。授权本身不是漏洞，**忘掉的授权才是。**

### 那是不是永远不要用无限授权？

也不是。比较务实的做法是分情况：

| 情况 | 建议 |
|---|---|
| 你每天都在用的大协议，合约经过多次审计，比如 Uniswap、Aave 这类 | 无限授权可以接受，但要定期检查 |
| 你只用一次的跨链、一次性的测试合约 | 只授权这次要用的数量，用完就收回 |
| 你不认识、没听说过、刚上线的合约 | 先授权最小够用的数量，或者干脆别授权 |
| 测试网练手 | 随便授权，测试币不值钱，但要养成看确认框的习惯 |

**核心原则就一句话：授权额度越小、授权对象越少、授权时间越短，风险越小。** 方便和安全之间，永远要做取舍，没有两全其美的默认选项。

### 新变化：不用上链也能授权，授权也能“只管一次”

授权这件事本身也在进化，有两个新发展值得知道：

- **EIP-2612 的 permit**：通过链下签名来改授权额度，不用再发一笔链上 Approve 交易，省 Gas，也省一次确认。很多新 Token（比如 USDC）已经支持了。OpenZeppelin 里对应的实现叫 ERC20Permit。
- **ERC-7674 的临时授权**：OpenZeppelin 5.x 里新加的 ERC20TemporaryApproval，让授权只在一次交易里有效，用完自动失效。相当于把“无限授权”改成了“一次性授权”，对跨链、兑换这类场景很友好。

这两个现在还不是每篇都要用的东西，但你以后在钱包里看到“签名授权”而不是“链上授权”，或者看到“一次性授权”的选项，就知道它是从哪来的了。

## 七、授权怎么收回？approve 回 0、定期检查

授权能给出去，也能收回来。收回的方法其实就是你已经学会的那个函数：**再调一次 `approve()`，把额度改成 0。**

### 收回授权，就是 approve(spender, 0)

```
approve(同一个合约地址, 0)
    ↓ 付一笔 Gas 费
    ↓ 链上记录：allowance[你的地址][这个合约] = 0
    ↓ 这个合约再也不能动你的币了
```

这笔操作也要花 Gas 费，但它买的是安心。用完一次性的跨链合约、测完一个不熟的协议，顺手把授权清掉，是个好习惯。

### 怎么知道自己授权过哪些合约？

光靠记忆肯定记不住，要用工具查。常用的有两个：

- **Revoke.cash**：连上钱包，它会列出你授权过的所有合约、每种 Token 的剩余额度，点一下 Revoke 就能批量收回。支持 80 多条链，包括以太坊、Arbitrum、Base 这些常用链。
- **Etherscan 的 Token Approval Checker**：在 Etherscan 上输入你的地址，就能看到你在以太坊主网上的授权记录，点一下就能撤销。

查的时候重点看三类：**额度是无限的、你已经很久没用过的、你不认识的合约。** 这三类，优先收回。收回之前先确认，这个合约是不是你现在还在用的协议正在依赖的——收回了正在用的授权，下次交易会失败，需要重新授权才能继续，不是什么大事。

### 养成一个定期检查的习惯

不用每天查，但可以定一个节奏，比如每个月花十分钟：

1. 打开 Revoke.cash，连上钱包，看一眼授权列表。
2. 把不用的、无限额度的、很久没碰过的合约，额度清成 0。
3. 正在用的大协议，留着就行，下次再检查。

**授权管理不是一次性动作，是持续的习惯。** 就像你不会把家门钥匙随便发给别人、发出去之后也不管了一样，链上的授权书也值得你定期回头看一眼。

## 八、新手最容易踩的五个坑

前面几节讲的都是“怎么做对”，这一节讲“怎么做错”。这五个坑，都是新手真实踩过的。

### 坑 1：以为点了 Approve，币就已经转过去了

这是经常犯的错。点了 Approve，钱包显示交易成功了，很多人就以为跨链完成了，关掉页面就走了。其实 Approve 只是授权，真正的转账还没发生。

**怎么避开：Approve 之后，一定要再完成真正的发送交易，并且去目标链的浏览器上确认币到账了，再关页面。**

### 坑 2：授权给了错误的合约地址

授权书上写错一个字符，授权就给了另一个合约。钓鱼页面最常用的手法，就是放一个看起来很像官方合约的地址，等你授权。

**怎么避开：授权之前，先去官方文档或者 CCIP Directory 核对合约地址。不要从聊天群、论坛帖子、搜索引擎广告里复制地址。**

### 坑 3：给不熟的合约开了无限授权

刚认识的合约、只用一次的页面，默认弹出来的经常是无限授权。很多人看都不看就点了确认。

**怎么避开：确认框里先看额度那一行。如果是无限，先改成这次要用的具体数字。只给够用的额度，不给多余的。**

### 坑 4：改额度的时候，直接从旧值改成新值

前面讲过，直接改额度有竞态风险：旧额度和新额度可能被各用一次。

**怎么避开：先把额度改成 0，确认上链之后，再设成你想要的新值。或者直接用 OpenZeppelin 的 `increaseAllowance` / `decreaseAllowance`，按增量改。**

### 坑 5：以为换了链，授权就跟着走了

授权是按链、按 Token 分开记的。你在 Sepolia 上授权了 CCIP-BnM，到了 Fuji 上还要重新授权；你在 Sepolia 上授权了 USDC，不等于授权了 LINK。

**怎么避开：每次换链、换 Token，都先查一次 `allowance`，确认这条链、这个 Token 的授权状态，再动手。**

> ⚠️ **风险提示**：授权操作涉及真实资产的移动权限，不同合约、不同 Token、不同链的风险差异很大。本文只讲原理和测试网操作，不构成任何操作建议或投资建议。实际操作前请自行核实官方文档，先在测试网（比如 Sepolia、Fuji）上完整走一遍流程，再考虑主网——而且永远只用你输得起的金额。

## 总结

1. **授权不等于转账。** `approve()` 只是写一张授权书，你的币还在自己手里；真正的转账要等 `transferFrom()` 发生。授权花 Gas，但不减少余额。
2. **三个函数分工明确：** `approve()` 写授权书，`allowance()` 查还剩多少额度，`transferFrom()` 凭授权书办事。`approve()` 会覆盖旧额度，改额度先清零再设新值。
3. **授权记录在 Token 合约里。** 断开钱包、换电脑、过再久，授权都还在；它没有过期时间，不用不会自己消失；每条链、每个 Token 的授权都是分开记的。
4. **跨链必须先授权。** CCIP 这类跨链合约要调用 `transferFrom()` 才能收走你的币，没有你的授权，它一步都动不了。手续费如果用 LINK 付，LINK 也要单独授权。
5. **无限授权图省事，但风险也大。** 额度填了最大值就永远不会扣完，合约一旦出问题，你的币随时可能被转走。不熟的合约只给够用的额度，用完就收回。
6. **收回授权就是 `approve(spender, 0)`。** 定期用 Revoke.cash 或者 Etherscan 的 Token Approval Checker 查一次授权，把不用的、无限的、很久没碰的授权清掉。

下次再有人问你“跨链前为什么要先授权”，你可以直接回答他：

**因为合约没有你的私钥，动不了你的币。你先写一张授权书，告诉 Token 合约“这个合约可以动我的币，最多动多少”，它才能替你把币收走、发往另一条链。授权书不转走币，但写错了对象、给多了额度，代价也不小。**
