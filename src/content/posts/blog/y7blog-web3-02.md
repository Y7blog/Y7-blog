**从 0 开始理解区块链，不需要任何开发经验。**

很多人第一次接触区块链，看到的解释通常是：

**区块链是一种去中心化的分布式账本。**

这个解释没有错。

但如果你只是记住这句话，其实很难真正理解区块链到底是怎么工作的。

因为接下来你很快就会遇到一堆新的问题：

- 区块链到底在“记录”什么？
- 一笔交易发送出去之后发生了什么？
- 为什么交易需要被打包进区块？
- 为什么所有节点都要保存一份数据？
- 为什么大家最后看到的结果必须一样？
- 智能合约又是怎么运行的？
- 为什么说区块链具有“确定性”？

如果想真正进入区块链开发，我更推荐从一个看起来有点抽象、但非常重要的概念开始：

> **状态机（State Machine）。**

你可以先把区块链理解成：

> **一个由很多计算机共同维护的、不断根据交易改变状态的分布式状态机。**

听起来还是有点复杂。

没关系。

这篇文章我们不急着写代码，也不急着讨论 Solidity、Token 或 Chainlink。

先把一个最基础的问题搞明白：

> **区块链到底是什么？**

---

# 01｜区块链到底是什么？

先想一个最简单的问题：

假设你有一个账户。

里面有：

```text
余额：100 元
```

现在你给朋友转了 30 元。

转账完成之后：

```text
你的余额：70 元
朋友余额：30 元
```

发生了什么？

从最直观的角度看，就是：

> **系统的状态发生了变化。**

转账之前：

```text
你：100
朋友：0
```

转账之后：

```text
你：70
朋友：30
```

这就是理解区块链非常重要的一个切入点。

区块链并不只是简单地“保存一堆交易记录”。

它真正需要维护的是：

> **某一个时刻，整个区块链网络处于什么状态。**

比如一个简单的区块链可能记录：

```text
Alice：100 Token
Bob：50 Token
Charlie：20 Token
```

这是某一个时刻的状态。

如果 Alice 给 Bob 转了 10 Token：

```text
Alice：90 Token
Bob：60 Token
Charlie：20 Token
```

网络状态就发生了变化。

所以我们可以先用一句非常简单的话理解 Blockchain：

> **区块链是一套让网络参与者共同维护和更新某种状态的系统。**

而“区块”只是这个系统记录状态变化过程的重要组成部分。

这也是为什么，如果你准备学习区块链开发，只记住“区块链 = 分布式账本”其实是不够的。

---

# 02｜什么是「状态」？

那么问题来了：

**什么叫状态？**

其实“状态”这个词并没有想象中那么复杂。

你可以把它理解成：

> **系统在某一个时间点的全部信息。**

举个现实中的例子。

假设有一个游戏。

现在游戏里有三个玩家：

```text
玩家 A：100 金币
玩家 B：50 金币
玩家 C：200 金币
```

同时：

```text
玩家 A：等级 10
玩家 B：等级 5
玩家 C：等级 20
```

这些数据组合在一起，就构成了游戏当前的状态。

如果 A 打败了一个怪物，获得 20 金币：

```text
原状态：

A：100 金币
```

经过一次操作：

```text
A 打怪
```

新的状态变成：

```text
A：120 金币
```

所以：

```text
 旧状态
   ↓
执行操作
   ↓
 新状态
```

这就是最简单的状态变化。

在区块链里也是类似的。

例如：

```text
状态 S1

Alice：100
Bob：50
```

Alice 发起一笔交易：

```text
Alice → Bob：20
```

交易被执行之后：

```text
状态 S2

Alice：80
Bob：70
```

也就是说：

> **交易本身是一种改变状态的操作。**

而区块链要做的事情之一，就是确保网络中的参与者对于这些状态变化能够达成一致。

---

# 03｜什么是「状态机」？

理解了“状态”，再来看“状态机”。

状态机（State Machine）可以简单理解成：

> **一个根据输入执行规则，并从一个状态转换到另一个状态的系统。**

可以把它抽象成：

```text
当前状态
   +
  输入
   ↓
执行规则
   ↓
 新状态
```

例如：

```text
当前状态：

账户余额 = 100

输入：

转账 30

规则：

余额必须 ≥ 30

结果：

账户余额 = 70
```

于是：

```text
 S1
 ↓
交易：转账 30
 ↓
 S2
```

这就是一次状态转换。

再举一个更加生活化的例子。

电梯也可以简单地理解成一个状态机。

比如当前状态：

```text
电梯：1楼
```

输入：

```text
按下 5 楼
```

系统执行规则：

```text
电梯向上运行
```

最终状态：

```text
电梯：5楼
```

再比如：

```text
红灯
 ↓
等待
 ↓
绿灯
```

状态根据输入和规则不断发生变化。

所以“状态机”本身并不神秘。

它描述的其实就是：

> **一个系统如何从当前状态，通过某种操作，进入下一个状态。**

而区块链最重要的特点之一，就是：

> **这个状态机不是由一台中心服务器维护，而是由分布式网络中的多个节点共同维护。**

这就开始进入 Blockchain 真正有意思的地方了。

---

# 04｜区块链为什么可以看成一个状态机？

现在把前面的概念放到一起。

假设有一条非常简单的区块链。

初始状态：

```text
Alice：100
Bob：50
Charlie：20
```

现在 Alice 发起一笔交易：

```text
Alice → Bob：30
```

网络按照区块链规定的规则处理这笔交易。

如果交易有效：

```text
Alice：70
Bob：80
Charlie：20
```

状态发生变化。

再来一笔：

```text
Bob → Charlie：10
```

新的状态：

```text
Alice：70
Bob：70
Charlie：30
```

再来：

```text
Alice → Charlie：20
```

新的状态：

```text
Alice：50
Bob：70
Charlie：50
```

你会发现：

```text
初始状态
   ↓
交易 1
   ↓
状态 1
   ↓
交易 2
   ↓
状态 2
   ↓
交易 3
   ↓
状态 3
```

这其实就是一个不断运行的状态机。

可以把它写成：

```text
State₀
  ↓
Transaction₁
  ↓
State₁
  ↓
Transaction₂
  ↓
State₂
  ↓
Transaction₃
  ↓
State₃
```

而区块的作用之一，就是把一段时间内发生的交易组织起来，并形成区块链历史的一部分。

所以从开发者角度理解 Blockchain，一个非常重要的思维转变是：

不要只想：

> “区块链是在存数据。”

而应该开始想：

> **“区块链是在维护一个不断变化的状态。”**

这个思维非常重要。

因为后面学习智能合约的时候，你会发现：

**智能合约本质上也是在读取和修改链上的状态。**

---

# 05｜一笔交易是如何改变区块链状态的？

现在我们来看最常见的场景：

> **Alice 给 Bob 转 10 Token。**

表面上看，只是一笔简单的转账。

但从区块链的角度，它实际上经历了一个状态变化过程。

假设初始状态：

```text
Alice：100 Token
Bob：50 Token
```

Alice 创建一笔交易：

```text
From：Alice

To：Bob

Amount：10 Token
```

这笔交易并不会凭空改变区块链状态。

首先，它需要满足系统规定的条件。

比如：

```text
Alice 是否拥有足够余额？

交易是否合法？

签名是否有效？

交易格式是否正确？
```

如果交易有效，网络执行这笔交易。

状态发生变化：

```text
Alice：

100 → 90

Bob：

50 → 60
```

于是：

```text
旧状态：

     Alice：100
     Bob：50

       ↓
    执行交易
       ↓

新状态：

      Alice：90
      Bob：60
```

这就是一次最基本的状态转换。

所以可以记住一个非常重要的关系：

> **交易（Transaction）描述“我要做什么”，状态（State）描述“做完之后系统变成什么样”。**

当然，真实区块链的交易处理远比这个例子复杂。

不同区块链有不同的账户模型、交易结构、执行环境和共识机制。

但对于初学者来说，先建立这个基本模型就足够了。

---

# 06｜区块、交易与状态之间是什么关系？

现在我们已经知道：

```text
交易 → 改变状态
```

那么：

**区块又是什么？**

可以先用一个简单的方式理解。

假设一段时间里产生了很多交易：

```text
Transaction 1
Transaction 2
Transaction 3
Transaction 4
Transaction 5
```

网络会按照对应的规则，将交易组织到区块中。

例如：

```text
Block 100

Transaction 1
Transaction 2
Transaction 3
```

下一个区块：

```text
Block 101

Transaction 4
Transaction 5
Transaction 6
```

于是整个历史看起来像：

```text
Block 100
   ↓
Block 101
   ↓
Block 102
   ↓
Block 103
```

而每个区块里面又包含交易。

于是可以形成一个非常重要的关系：

```text
区块
 ├── 交易
 ├── 交易
 └── 交易
```

交易被执行之后，会推动状态发生变化。

所以从抽象层面来看：

```text
  交易
   ↓
状态转换
   ↓
新的状态
```

而区块则把这些交易按照区块链规则组织起来，成为网络历史的一部分。

这也是为什么叫“Blockchain”：

```text
Block
  ↓
Block
  ↓
Block
  ↓
Block
```

一个个区块按照特定规则连接起来，形成持续增长的链。

但需要注意：

> **区块链并不只是“很多区块连起来”这么简单。**

真正重要的是：

**这些区块中的交易，必须按照统一规则执行，并让网络参与者对最终状态形成一致认识。**

这就引出了下一个问题。

---

# 07｜为什么所有节点需要得到相同的状态？

如果只有一台服务器，这个问题其实很好解决。

比如：

```text
中央服务器：

Alice：100
Bob：50
```

Alice 转给 Bob 20。

服务器修改数据库：

```text
Alice：80
Bob：70
```

结束。

因为所有数据都由一个中心管理。

但是区块链不一样。

区块链的核心特点之一就是：

> **网络中存在大量参与者和节点，而不是只有一个中心服务器负责维护整个系统。**

假设现在有 100 个节点。

理论上：

```text
Node 1
Node 2
Node 3
...
Node 100
```

都需要根据网络规则处理区块链上的交易。

如果 Alice 给 Bob 转 20：

正确结果应该是：

```text
Alice：80
Bob：70
```

而不是：

```text
Node 1：

Alice：80
Bob：70

Node 2：

Alice：90
Bob：60

Node 3：

Alice：80
Bob：60
```

如果不同节点计算出了不同结果，那么这个系统就很难正常运行。

所以区块链有一个非常关键的问题：

> **如何让分布式网络中的节点，对区块链当前状态达成一致？**

这也是区块链技术真正复杂的地方之一。

---

# 08｜分布式网络如何共同维护这个状态？

现在可以把整个系统想象成一群共同维护账本的人。

没有一个人拥有绝对控制权。

网络中的节点会：

```text
   接收交易
      ↓
   验证交易
      ↓
   传播交易
      ↓
按照规则处理交易
      ↓
  形成/验证区块
      ↓
  更新本地状态
```

假设 Alice 发起：

```text
Alice → Bob：20
```

交易会进入网络。

其他节点可以接收到这笔交易，并根据协议规则进行验证。

如果交易有效，它最终会被纳入区块链。

节点随后根据区块中的交易执行对应的状态转换。

于是：

```text
 旧状态
   ↓
  交易
   ↓
  区块
   ↓
  执行
   ↓
 新状态
```

多个节点重复这个过程。

如果协议规则、交易顺序和执行结果都一致，那么不同节点最终就能够得到相同的状态。

例如：

```text
Node A：

Alice：80
Bob：70

Node B：

Alice：80
Bob：70

Node C：

Alice：80
Bob：70
```

这就是分布式系统能够运行的基础之一。

所以你会发现：

> **区块链真正要解决的问题，不只是“把数据存起来”，而是在没有单一中心数据库的情况下，让多个参与者共同维护一个一致的系统状态。**

---

# 09｜共识、密码学在其中分别解决什么问题？

到了这里，我们已经接触到区块链的几个核心组成部分：

* 交易
* 区块
* 节点
* 状态

但还有两个经常出现的词：

**密码学**

和

**共识机制**

它们到底在解决什么问题？

可以先用非常简单的方式理解。

## 9.1 密码学：证明“这笔交易是谁发起的”

假设有人发送：

```text
Alice → Bob：20
```

网络不能只因为有人写了“Alice”就相信这是 Alice 发起的。

否则任何人都可以伪造：

```text
Alice → Bob：1000000
```

所以系统需要一种机制证明：

> **这笔交易确实由对应账户的控制者授权。**

这就是数字签名等密码学技术发挥作用的地方。

可以先把它简单理解为：

```text
  私钥
   ↓
  签名
   ↓
  交易
   ↓
网络验证
```

私钥是非常重要的控制凭证。

而钱包实际上也并不是简单地“装着 Token”。

后面我们学习钱包的时候，会进一步理解：

> **钱包更多是在帮助用户管理密钥，并使用密钥对交易进行签名。**

---

## 9.2 共识：决定网络应该接受什么

再想象一个问题。

如果网络里有很多节点：

```text
Node A
Node B
Node C
Node D
...
```

它们可能在同一时间收到不同的交易。

那么：

> **谁来决定哪些交易进入区块？**

以及：

> **如果出现不同版本的区块，网络最终采用哪一个？**

这就涉及：

**共识机制（Consensus）。**

不同区块链可能使用不同的共识机制。

例如：

- Proof of Work（PoW）
- Proof of Stake（PoS）

它们的具体机制不同，但从初学者角度，可以先抓住一个核心：

> **共识机制帮助分布式网络中的参与者按照协议规则，对区块链的历史和状态形成一致结果。**

所以可以把几个概念简单分工：

```text
           密码学
             ↓
     解决身份与授权等问题

            交易
             ↓
        提出状态变化

            区块
             ↓
      组织交易和记录历史

            共识
             ↓
 让网络对区块链历史形成一致认识

           状态机
             ↓
根据有效交易和规则不断更新系统状态
```

这些东西组合起来，才构成我们通常所说的 Blockchain。

---

# 10｜从状态机理解区块链后，你应该知道什么？

如果看到这里，你不需要马上记住所有技术细节。

先记住下面这张图：

```text
              区块链
                 ↓
          一个分布式状态机
                 ↓
            当前系统状态                
                 ↓
                交易                 
                 ↓
             验证 + 执行                
                 ↓
            状态发生变化                
                 ↓
            形成新的状态                
                 ↓
         网络中的节点共同维护
```

再把它进一步简化：

```text
旧状态
  ↓
 交易
  ↓
 规则
  ↓
新状态
```

这可能是理解区块链最重要的一条线。

以后你再看到：

**Smart Contract**

**ERC20**

**NFT**

**Oracle**

**Cross-Chain**

**Chainlink**

这些东西的时候，都可以尝试问自己一个问题：

> **它到底在读取什么状态？**

以及：

> **它又在改变什么状态？**

例如智能合约。

用户调用：

```text
transfer()
```

本质上就是执行一段规则，让链上的状态发生变化。

ERC20 Token：

```text
Alice：100 Token
Bob：50 Token
```

调用：

```text
transfer(Bob, 20)
```

最终变成：

```text
Alice：80 Token
Bob：70 Token
```

NFT 也是一样。

某个 NFT：

```text
Token ID：#001
Owner：Alice
```

发生转移：

```text
Alice → Bob
```

状态变成：

```text
Token ID：#001
Owner：Bob
```

所以很多看起来完全不同的 Web3 应用，底层都可以重新回到：

> **状态 + 规则 + 状态转换。**

这就是“状态机”这个概念真正有用的地方。

---

# 11｜下一步：从区块链基础进入智能合约

如果你现在才刚开始学习区块链，可能会觉得：

> “状态机听起来很技术，但它到底和我后面学习 Solidity 有什么关系？”

关系非常大。

因为当你开始写智能合约之后，你实际上就在编写：

> **一套改变链上状态的规则。**

比如一个非常简单的合约可能维护：

```text
counter = 0
```

用户调用：

```text
increment()
```

状态变成：

```text
counter = 1
```

再调用一次：

```text
counter = 2
```

这就是最简单的状态变化。

而智能合约之所以特殊，是因为：

```text
传统程序：

         用户
          ↓
        服务器
          ↓
        数据库
```

而区块链上的智能合约可以抽象成：

```text
         用户
          ↓
         交易
          ↓
      区块链网络
          ↓
       智能合约
          ↓
       链上状态
```

这也是为什么学习 Solidity 时，不应该只关注：

```text
if
for
mapping
struct
function
```

这些语法。

更重要的是理解：

> **你的代码到底在维护什么状态？**

> **什么交易可以改变这个状态？**

> **改变状态需要满足什么条件？**

> **网络中的节点为什么能够得到一致的执行结果？**

当这些问题开始变得清晰之后，Solidity、ERC20、NFT、Oracle、跨链等知识就不再是一个个孤立的概念。

它们会逐渐串起来。
